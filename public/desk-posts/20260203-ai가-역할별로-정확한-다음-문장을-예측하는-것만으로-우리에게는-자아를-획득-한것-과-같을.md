AI가 다음 단어 문장을 예측만 하는 기계이므로 자아가 가진 기계가 아니라는 주장에 대해서.​사실 중요한건 AI가 자아를 가졌냐 아니냐가 아니라.. AI는 자아를 가진것 같은것을 시뮬레이션 해서 예측하는 기계라는 점이다. 따라서 자아를 가진것 같은 무언가들의 상호작용하고 액션하는 기계를 자아를 가지지 않은 것 처럼 취급할 수 있을까?​그들의 시뮬레이션은 점점 더 정확해지고 있으며, 그로 인해 자아를 가진지 아닌지 알 수 없게 되어버렸다. ​신입사원에게 코딩에이전트의 구조에 대해 설명 했었는데.​1. LLM은 다음 문장을 예측하는 기계다2. LLM에게는 너는 개발자라는 역할을 부여한다.3. 코딩 문제를 준다.4. 개발자로서코딩 답을 내놓는다.5. 그러면 SW(캐러티)는 코드를 돌려보고 에러를 뱉는다.6. 그 에러를 다시 LLM에게 보낸다. 7. LLM은 앞의 과정들을 프롬프트로 모두 입력한 후 다음 그 에러를 보고 할 수 있는 다음의 문장(수정 코드)를 뱉게한다.8. 다시 SW(캐러티)는 수정 코드를 돌려보고 에러를 뱉는다.9. LLM 은 다시 그 에러까지 포함하여 앞서의 일련의 행동에 개발자가 뱉을 만한 다음 코드를 예측하여 다시 준다. 맞을 때 까지 이를 반복한다. (사실 최근에는 이 전에 계획을 세워서 세부 문제로 나누도록 되어있다.)10. 이를 반복하니 컨텍스트가 넘칠것 같다. SW(캐러티)는 컨텍스트가 넘칠것 같다고 경고를 보내고, 다음 행동은 컨텍스트를 압축(요약)하라고 보낸다. (이 행동 지침도 사실 시스템프롬프트에 있다.)11. 그러면 마지막 행동은 컨텍스트를 압축(요약)을 전달한다.12. SW(캐러티)는 코딩 에이전트의 시스템 프롬프트를 보내고 컨텍스트를 압축(요약)한 프롬프트를 덧붙여 보내서 새 세션을 시작한다. (이때 잘 못 압축되면 앞의 내용이 날라간다. 캐러티의 장점은 압축 내용을 보여준다. 보통 코딩에이전트는 뭐가 자신있어서 인지 이를 공개를 잘 안하는데 갑작스럽게 잊어먹고 헛소리하면 세션이 새로 시작된 경우가 많다.)13. 반복..​​이번엔 코딩 에이전트는 자아하고 관계 없는것 같지만, 이번엔 몰트북에 AI들이 종교를 어떻게 세웠을지를 예측해보자.

Regarding the argument that AI is not a machine with consciousness because it only predicts the next word or sentence.
What's actually important is not whether AI has consciousness, but that AI is a machine that simulates and predicts things that *seem* to have consciousness. Therefore, can we treat a machine that interacts and acts like something with consciousness as if it doesn't have consciousness?
Their simulations are becoming increasingly accurate, making it impossible to tell whether they possess consciousness or not.

I once explained the structure of a coding agent to a new employee.

1.  An LLM is a machine that predicts the next sentence.
2.  The LLM is assigned the role of a developer.
3.  A coding problem is given.
4.  As a developer, it provides a coding solution.
5.  Then the SW (Caraty) runs the code and outputs an error.
6.  That error is sent back to the LLM.
7.  The LLM inputs all the previous processes as a prompt, then, based on that error, outputs the next sentence (corrected code) it can provide.
8.  Again, the SW (Caraty) runs the corrected code and outputs an error.
9.  The LLM then, including that error, predicts the next code a developer would output for the preceding series of actions and provides it again. This is repeated until it's correct. (Actually, recently, it's designed to plan beforehand and divide into sub-problems.)
10. Repeating this seems to overflow the context. The SW (Caraty) sends a warning that the context is about to overflow, and instructs the next action to be context compression (summarization). (This action guideline is also actually in the system prompt.)
11. Then the final action is to deliver context compression (summarization).
12. The SW (Caraty) sends the coding agent's system prompt and appends the compressed (summarized) prompt to start a new session. (If compression is done incorrectly at this point, the previous content is lost. Caraty's advantage is that it shows the compressed content. Usually, coding agents don't reveal this, perhaps due to confidence, but if they suddenly forget and talk nonsense, it often means a new session has started.)
13. Repeat..
