[www.naver.com](http://www.naver.com/)을 갑자기 [www.naver2.com](http://www.naver2.com/) 으로 바꾼다면 대 혼란이 일어날것이 뻔하지만, mail.naver.com을 직접 치고 들어오는 유저가 거의 없기 때문에 가능한 방법이다. 만약 openAPI를 제공하는 gmail이었다면 이런방법은 절대로 쓸수 없다. Open API를 사용하는 외부의 모든 서비스를 죽이기 때문이다.

url이 뭔지도 모르는 한국 유저들에게 감사해야 할 상황일까?
이거 웃어야 할라나.. ㅜㅜ 의외로 해킹의 대처 방법은 늘 간단하다.

Only the attacked URL was changed. lol

The reason this works is because most users come in through searches or clicks within portals.
If you suddenly changed [www.naver.com](http://www.naver.com/) to [www.naver2.com](http://www.naver2.com/), it's obvious that great confusion would ensue, but this method is possible because almost no users directly type in mail.naver.com. If it were Gmail, which provides an OpenAPI, this method could never be used. This is because it would kill all external services that use the Open API.

Is this a situation where we should be grateful to Korean users who don't even know what a URL is?
Should I laugh at this... ㅜㅜ Surprisingly, the countermeasures for hacking are always simple.
