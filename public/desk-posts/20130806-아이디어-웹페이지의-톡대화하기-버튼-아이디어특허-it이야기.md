**현재의 업체전용 카카오나 라인친구와 유사하나 이는 push용도 보다는 ARS를 대체할 수 있는 커뮤니케이션창구로 사용하기 위한 용도로 생각해본겁니다.****
****-----****1. 제목 : 웹페이지의 톡대화하기 버튼**
**2. 작성일 : 2011년 8월 4일**
**3. 배경 : **인터넷 검색을 하다보면 POI나 커뮤니티를 검색 하게 된다. 이 때, 노출되는 전화번호로 문의를 하거나 하는데 이를 톡같은 대표 IM을 노출 하는 방법을 제시하려고 한다.
**4. 기본 시나리오** 검색을 한 후, 나오는 POI결과 옆에 전화번호 대신, 톡대화하기 버튼을 눌러 톡을 띄워 상담을 진행한다.
**5. 기본 프로세스 **** 1) 페이지 관리자와 talk ID 매칭(등록)**   - POI 관리 페이지, 네이버 카페 관리 페이지, 혹은 블로그등 인터넷상에 노출되는 특정 페이지의 관리자 권한을 의미한다. 이 관리자 페이지에서 유저는 자신의 talk ID를 등록할 수 있다.
** 2) talk 연락하기 버튼 노출**    - 인터넷 페이지에서 talk ID를 등록하면, 해당 페이지에서 talk 연락하기 버튼이 노출 된다. 해당 페이지의 헤더나 혹은 검색결과(POI)의 페이지내에서 노출될 수 도 있다.
** 3) 페이지 관리자와 연락**    - 유저는 검색혹은 해당 페이지 방문을 통해, talk 버튼을 누르면, 웹 혹은 앱형태로 talk이 실행되고 페이지 관리자에 연락이 전달된다. 이때 전달되는 형태는 문자메시지, 혹은 Voip통화 일 수도 있다.
** 4) 외부 홈페이지의 talk 버튼 활용**    - POI나 카페 외에 외부의 홈페이지를 가진 유저도 talk버튼을 추가할 수 있다. 홈페이지 등록시 talkID를 등록하고, 만들어지는 버튼 API를 가져다가 외부의 홈페이지에 등록할 수 있다. 외부의 홈페이지에 톡버튼을 클릭시 네이버톡의 팝업이 뜨면서 상담을 진행 할 수 있다.

**4. 노출하고 싶지 않은 개인 talk ID 니즈에 대한 대비** 위의 프로세스를 사용시, 유저는 업체에 자신의 talk ID가 노출되는 것을 원하지 않을 수 있다. 페이지 관리자 역시, 자신의 개인용도로 사용되고 있는 talk이 업무관계로 상담자들과 뒤섞이는 것을 원하지 않을수도 있다. 때문에 아래와같은 기술적 대안을 제시한다.
** 1) 업체 talk ID와 대화창 리스트의 분리**   - 개인 talk대화와 페이지(업체)talk을 분리하여 유저가 관리할 수 있다. 때문에 유저는 친구추가를 하지 않더라도, 상담 내역들을 계속 남겨두거나, 업체talk만 따로 리스트를 만들어 향후에 다시 상담을 진행 할 수 있다.
** 2) 유저 아이디 미노출**   - 유저의 경우 아이디의 일부만 노출되고, 페이지 관리자의 경우, 페이지명으로 대화명이 노출되게 하여, 업체가 마음대로 유저를 친구에 추가할 수 없도록 한다.
**5. 가치** - 웹에서 업체와의 커뮤니티및 상담을 전화를 대체할 수 있다. - 톡과 웹의 접점을 늘릴 수 있다.
**6. 차별성(특허포인트)** 1) 페이지 관리자와 talk ID 매칭(등록) 2) 외부 사이트의 페이지 관리자 톡버튼 제공 3) 페이지 관리자의 대화시 개인의 talk정보 숨김 4) 페이지 관리자의 talk 대화 리스트 이원화

**This is similar to current business-specific Kakao or Line Friends, but it's envisioned not for push notifications, but as a communication channel to replace ARS (Automated Response System).****
****-----****1. Title: Talk Chat Button on Webpages**
**2. Date: August 4, 2011**
**3. Background:** When searching the internet, users often look for POIs (Points of Interest) or communities. At such times, they might inquire using the displayed phone number. This proposal aims to present a method for displaying a representative IM (Instant Messenger) like 'Talk' instead.
**4. Basic Scenario** After a search, next to the POI results, instead of a phone number, users click a 'Talk Chat' button to launch Talk and proceed with a consultation.
**5. Basic Process**
**1) Page Manager and Talk ID Matching (Registration)**
- This refers to the administrator rights of specific pages exposed on the internet, such as POI management pages, Naver Cafe management pages, or blogs. On this administrator page, users can register their Talk ID.
**2) Displaying the Talk Contact Button**
- When a Talk ID is registered on an internet page, a 'Talk Contact' button is displayed on that page. It can be displayed in the page's header or within the search results (POI) page.
**3) Contacting the Page Manager**
- Users, through search or by visiting the relevant page, click the Talk button, which launches Talk in a web or app format, and a message is delivered to the page manager. The form of delivery can be a text message or a VoIP call.
**4) Utilizing the Talk Button on External Homepages**
- Users with external homepages, in addition to POIs or cafes, can also add a Talk button. When registering their homepage, they can register their Talk ID and then take the generated button API to embed it on their external homepage. When the Talk button on an external homepage is clicked, a Naver Talk pop-up appears, allowing for consultation.

**4. Addressing the Need for Not Exposing Personal Talk IDs** When using the above process, users may not want their Talk ID to be exposed to businesses. Similarly, page managers may not want their personal Talk, used for private purposes, to be mixed with business-related consultations. Therefore, the following technical alternatives are proposed.
**1) Separation of Business Talk ID and Chat List**
- Users can manage personal Talk conversations and page (business) Talk separately. Therefore, even without adding friends, users can keep consultation histories or create a separate list for business Talk to continue consultations in the future.
**2) Non-exposure of User ID**
- For users, only a part of their ID is exposed, and for page managers, the conversation name is displayed as the page name, preventing businesses from arbitrarily adding users as friends.
**5. Value**
- It can replace phone calls for communication and consultation with businesses on the web.
- It can increase the points of contact between Talk and the web.
**6. Differentiation (Patent Points)**
1) Page manager and Talk ID matching (registration)
2) Provision of Talk buttons for page managers on external sites
3) Hiding personal Talk information during page manager conversations
4) Dualization of page manager's Talk conversation list
