An idea I found while sifting through a list of rejected applications. I'm finally revealing an idea that I've been sitting on for days, unable to make a single post about it. **Title: METHOD, SYSTEM, TERMINAL AND COMPUTER-READABLE RECORDING MEDIUM FOR PROVIDING EMOTICON CORRESPONDING TO WRITTEN IMAGE**
Application No.: 10-2007-0140986 (20071228) Publication No.: 1020090072773 (20090702)
This content was applied for in December 2007 and then rejected. Many early patents were lost or left in limbo when the organization later changed to nbp... I'm not sure why it was rejected.
(Actually, if Apple had registered it with the Korean Intellectual Property Office, most of them would have been rejected. Haha.)

The idea is simple. When you draw a picture in a messenger window, it lists corresponding emoticon models, and you select one to insert it. With the S Pen on the Galaxy Note and in today's era, it would be a good idea if applied to something like KakaoTalk. However, implementation is not that simple. The method I thought of at the time was to first secure a diverse emoticon database, then have part-time workers draw associative pictures for these emoticons to create a training model. Based on this model, the process shows the most similar images in order from the drawing data input by the user. Simply put, like Naver's Hanja dictionary input method, candidates appear while drawing, but in this case, emoticons appear. An image would be faster than words.

{{IMG:1}}
If you draw in 450 (drawing input window), it is listed in 454 (candidate window), and if you select it in 454, it is entered into 430 (input window). Of course, 450 and 430 could also be combined, like the input window on old Pocket PCs.

Since this is a rejected/published idea, you are free to apply it. (I'd be more grateful if you credited me, but you probably won't, right? Ideas in this field just circulate if they're not documented.)
