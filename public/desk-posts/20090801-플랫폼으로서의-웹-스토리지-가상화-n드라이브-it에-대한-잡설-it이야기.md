네이버에서 N드라이브가 출시 되었습니다.
사실 저는 이러한 서비스를 학수고대하고 있던 사람의 한명으로서 아주 반가운 서비스 입니다.
네이버가 웹하드를 무료로 준다란 식으로 인터넷 상에서 떠도는 듯 하지만, N드라이브는 의의는 그저 웹하드가 아니라고 생각합니다.
최근 기업에게 제공되는 스토리지 가상화 서비스가 개인에게 까지 확대된, 플랫폼 웹으로서의 스토리지 서비스란 것이 제 사견입니다. 왜 이런 가상 네트워크 드라이브가 기존 웹 하드와 다르고 어떻게 발전할 것인지 잠깐 제 생각을 써보겠습니다.

** * N드라이브가 기존의 웹하드와 다른 점**
****
** 1.  이동형 스토리지를 완전 대채하는 가상 스토리지**
**** 차세대 웹 스토리지가 기존 웹하드와 가장 다른 점이 바로 이러한 특징입니다. 인터넷이 접속되는 어디서나 똑같은 저장공간의 이용. 인터넷이란 것이 웹브라우져를 통해 어디서나 똑같은 형태로 접속될 수 있는 서비스기는 하지만, FTP나 HTTP를 이용한 방식은 해당 프로그램을 이용해 다운로드를 받아야만 서비스가 가능했습니다. 실제 개인의 스토리지 보다는 네트워크에서 다운로드를 받는 다는 개념이 강했습니다.
그러나, N드라이브는 이러한 개념이 없어졌습니다.  그러한 특징을 보여주는 것이 바로 N드라이브 탐색기입니다.
{{IMG:1}}
** [ 기존 윈도우 탐색기와 동일하게 동작하는 N드라이브 ]**
****
그저 웹하드용 탐색기가 조금 더 접근성이 좋지 않느냐 ? 정도로만 해석할지 모르겠는데, 크게 다릅니다. 이동형 USB를 생각해보시죠. USB에 저장하는 것은 문서, 그리고 공인인증서 같이 작지만 어디서나 필요한 파일입니다. 굳이 다운로드 받는게 귀찮아서 웹에 올려두지 않고 USB에 넣어가지고 다니죠. 이동형 스토리지 제작 업체들에 타격이 있지 않을까 싶네요.
그리고, 이는 웹 디스크라기보다는 가상디스크입니다. 가상 스토리지는 이미 잘 알려져 있는것이 있죠. CD를 가상화 하여 스타크래프트를 돌릴 때 썼던, CD-Space같은 솔루션입니다. 파일을 씨디같은 가상 디스크로 만들었다면, N드라이브는 네트워크의 서비스를 가상 디스크로 만든것 입니다.

**2. 싱크가 필요없는 모바일 기기의 스토리지 대채 **
저 역시 MS의 Win Mobile 5.0 이 설치된 스마트폰을 사용합니다. 이동 중에 떠오르는 아이디어나 포스팅 내용, 업무용 문서를 작성하곤 합니다. 그리고 Active Sync를 이용해 일정을 Sync하긴 하는데, 이러한 파일들은 Sync가 되지 않죠. 또한 노트북도 있는 관계로 회사 PC, 노트북, 스마트폰 까지 세군대의 스토리지 공간에 중복 적으로 있는 파일들이 있습니다. 일부 문서와 음악 파일들이죠. 이동중에는 스마트폰으로 음악을 듣고, 업무할때는 PC나 노트북으로.. 한데, 이걸 복사할라믄 엄청 귀찮습니다. 그리고 이쪽에서 작업한 줄 알았던 파일이 저쪽에 있어서 난감하고 했던 경험이 있죠.
이러한 경험을 완전히 날려 줄 수 있는것이 바로, 네트워크 스토리지 입니다. 충분한 네트워크 속도만 보장이 된다면 수십 킬로 바이트나 수메가의 음악과 문서 파일은 플레이하고 읽는 속도보다 스트리밍 속도가 더 빠르므로, 네트워크에 있다고 해서 아무 불편함을 느끼지 않습니다.
(IPTV의 경우) 100Mb 급 이상의 네트워크 환경이라면, HD급 동영상 까지도 네트워크 상에 있더라도 플레이에 아무 불편함을 못느끼죠.

{{IMG:2}}
**  [ 아이폰용 ? N드라이브 ]**
이렇듯 모바일 기기가 배터리 문제만 없고, 항상 연결되어있고, 네트워크 속도만 보장이 된다면 네트워크 드라이브만큼 이동기기의 스토리지로서 적절한게 없습니다. 아이폰은 16기가고, 제 하드디스크는 200 기가라죠. 연결만 되어있다면 아이폰에 200기가 하드디스크가 달려있는 것과 마찬가지일꺼고, 환경만 도와준다면, 아이폰 용 어플리케이션도 네트워크 드라이브에 깔아서 구동시에만 다운로드하여 메인메모리에 올리는 방식으로 되어 EFS(Embeded File System)대신, 실제 NFS(Network File System)이란 이름으로 불리울 날이 있을지도 모르겠습니다.

**3. 사진 저장소로서의 N드라이브**
이건 네트워크 드라이브의 특징으로 보기는 어려우나, 사진을 포함한 멀티미디어 파일은 네트워크 드라이브의 킬러 어플리케이션이 될 수 있다고 믿습니다. 가장 USB를 제외하고 대용량 이동형 메모리를 많이 쓰는 기기가 무엇일까요 ?  바로 디지털 카메라입니다. 또한 이놈의 데이터는 항상 최종 목적지는 PC죠. 매번 복사해야 합니다. 그러나 1번의 특징과 2번의 특징을 더해서 조금만 상상력을 더해봅시다. 어떤 기기가 떠오르시나요 ?
바로, **메모리가 없는 디지털 카메라.** 입니다.
그것이 왜 킬러 어플리케이션이 될 수 있는가는 조금만 상상해 보시면 압니다. 잠깐만 요즘 사진파일에 대한 제 고민을 말씀드리겠습니다.
****
** - 파일 크기의 대형화**
요즘 DSLR등 고화질 카메라로 인해 사진 파일은 무지하게 커졌습니다.  600만화소로 찍어대도 금방 수십메가는 가뿐히넘깁니다. 1000만, 1200만화소는 어떨까요 ?  스토리지 비용은 고민스럽습니다.

** - 많은 파일**
무지하게 파일도 많습니다. 찍고 확인하기 쉬운 디지털의 특성만큼 과거에 처럼 놀러가서 24방 30방 찍는게 아니라 수백방씩 찍어 옵니다. 기하 급수적으로 늘어나는 파일, 검색 필요.

** - 스토리지 안정성의 고민**
결국은 이렇게 어마어마한 데이터들을 종종 하드디스크로 복사하죠. 한데, 전 엔지니어라서 그런지 하드디스크는 영 못미덥습니다. DVD나 CD로 구우면 된다고요 ? 글쎄요. 저희집은 공인전자문서 보관서 같이 대단한 관리를 갖추고 있지 못한 관계로 영원히는 보관못하겠죠.
그리고 CD는 다시 찾아보기도 힘들고, 검색도 안됩니다. 그리고 한번 겪은 일이지만, 스토리지의 저장 기기는 10년내에는 DVD를 돌리고 있을까요? 과거 ZIP드라이브와 플로피 드라이브가 어떤 운명을 겪었는지는 잘 기억하고 있습니다. 영원히 사용할 스토리지가 필요합니다. 200기가 하드디스크날아가면 5년간 추억은 바이바이입니다. 그렇다고 블로그에 모두 올린다면 미친짓이죠. ㅡㅡ;

**-  하나의 공통 스토리지**
마눌님이 자꾸 사진을 이 PC 저 PC뿌린다고 화를 냅니다. 집에 PC가 두대고 노트북이 한대인데, 노트북에 메모리 리더기가 달려있다보니 귀찮을때는 자꾸 그쪽으로 복사합니다. 결국, 소스 Merge 하듯, 사진 폴더 Merge 작업을 해야하죠 ㅡㅡ; 이 기종에서 접근이 손쉽고 하나로 관리할 수 있는 공간이 필요합니다.

위의 네가지 요구조건을 고민하면 딱 나옵니다. 집에 미디어 베이를 하나 두고 RAID로 서버를 하나 구성해서 데이터를 저장하거나,(심각하게 고려해봤습니다. 최근 SOHO용으로 장비가 많이싸졌더군요) N드라이브같은 네트워크 스토리지 서비스를 이용하는겁니다. 사진은 매우 중요한 데이터란 면에서 게임과 윈도우즈가 수시로 돌아가는 소프트웨어와 함께 저장 하기에는 매우 불안합니다.

**4. 궁극적인 길 메모리 없는 카메라, 이동기기들 등장 !! 스토리지 가상화 !**
결국은 이리 갈겁니다. 아니 이동기기가 아니라, 모든 네트워크 기기들일지도 모릅니다. 하드디스크는 완벽히 서버 베이스로 가고, 로컬의 하드디스크처럼 네트워크 자원에서 다운받은 어플리케이션을 기기의 메모리에 올리고 CPU로 구동하는겁니다. 메모리 제한 없는 네트워크에 연결된 카메라, 그리고 어쩌면 하드디스크란 것 자체가 없는 PC가 생길지도 모르는 일이죠. 어플리케이션도 네트워크에 까는 시대가 옵니다.
아이폰에 달린 카메라만 생각해보십쇼. 더이상 16기가의 메모리에 허덕일 필요가 없습니다. 물론 네이버가 5기가밖에 안주니 아직은 gg입니다.

**5. 네트워크 컨탠츠의 폭발 ! 공유와 배포가 용이한 데이터**
지금은 이메일과 블로그, 카페에 전송이 됩니다. 하지만 미투데이를 한번 생각해보시죠 ? 지금은 MMS로 전송합니다. 그리고, 제가 말씀드린 4번의 상황이 왔을 때, 그때도 MMS로 전송하고 있을까요 ? 바로 그 점이 네트워크 스토리지가 가지는 강점입니다. 현재는 네이버의 서비스 뿐일지도 모르지만, 차후에 Open API를 이용하여 플릭커같은 다른 외부 플랫폼이나 서비스에서 N드라이브의 서비스를 이용 가능할지도 모릅니다. (N드라이브가 그렇다는게 아니고, 네트워크 드라이브의 특징이 그럴거라는 이야기입니다.)

*** N드라이브에 거는 기대
위와같은 요건들로 나가고, 기술적인 보장만 해준다면 5기가 이상의 유료구매도 고려해볼만 할겁니다. (단, 충분히 납득할만한 가격이여야겠죠.) 기존의 5기가로서의 한계에 머무른다면, 플랫폼 웹으로서의 기능 보다는 USB메모리 대체. 정도의 개념으로만 머무를것입니다.**
네이버의 N스토리지의 전략은 더 두고봐야 할 일이지만, 구글이나 MS의 웹Os가 스토리지를 제공한다면, 네이버와 비슷한 모습일것 같습니다. 실제 2006년 구글의 G드라이브 관련 기사들을 검색해보니 현재 N드라이브의 모습과 거의 흡사합니다. 그러나 결국 실체는 3년 후나 지나 네이버가 먼저 가시화해버렸네요. 네이밍 센스도 비슷하고 결국 플랫폼으로서의 웹이라는 목표는 공동이란 걸까요 ?

점차 가상화가 화두가 되고 있습니다. 이러한 수천만명을 대상으로한 스토리지 서비스는 기존의 비싼 서버 기반의 IDC센터의 비싼 스토리지로는 버거우리라 예상됩니다. 이러한 스토리지 요구사항은 블로그를 비롯하여 네이버에게 가상화 기술들을 도입하는 계기가 되지 않을까 싶습니다. 실제로 [http://dev.naver.com](http://dev.naver.com/) 에는 가상화 관련 프로젝트들이 많습니다.

가트너가 정한 10대 기술에 클라우드 서비스가 있고, 그 핵심에는 가상화가 있는 만큼, 한국에 그만한 기술력을 가진 회사는 분명 필요하다고 생각합니다. 그리고 그렇기 위해서는 사업적으로 킬러 어플리케이션이 나와야만 하죠. 때문에라도 N드라이브가 한국의 가상화 기술을 이끄는 Enabler가 됬으면 하고 바래봅니다.

Naver has launched NDrive.
As someone who has been eagerly awaiting such a service, I am very pleased with it.
While it seems to be circulating online that Naver is giving away web storage for free, I believe the significance of NDrive goes beyond just being web storage.
In my opinion, it's a storage service as a platform web, where storage virtualization services, recently provided to businesses, have now expanded to individuals. I'd like to briefly share my thoughts on why this virtual network drive differs from existing web storage and how it might evolve.

**\* Differences between NDrive and existing web storage**

**1. Virtual storage that completely replaces portable storage**
This is the most significant difference between next-generation web storage and existing web storage. It allows access to the same storage space from anywhere with an internet connection. While the internet is a service that can be accessed in the same way anywhere via a web browser, methods using FTP or HTTP required downloading a specific program to use the service. The concept was more about downloading from the network rather than personal storage.
However, NDrive has eliminated this concept. NDrive Explorer is a prime example of this feature.
{{IMG:1}}
**[NDrive operates identically to existing Windows Explorer]**

You might interpret it as merely a web storage explorer with better accessibility, but it's vastly different. Consider a portable USB drive. What do you store on a USB? Documents and small but essential files like public certificates. You carry them on a USB rather than uploading them to the web because downloading them is bothersome. I wonder if this will impact manufacturers of portable storage devices.
Furthermore, this is less of a web disk and more of a virtual disk. We already know about virtual storage solutions like CD-Space, which virtualized CDs to run games like StarCraft. If files were made into virtual disks like CDs, NDrive has made a network service into a virtual disk.

**2. Mobile device storage replacement without the need for syncing**
I also use a smartphone with MS Win Mobile 5.0 installed. I often write down ideas, post content, or work documents while on the go. I use Active Sync to sync my schedule, but these files don't sync. Also, since I have a laptop, there are files duplicated across three storage spaces: my company PC, laptop, and smartphone. These are some documents and music files. I listen to music on my smartphone while commuting, and on my PC or laptop when working. But copying them is incredibly annoying. And I've had frustrating experiences where I thought I worked on a file on one device, only to find it on another.
Network storage can completely eliminate such experiences. If sufficient network speed is guaranteed, streaming speeds for tens of kilobytes or several megabytes of music and document files are faster than playback and reading speeds, so you won't feel any inconvenience having them on the network.
(In the case of IPTV) In a network environment of 100Mb or higher, even HD-quality videos can be played without any inconvenience, even if they are on the network.

**3. NDrive as a photo storage**
While this is not strictly a feature of network drives, I believe multimedia files, including photos, can be a killer application for network drives. What device, besides USB, uses large-capacity portable memory the most? It's digital cameras. And the ultimate destination for this data is always the PC. You have to copy it every time. But let's combine the features of 1 and 2 and add a little imagination. What device comes to mind?
It's a **digital camera without memory.**
You'll understand why it can be a killer application with just a little imagination. Let me briefly share my current concerns about photo files.

**- Increasing file size**
With high-resolution cameras like DSLRs, photo files have become incredibly large. Even shooting at 6 megapixels easily exceeds tens of megabytes. What about 10, 12 megapixels? Storage costs are a concern.

**- Many files**
There are also an enormous number of files. Thanks to the ease of shooting and reviewing digital photos, people don't just take 24 or 30 shots when they go out like in the past; they take hundreds. Files are increasing exponentially, requiring search capabilities.

**- Storage stability concerns**
Ultimately, this enormous amount of data is often copied to hard drives. However, as an engineer, I find hard drives quite unreliable. You say I can burn them to DVD or CD? Well, my home doesn't have the sophisticated management of a certified electronic document archive, so I probably can't store them forever.
And CDs are hard to find again, and you can't search them. And I've experienced this once: will storage devices still be spinning DVDs in 10 years? I vividly remember the fate of ZIP drives and floppy drives. I need storage that I can use forever. If a 200GB hard drive crashes, five years of memories are gone. Uploading everything to a blog would be crazy. T_T;

**- A single common storage**
My wife keeps getting angry because I scatter photos across different PCs. We have two PCs and one laptop at home, and since the laptop has a memory card reader, I often copy them there when I'm lazy. Eventually, I have to merge photo folders like merging source code T_T; I need a space that is easily accessible from different devices and can be managed as one.

Considering the four requirements above, the answer is clear. Either set up a media bay at home and configure a RAID server to store data (I seriously considered this; SOHO equipment has become much cheaper recently), or use a network storage service like NDrive. Photos are very important data, and storing them alongside software like games and Windows, which are constantly running, is very unstable.

**4. The ultimate path: cameras and mobile devices without memory appear!! Storage virtualization!**
Ultimately, this is where it's headed. Or perhaps not just mobile devices, but all network devices. Hard drives will completely move to a server-based model, and applications downloaded from network resources will be loaded into the device's memory and run by the CPU, just like local hard drives. We might see network-connected cameras with unlimited memory, and perhaps even PCs without hard drives altogether. The era of installing applications on the network is coming.
Just think about the camera on an iPhone. You no longer need to struggle with 16GB of memory. Of course, Naver only gives 5GB, so it's still a "gg" for now.

**5. Explosion of Network Content! Data Easy to Share and Distribute**
Currently, it is sent to emails, blogs, and cafes. But consider Me2day for a moment. Currently, it's sent via MMS. And when the situation I mentioned in point 4 arises, will it still be sent via MMS?
