## 1. 제목 : 웹 페이지에 포함되는 이미지 상의 텍스트를 판독하고 이에 대한 번역 서비스를 제공하기 위한 방법, 장치 및 컴퓨터 판독 가능한 기록 매체  (METHOD, APPARATUS AND COMPUTER-READABLE RECORDING MEDIUM FOR READING TEXT ON IMAGE CONTAINED IN WEB PAGE AND PROVIDING TRANSLATION SERVICE ON SAME TEXT)

**2. 초안 **

1.     제목 : 인식기술을 이용한 웹상의 멀티미디어 번역기
2.     배경 : 현재는 웹 번역기를 돌리게 되면 이미지와 동영상,사운드 같은 텍스트외의 데이터는 번역이 되지 않는다. 이를 인식 기술을 통해 번역기의 활용을 높이는 방법을 제안한다.
{{IMG:2}}
[현재의 번역기의 한계] : 이미지, 플래시, 동영상에 삽입되어 있는 외국어는 번역이 되지 않는다.

2.1   사용자가 번역기에 쿼리로 해당 사이트의 번역을 요청
2.2   번역기는 해당 사이트의 데이터를 다운로드 하여 번역
l  이때 포함된 데이터중 txt데이터만 유효하게 번역을 함

<img src=’ [http://yahoo.jp/japan.jpg>](http://yahoo.jp/japan.jpg%3E) 일본
2.3   번역기는 번역한 페이지를 사용자에게 전달

3.     개선 : 페이지에 포함되어 있는 멀티미디어 파일의 번역을 필요로 함
3.1   사용자가 번역기에 쿼리로 해당 사이트의 번역을 요청
3.2   번역기는 해당 사이트의 데이터를 다운로드 하여 번역 한다. 이때 멀티미디어 파일들의 경우, OCR을 통하여 번역된 새로운 멀티미디어 파일을 만든다.

3.3   변경된 멀티미디어 파일 주소로 링크를 교체한다.
3.4   이 만들어진 새로운 페이지를 사용자에게 전달한다.

4.     멀티미디어 OCR의 어려움의 해결 방법
-       범용적인 멀티미디어 파일내에서 글자 영역을 찾아내는 것은 매우 어려운 일이다.
때문에 사용자가 원하는 영역을 지정하게 하여 성능을 높일 수 있다.
{{IMG:3}}
-       빨간 선으로 표시된 부분은 사용자가 마우스로 번역을 요구한 페이지이다.
이 경우, 해당 이미지의 OCR후 추출된 Txt 원문과 번역된 텍스트결과를 유저에게 알려 줄 수 있다.
l  영역 외에도 글자 수, 글자의 기울어진 정도, 혹은 역상, 글자의 색깔 등을 추가 정보를 사용자가 입력하게 하는 모든 영역에 해당 할 수 있다.
l  위의 예는 이미지의 글자 인식기술 중 하나인 OCR을 활용한 예이다. 음성인식과 음성합성기술을 이용 시 똑 같은 방법으로 번역된 음성파일을 대치하는 방식으로 확장 할 수 있다.

**5.   ****웹 이미지 및 페이지 OCR및 OpenAPI**

**  -  **현 상용 OCR은 독립 어플리케이션으로 되어 있고, 이미지를 파일로 로딩하여 OCR 작업을 수행 후, 정해진 파일 포맷을 로컬 하드디스크에 저장하게 되거나, 선행 특허의 경우, 파일을 업로드 하여 OCR의 결과를 받아보는 시스템으로 되어있다.

**  5.1.     ****차이점 **
5.1.1)     파일을 업로드 하지 않는다.
-       네이버 일본어 번역 처럼, 페이지의 URL을 입력 받는다.
: 해당 웹페이지내에서 이미지 파일들만 OCR로 처리하여 페이지를 재구성하여 리턴한다.
-       이미지 파일 URL을 입력 받아서 해당 이미지 파일만 OCR한 결과를 리턴 할 수도 있다.

5.1.2)     OpenAPI의 활용
-       [http://openocr.naver.com/ocr.nhn?url=http://myhomepage.net/](http://openocr.naver.com/ocr.nhn?url=http://myhomepage.net/)논문.img?language=kor,eng&font=myongjo,arail?outputtype=xml
위와 같이 입력시 리턴 값은 해당 이미지를 XML이나 HTML파일로 리턴 하는 서비스를 말한다.
l  기존 OpenAPI를 이용한 단순한 OCR 활용이라고 할 수도 있겠다.
-       입력값은 이미지 소스를 다운로드 받을수 있는 URL
-       언어나, 폰트, 혹은 텍스트 영역정보 같은 OCR엔진에 의존적인 정보들을 포함 할 수 있다.
이때, 이러한 정보들은 OCR엔진에 따라 OpenAPI규칙을 만들도록 한다.

Currently, Naver Japan or Google recognizers display multimedia files as they are. I've conceived a web service concept that reprocesses and displays multimedia files using recognition technology.

## 1. Title: METHOD, APPARATUS AND COMPUTER-READABLE RECORDING MEDIUM FOR READING TEXT ON IMAGE CONTAINED IN WEB PAGE AND PROVIDING TRANSLATION SERVICE ON SAME TEXT

## 

## {{IMG:1}}

1) IPC Code: G06F 17/28 (2006.01)
2) Application No.: 1020080033923 (2008.04.11)
3) Publication No.: 1020090108485 (2009.10.15)
4) Registration No.: 100953627 (2010.04.12)
5) Inventor/Designer: Yang Byung-seok | Choi Won-hyo
6) Agent: AIP Patent & Law Firm

**2. Draft**

1. Title: Web-based Multimedia Translator Using Recognition Technology
2. Background: Currently, when a web translator is used, data other than text, such as images, videos, and sounds, is not translated. We propose a method to enhance the utility of translators through recognition technology.
{{IMG:2}}
[Limitations of Current Translators]: Foreign languages embedded in images, Flash, and videos are not translated.

2.1 User requests translation of the site to the translator via a query
2.2 The translator downloads and translates the site's data
l At this time, only txt data among the included data is effectively translated.
<img src='[http://yahoo.jp/japan.jpg>](http://yahoo.jp/japan.jpg%3E) 一本
<img src=' [http://yahoo.jp/japan.jpg>](http://yahoo.jp/japan.jpg%3E) Japan
2.3 The translator delivers the translated page to the user

3. Improvement: Requires translation of multimedia files included in the page
3.1 User requests translation of the site to the translator via a query
3.2 The translator downloads and translates the site's data. For multimedia files, a new multimedia file translated via OCR is created.
<img src='[http://yahoo.jp/japan.jpg>](http://yahoo.jp/japan.jpg%3E) 一本
<img src=' [http://trans.naver.com/japan_kor.jpg](http://trans.naver.com/japan_kor.jpg)> Japan
3.3 Replace the link with the changed multimedia file address.
3.4 Deliver this newly created page to the user.

4. Solution to the difficulties of multimedia OCR
- It is very difficult to find text areas within general multimedia files.
Therefore, performance can be improved by allowing the user to specify the desired area.
{{IMG:3}}
- The part indicated by the red line is the page for which the user requested translation with the mouse.
In this case, the user can be informed of the original text extracted via OCR from the image and the translated text result.
l In addition to the area, this can apply to all areas where the user can input additional information such as character count, text skew, inversion, or text color.
l The above example utilizes OCR, one of the text recognition technologies for images. When using speech recognition and speech synthesis technology, it can be extended by replacing the translated audio file in the same way.

**5. Web Image and Page OCR and OpenAPI**

- Current commercial OCR is implemented as a standalone application, loading images as files to perform OCR and then saving the results in a defined file format to a local hard disk, or in the case of prior patents, it is a system where files are uploaded to receive OCR results.

**5.1. Differences**
5.1.1) No file upload.
- Like Naver Japanese translation, it receives the URL of the page as input.
: It processes only image files within the web page using OCR, reconstructs the page, and returns it.
- It can also receive an image file URL as input and return only the OCR result for that image file.

5.1.2) Utilization of OpenAPI
- [http://openocr.naver.com/ocr.nhn?url=http://myhomepage.net/](http://openocr.naver.com/ocr.nhn?url=http://myhomepage.net/)논문.img?language=kor,eng&font=myongjo,arail?outputtype=xml
When input as above, the return value refers to a service that returns the image as an XML or HTML file.
l It could also be considered a simple utilization of existing OpenAPI for OCR.
- The input value is a URL from which the image source can be downloaded.
- It can include OCR engine-dependent information such as language, font, or text area information.
In this case, these pieces of information are used to create OpenAPI rules according to the OCR engine.
