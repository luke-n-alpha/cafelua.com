## 메신저에서 확장된 대화 상대 리스트 및 강화된 대화 기능을 제공하기 위한 방법 및 컴퓨터 판독 가능한 기록 매체

METHOD AND COMPUTER-READABLE RECORDING MEDIUM FOR PROVIDING EXTENDED USER LIST AND ENHANCED DIALOG FUNCTIONS

**IPC 코드 **G06Q 50/00 (2006.01)
**출원번호 **1020070140991 (2007.12.28)
**공개번호 **1020090072777 (2009.07.02)
**등록번호 **100958936 (2010.05.12)
**발명자/고안자** 양병석 | 김형태
**대리인 **특허법인에이아이피

**1. 메신져와 채팅창의 결합**
배경  : 메신져로 친구끼리 대화하는 도중 타자를 함께 대화하고 싶은경우에는 친구를 초대해야만 한다.

**요구사항 : **
* A,B,C 사용자가 모두 친구이고, A,B가 대화를 하는경우, C에게 A-B간의 대화창이 열려있음을 알려주고,
C가 들어올수 있게 한다.

1) 메신져의 대화창에 채팅방명을 설정할수 있도록 한다. (공개되는 채팅방 명)
2) 메신져의 대화창의 공개범위 여부를 설정할수 있도록 한다. (공개가 되지 않아야 하는경우)
3) 혹은 2)번대신, 기존 대화와 달리, 공개대화를 따로 만들수도 있다.

* A,B,C 사용자중 A-B만 친구이고, B-C가 친구인 경우
A-B가 대화중에 C사용자에게 A-B가 대화중임을 알려준다.
C가 들어올수 있게 한다.

* A,B,C 사용자중 A-B만 친구이고, B-C가 친구인 경우
A가 공개대화방을 만들고 기다린다.
B와 C가 들어올수 있게 한다.

* A,B,C 사용자중 A가 B,C 를 D란 그룹에 넣은 상태인데, A-B가 대화중인 경우
A-B가 대화중에 C사용자에게 A가 D그룹의 B와 대화중임을 알려준다.
C사용자가 대화에 참여한다.

* A,B,C 사용자가 D란 카페를 친구추가 하였다.
D카페 그룹 밑에 A가 B와 대화를 한다.
D카페에 소속된 C가 A-B대화에 참여한다.
{{IMG:2}}

* 기존의 채팅창과 같이 방장의 역할이 최초 화자에게 주어지며, 위임이 가능해진다.

* 차별성 :
1) 사용자의 대화창리스트를 메신져에 보여준다. (기존의 채팅창 개념)
2) 사용자의 공개 대화창은 대화자가 없더라도 1인 개설 가능
3) 대화를 시작한 방장은 메신져의 대화창에 제목을 붙이거나,
색깔을 넣거나 하는 등의 꾸미기를 하여 친구들에게 공개되는 대화창모양을 콘트롤 할수 있다.
4) 대화창의 공개여부와 범위를 설정할 수 있다.
공개 범위 : 비공개
< 쌍방의 화자가 함께 속해 있는 그룹/카페 멤버에게 공개
< 한쪽의 화자를 친구로둔 모든 유저에게 공개
< 쌍방의 화자를 친구로둔 모든 유저에게 공개

**2.메신져와 카페 연동기능**
{{IMG:3}}
1) 친구추가
현재 : 메신져는 개인의 이름을 쳐서 사용자를 추가한다.
개선점 : 메신져에 카페아이디를 쳐서 카페를 추가하면
해당 카페아이디를 친구 추가한 모든 사용자들이 카페 그룹밑에 달릴수 있도록 한다.

ex) http://cafe.naver.com/bookcomm.cafe 의 북꼼 카페를 친구 추가
메신져에 카페 추가를 클릭하고 bookcomm을 입력한다.
카페 그룹에 [북꼼]이 추가되고, 아래에 bookcomm을 친구추가한 모든 사용자들이 추가가 된다.

* 카페 가입시 기본으로 메신져 추가가 되도록 설정할수도 있다.
(메신져의 유저 확보)

2) 정팅 예약 및 정팅 포스트 기능
현재 : 카페 사람들끼리 정팅을 할 경우 카페접속 후 대화방 개설을 해야한다.
개선점 : 메신저에 카페 대화방에서 바로 대화 가능하며,
예약을 할 경우 예약시간에 카페 대화방이 자동으로 개설(메신저에도 개설)
카페나 메신저에서 대화 참여 가능
방장 혹은 운영자는 정팅내용을 카페에 포스팅 할 수 있다.

* A system where chat windows for members within a cafe are public, allowing users to join conversations between acquaintances. Its characteristic feature is the ability to add groups (cafes) as friends, not just individuals. (This idea started from a longing for the "jungting" (scheduled chat) nostalgia of old PC communication, wondering what if it were combined with a messenger?) In today's social-centric world, this could be a good system if implemented well.

## Method and Computer-Readable Recording Medium for Providing Extended User List and Enhanced Dialog Functions

METHOD AND COMPUTER-READABLE RECORDING MEDIUM FOR PROVIDING EXTENDED USER LIST AND ENHANCED DIALOG FUNCTIONS

**IPC Code **G06Q 50/00 (2006.01)
**Application No. **1020070140991 (2007.12.28)
**Publication No. **1020090072777 (2009.07.02)
**Registration No. **100958936 (2010.05.12) 
**Inventor/Designer** Yang Byung-seok | Kim Hyung-tae
**Agent **AIP Patent & Law Firm
 
**1. Combination of Messenger and Chat Window**
Background: When friends are chatting via messenger and want to include others in the conversation, they currently have to invite them.
 
**Requirements:**
* If users A, B, and C are all friends, and A and B are chatting, C should be notified that an A-B chat window is open, 
 C should be able to join.
 
1) Allow setting a chat room name in the messenger's chat window. (Public chat room name)
2) Allow setting the public visibility of the messenger's chat window. (For cases where it should not be public)
3) Alternatively, instead of (2), a separate public chat can be created, unlike existing chats.
 
* If among users A, B, and C, only A-B are friends, and B-C are friends, 
  C should be notified that A-B are chatting while A-B are in conversation.
 C should be able to join.
 
* If among users A, B, and C, only A-B are friends, and B-C are friends, 
  A creates a public chat room and waits.
  B and C should be able to join.
 
* If among users A, B, and C, A has put B and C into a group named D, and A-B are chatting,
  C should be notified that A is chatting with B in group D while A-B are in conversation. 
  User C participates in the conversation.
 
* If users A, B, and C have added a cafe named D as a friend.
  A chats with B under the D cafe group.
  C, who belongs to the D cafe, participates in the A-B chat.
 {{IMG:2}}
 
 
 

 
* Similar to existing chat rooms, the role of the host is given to the initial speaker and can be delegated.
 
* Differentiation:
 1) Displays the user's chat window list in the messenger. (Concept of existing chat rooms)
 2) A user's public chat window can be opened by a single person, even without other participants.
 3) The host who started the conversation can control the appearance of the chat window made public to friends by adding a title, 
    or decorating it with colors, etc.
 4) The public visibility and scope of the chat window can be set.
  Public Scope: Private 
              < Public to members of groups/cafes that both speakers belong to 
              < Public to all users who are friends with one of the speakers
              < Public to all users who are friends with both speakers
 
**2. Messenger and Cafe Integration Function**
 {{IMG:3}}
1) Add Friend
Current: Messenger adds users by typing individual names.
Improvement: If a cafe is added to the messenger by typing its cafe ID,
         all users who have added that cafe ID as a friend can be listed under the cafe group.
 
ex) Add "Bookcomm" cafe from http://cafe.naver.com/bookcomm.cafe as a friend.
  Click "Add Cafe" in the messenger and enter "bookcomm".
  "[Bookcomm]" is added to the cafe group, and all users who have added "bookcomm" as a friend are added below it.
 
* It can also be set so that adding to messenger is the default when joining a cafe.
 (Securing messenger users)
 
2) Scheduled Chat (Jungting) Reservation and Post Function
Current: When cafe members want to have a scheduled chat, they must access the cafe and open a chat room.
Improvement: Direct chat is possible in the cafe chat room within the messenger, 
            and if a reservation is made, the cafe chat room is automatically opened at the reserved time (also opened in the messenger).
            Participation in the chat is possible from either the cafe or the messenger.
            The host or operator can post the scheduled chat content to the cafe.
   * If no participants join after a certain period from the scheduled time, the room is automatically closed, and a notification function is provided.
