**1. 객체 지향 이란 ?**
현실 세계의  개체(Entity)를 상태(Attribute)와 행동(Method)을 결합한 객체(Object)란 개념을 중심으로 모델링 하여 시스템을 구현하는 개발 방법론
** 가. 객체 지향의 가치**
- 상속과 다형성을 이용한 확장성, 재사용성
- 실세계의 객체를 개념적 차원에서 지원
****
**2. 객체 지향의 기본 개념**
**  가. 객체 지향의 구성 요소**

| 구성요소 | 의미 |
| --- | --- |
| 객체 | 실세계에 존재하는 개념을 데이터와 함수로 표현 |
| 메시지 | 객체간의 통신 방법 외부 객체의 함수 호출로 객체 데이터에 접근 |
| 클래스 | 같은 종류및 특성을 가친 객체들의 템플릿 |
| 인스턴스 | 클래스가 파생된 실제 객체 |

**  나. 객체지향의 주요 개념**

| **개념** | **의미** | **구현** |
| --- | --- | --- |
| 캡슐화 | 데이터와 함수가 하나로 묶어 박스화 | 어트리뷰트와 메소드의 집합 |
| 정보은닉 | 데이터의 임의 변경을 통제하기 위해 특정함수 통해서만 데이터를 접근 | 퍼블릭 메소드 |
| 다형성 | 같은 함수 이름이 여러 목적에 이용 | 오버로딩 : 메소드 다중 정의 오버라이딩 : 하위 클래스에서 메소드 재정의 |
| 상속성 | 계층 구조를 통해 공통 특성을 상위 클래스로 부터 물려 받는것 | 단일 상속 : JAVA 지원 (보다 명확) 다중 상속 : C++ 지원 (높은 확장성) |

**4.  자바의 인터페이스의 개념**
- 추상 메소드(인스턴스화 되기 위해서는 구상 메소드가 반드시 필요한 클래스)와 파이널 변수(변경이 불가한 정적 변수)로만 이루어진 클래스
** 가. 용도**
1. 관련없는 클래스들 상이의 유사성을 나타내야 할 경우
2. 공통으로 구현하기를 원하는 메소드를 선언할 경우
3. 클래스를 은닉한체 프로그래밍 인터페이스만 보여주어야 할 경우
** 나. 인터페이스의 상속과의 차이점**
- 하나의 클래스에 여러 인터페이스를 적용 가능
- 상수만을 상속
- 클래스 계층 구조와 무관
** 다. 문법**
접근지정자 class [extends 클래스이름]  implements 상위인터페이스리스트 {
// 인터페이스에 선언된 메소드 구현

**6. OR-MApping (객체 관계 맵핑)**
- OO프로그래밍시 클래스와 데이터 저장소로 이용될 RDBMS의 테이블간 맵핑
** 가. OOP 코드와 RDBMS의 맵핑**

| **OOP 코드** | **맵핑 내용** | **데이터베이스** |
| --- | --- | --- |
| class | 실세계의 엔티티 | table |
| attribute | 엔티티의 속성값 | column |
| Class Relationship | 엔티티간의 관계 | Relational Relationship |

**  나. OOP와 RDBMS의 Relation(관계) 맵핑****

| **OOP 관계** | **내용** | **데이터베이스 설계, 구현** |
| --- | --- | --- |
| Association(연관) | 엔티티간의 관계 | ER 다이어그램 1:M, 1:1, M:M 맵핑 |
| Aggregation(집합연관) | 느슨한 연관 관계 | Foreign Key 생성 |
| Composition(복합연관) | 생명주기 동기화 | Delete Cascading 이용 |
| Generalization(일반화) | 상속 관계 | - 부모객체와 자식객체의 정보를 1개의 테이블에 저장하는 방법 - 부모객체에 해당되는 1개의 테이블과 자식객체의 특정 속성만을 가지고 있는 각각의 테이블 - 부모객체, 자식객체의 정보를 따로따로 가지고 있는 별도의 테이블들. |

다. 코드쪽의 ORMapping 접근
- DAO interface이용
- 쿼리와 컬럼을 XML 로 정의
- XML 을 파싱하여 DAO 객체를 바인딩
- 실졔 사용 예 : iBatis

**1. What is Object-Oriented?**
  A development methodology that implements systems by modeling real-world entities (Entity) around the concept of an object (Object) that combines state (Attribute) and behavior (Method).
** a. Value of Object-Oriented Programming**
  - Extensibility and reusability using inheritance and polymorphism
  - Supports real-world objects at a conceptual level
**** 
**2. Basic Concepts of Object-Oriented Programming**
**  a. Components of Object-Oriented Programming**

| Component | Meaning |
| --- | --- |
| Object | Represents concepts existing in the real world with data and functions |
| Message | Method of communication between objects; accesses object data by calling functions of external objects |
| Class | A template for objects with the same kind and characteristics |
| Instance | An actual object derived from a class |

**  b. Key Concepts of Object-Oriented Programming**

| **Concept** | **Meaning** | **Implementation** |
| --- | --- | --- |
| Encapsulation | Data and functions bundled into one box | Collection of attributes and methods |
| Information Hiding | Controls arbitrary changes to data by accessing it only through specific functions | Public Method |
| Polymorphism | The same function name is used for multiple purposes | Overloading: Multiple method definitions; Overriding: Redefining methods in a subclass |
| Inheritance | Inheriting common characteristics from a superclass through a hierarchical structure | Single Inheritance: Supported by JAVA (more explicit); Multiple Inheritance: Supported by C++ (higher extensibility) |

**4. Concept of Java Interface**
 - A class composed only of abstract methods (a class that requires concrete methods to be instantiated) and final variables (static variables that cannot be changed).
** a. Usage**
   1. When similarity between unrelated classes needs to be expressed
   2. When declaring methods that are desired to be commonly implemented
   3. When only the programming interface should be shown while the class is hidden
** b. Differences from Class Inheritance**
   - Multiple interfaces can be applied to a single class
   - Inherits only constants
   - Independent of class hierarchy
** c. Syntax**
  access_modifier class [extends ClassName] implements InterfaceList {
   // Implement methods declared in the interface
   }

| Development Pattern | - Developers develop all programs in detail - Lack of standards - White Box level framework | - Focus on combining provided components with business tasks - Provides standard interfaces |

**6. OR-Mapping (Object-Relational Mapping)**
 - Mapping between classes in OO programming and RDBMS tables used as data storage.
** a. Mapping between OOP Code and RDBMS**

| **OOP Code** | **Mapping Content** | **Database** |
| --- | --- | --- |
| class | Real-world entity | table |
| attribute | Attribute value of an entity | column |
| Class Relationship | Relationship between entities | Relational Relationship |

 
**  b. Mapping OOP and RDBMS Relations**

| **OOP Relationship** | **Content** | **Database Design, Implementation** |
| --- | --- | --- |
| Association | Relationship between entities | ER Diagram 1:M, 1:1, M:M mapping |
| Aggregation | Loose association | Foreign Key creation |
| Composition | Lifecycle synchronization | Using Delete Cascading |
| Generalization | Inheritance relationship | - Method of storing parent and child object information in one table - One table corresponding to the parent object and separate tables each containing only specific attributes of child objects - Separate tables holding parent and child object information independently. |

 
  c. ORMapping Approach on the Code Side
  - Using DAO interface
  - Defining queries and columns in XML
  - Parsing XML to bind DAO objects
  - Actual usage example: iBatis
