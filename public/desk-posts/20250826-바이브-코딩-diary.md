Normally, when developing, one would look at functions and parameters and draw the call stack and the flow of key parameters in their head... but it seems to understand code by drawing a picture through token search. Rather than reading along the logic, it reads the code sparsely and grasps its structure. When developing after design, it seems to create a low-resolution design and then increase the resolution for each function. The problem is that while this is suitable for new development, it's an impossible method for understanding existing logic. Because it can only see a very small scope and perform narrow tasks, in small codebases, a low depth of context and code is maintained, but in large codebases, the gap in understanding of the structure and details seems to widen.
I suspect that scope probably doesn't even exceed a few thousand lines. It thinks it's holding a lot of context in its head, but in reality, it seems to lack contextual information about which functions and parameters are important.
As a result, the current task of converting from structure A to structure B, which I'm having it do, is impossible. It can only maintain context within a very small scope. In a large scope, even with the same pattern, errors seem to accumulate.
Ah... what to do about this. Andrej Karpathy said he was "vibing" his code, but in reality, he was just checking small ranges of suggested code with tap-tap, and was frustrated with agent mode... was that the best option after all? I feel like I've wasted almost 1.5 days. In the end, I guess I'll have to visually understand the code and then verify it as I transfer the structure. It seems to take an immense effort to properly recognize what AI can and cannot do.
