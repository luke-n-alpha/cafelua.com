왜 이런 결과가 나왔을까?

결론은 단순하다. 유저가 느끼는 웹표준, 곧 크로스브라우져 대책은 웹표준만으로 해결되지는 않는다.
웹표준을 지키면 크로스브라우징을 할 때 공수가 적게 들 가능성이 높지만, 그것만으로 유저가 원하는 수준의 크로스브라우져 문제가 해결되는것이 아니다.
예를들어 QA에서 가끔은 핸드오버 기능을 요구한다. 마우스가 손모양으로 바뀌는것이 왜 파이어 폭스에서 되지 않느냐고 불만을 올린건데. 이는 웹표준이 아니다. 유저가 원하는 것은 모든 브라우져에서 똑같이 사용하길 바라지만, 사실은 그것은 기능을 제한해야 한다는 이야기일 수 밖에 없다.
google처럼 단순한 페이지는 그만큼 공수가 적게 든다. 테스트하는데도 오래걸리지 않고, 한 페이지에서 할수 있는 작업이 적으므로 Test Case가 그만큼 작아지는 것이다.

Surprisingly, the top 3 domestic portals adhered well to web standards.
Conversely, Google and Apple, which were expected to perform well, had poor scores.
MSN, often called the 'axis of evil' for web standards, passed.
Yahoo, surprisingly, showed 681 errors and 192 warnings.

Why did these results appear?

The conclusion is simple. The web standards perceived by users, or rather, cross-browser compatibility, cannot be solved by web standards alone.
Adhering to web standards likely reduces the effort required for cross-browsing, but it alone does not resolve cross-browser issues to the level users desire.
For example, QA sometimes requests a 'handover' function. A complaint was raised about why the mouse cursor doesn't change to a hand shape in Firefox. This is not a web standard. Users want to use everything identically across all browsers, but in reality, this often means limiting functionality.
Simple pages like Google's require less effort. Testing doesn't take long, and since there are fewer operations possible on a single page, the number of test cases is proportionally smaller.

Perhaps the multi-platform experience users perceive is closer to Mobile OK's web standards than to www's web standards.
This is because the specifications of mobile environments, which demand minimal specs, are commonly handled by most browsers.

Web standards are not a panacea. They are merely recommendations, and cross-browsing requires extensive testing and QA. Simply adhering to standards doesn't solve everything. It seems there's too much blind faith in them these days, perhaps as a reaction to demonizing MS.

There's a very simple way to adhere to web standards: don't use scripts and create simple pages.
But would users truly be satisfied with such a web? User expectations are beyond mere web standards.

Web standards are not entirely synonymous with cross-browser compatibility.
Furthermore, the issue of cross-browser compatibility is not a matter of good or evil; it's now a matter of competitiveness, requiring more strenuous effort than simply following web standards.
