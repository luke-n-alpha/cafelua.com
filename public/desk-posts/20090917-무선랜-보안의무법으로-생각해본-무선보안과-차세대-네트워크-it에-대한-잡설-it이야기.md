1. 왜 무선랜 보안이 문제인가 ?
무선랜 보안법인가 뭔가가 생기는 모양입니다. 이 법이 정말 이동통신사의 압력이 작용했는지 안했는지는 모르겠으나 기술적으로는 무선랜이 취약한것은 사실입니다.

참고 : http://www.ddaily.co.kr/news/news_view.php?uid=32121[[집중기획-무선랜+보안①] 취약성 무방비 노출, 무선랜 보안실태 ‘심각’](http://www.ddaily.co.kr/news/news_view.php?uid=31864)

법의 근거로 든 DDOS문제도 신문의 이야기도 꼭 틀린것은 아닙니다. DDOS의 클라이언트가 무선을 통해  더 많이 전파 되는지 혹은 무선을 경유해 더 많이 타겟을 공격하는지는 모르겠으나 기업 보안 측면에서 무선보안이 걸리는 것은 분명합니다.
무선 사용자는 기업외 뿐만이 아니라 기업내에도 존재합니다. 그리고 이들은 기업에서 통제를 못하고 있는 무선을 통해 침입경로가 되거나 내부망내의 DDOS봇이라도 된다면 비싼 보안장비를 유명무실하게 만듭니다. 무선의 통제가 어려운 이유는 가입과 탈퇴가 자유롭고 와이브로나 hsdpa처럼 기업내에서 통제가 어려운 망 또한 존재하기 때문이기도 합니다. 유선랜을 통해 보안에 허용받은 내부망에 물려있고 무선망을 통해 별다른 보안 조치없는 외부 무선망에 물려있다면 해커가 해당 pc를 점령한다면 어려운 보안장비를 해킹할 필요가 없게 되는 것이죠.
유저들 중에는 공유폴더만 안만들면 된다.로 잘못 인식하는 분들도 많은 것 같습니다. 공유폴더는 하나의 서비스일 뿐입니다. 윈도우즈 OS가 침입되는 경로는 공유폴더 하나가 아니고 공유폴더를 안 쓰더라도 침입된 사례는 많습니다. 기업에서는 대부분 보안상의 이유로 아예 공유폴더나 ftp같은 서비스를 금지시키는 경우도 많습니다. 윈도우즈가 아니고 리눅스를 쓰더라도 마찬가지입니다. 공격빈도의 문제지 리눅스도 취약점 패치가 안올라오는 것이 아니고 기업의 주요 서버는 대부분 윈도우가 아닌 관계로 실제 해커들이 자주 공격하는 가치있는 시스템은 윈도우가 아닌 것이 더 일반적입니다.

2. 적절한 수준의 보안은 필요하며 공유의 정신과는 별개입니다.
가장 이상적인 보안은 인터넷을 쓰지않고 물리적으로도 격리된 곳에 두는 것이라는 말까지 있습니다. 그렇다고 인터넷이나 무선랜이 주는 편리함을 버릴 수는 없을 것이기에 적절한 수준의 통제와 보안이 필요한 것입니다. 대부분의 무선공유기를 구매하는 경우 기본값이 보안 설정이 필요없게나옵니다. 이는 마치 웹서버의 관리자 비밀번호를 기본값으로 해두는 것과 별 다를바가 없습니다. 새 아파트에 입주하면서 전자좌물쇠의 비밀번호를 바꾸지 않는 사람은 거의 없겠지만 무선공유기의 경우에는 사정이 다릅니다.
- 좀 쉽게 안되겠니 ? -
해당 설정을 해야하는지 모르는 분들도 있고 이미 암호가 깨진 알고리즘을 선택해서 적용한 경우나 무선 인터넷전화의 공유기도 사업자에서 선정해주는 기본 암호를 설정해두는 경우가 빈번합니다.
사실은 저도 그렇게 해놓았죠. 제가 피해를 받아봐야 얼마나 받겠냐는 안이함도 있지만 무선기기들을 보안 설정하는게 얼마나 귀찮은 일인지 잘압니다. ip가 뭔지도 모르는 분들이 mac같은 것을 알아 보안설정을 기대하기는 어려울것입니다. 따라서 중요한 것은 허용가능한 유저들에게는 손쉬운 제품과 기술이 필요한 시점입니다.
이동통신사의 음모론의 진위를 파악하기 위해서는 전세계적인[무선랜 공유 운동의 FON](https://www.fon.com/kr/info/whatsFon)이 위법인지를 한번 살펴봐야 할 것입니다. 분명 이러한 공유운동이나 해외의 Public wifi도 보안은 고려가 되어있으며 암호화는 기본입니다.

3. Qos를 보장하고 공유가 가능한 네트워크가 필요합니다. 더 나가 Adhoc Mesh Network를 꿈꿉니다.

개인적으로 개인 무선망의 대역폭만 보안적으로 완전히 격리시켜 외부 유저에게 adhoc 형태로 오픈하고 개인은 Qos를 보장받을 수 있는 구조가 되었으면 하고 바래봅니다. 그렇다면 동영상 다운로드 같은 경우는 무선 내부망에서 충분히 보장받고 나가서는 이런 adhoc 매쉬 네트웤크를 이용해 인터넷을 이용하고 타인에게도 공유 할 수 있지 않을까요? Qos를 보장하기 위해서는 인증및 보안은 필수 요소가 될겁니다.
무선망을 마음대로 이용하게 해달라는 아이폰등의 스마트폰의 경우에도 adhoc 매쉬를 전혀 지원하지 않는 것은 사용만 하겠다는 것이지 네트워크 자원을 주지 않겠다는 도둑놈 심보같다는 생각도 들곤합니다. 물론 이동통신사 입장에서는 AP가 폭발적으로 늘어버리는 정말 adhoc이야 말로 재앙일 수 있겠고 스마트폰의 경우 망 사용중에는 배터리 소모가 더 많아질 것입니다만 적정만큼의 열린 자원을 사용하겠다면 자신의 자원도 나누어주는 기술적 준비도 필요하다고 봅니다.

1. Why is wireless LAN security a problem?
It seems that some kind of wireless LAN security law is being created. Whether or not this law was influenced by pressure from mobile carriers, it is technically true that wireless LANs are vulnerable.

Reference: http://www.ddaily.co.kr/news/news_view.php?uid=32121[[Special Feature - Wireless LAN Security ①] Vulnerability Exposed Defenselessly, Wireless LAN Security Status 'Serious'](http://www.ddaily.co.kr/news/news_view.php?uid=31864)

The DDOS issue cited as the basis for the law, and the newspaper's story, are not entirely wrong. I don't know if DDOS clients spread more widely via wireless or attack targets more via wireless, but from an enterprise security perspective, wireless security is definitely a concern.
Wireless users exist not only outside the enterprise but also within it. And these users, through uncontrolled wireless networks within the enterprise, can become an intrusion path or even a DDOS bot within the internal network, rendering expensive security equipment useless. The difficulty in controlling wireless networks is also due to the freedom of joining and leaving, and the existence of networks like WiBro or HSDPA that are difficult for enterprises to control. If a PC is connected to an internal network allowed for security via a wired LAN, and also connected to an external wireless network without separate security measures via a wireless network, a hacker who takes over that PC wouldn't need to hack difficult security equipment.
Many users seem to mistakenly believe that as long as they don't create shared folders, they'll be fine. Shared folders are just one service. The Windows OS can be infiltrated through more than just shared folders, and there are many cases of infiltration even without using shared folders. In enterprises, for security reasons, shared folders or FTP services are often completely prohibited. The same applies even if you use Linux instead of Windows. It's a matter of attack frequency; Linux also receives vulnerability patches, and since most major enterprise servers are not Windows, it's more common for valuable systems frequently attacked by hackers not to be Windows.

2. An appropriate level of security is necessary and separate from the spirit of sharing.
There's even a saying that the most ideal security is to not use the internet and to keep things physically isolated. However, we cannot abandon the convenience that the internet and wireless LANs provide, which is why an appropriate level of control and security is needed. Most wireless routers come with default settings that do not require security configuration. This is no different from leaving the administrator password of a web server at its default value. While almost no one would move into a new apartment and not change the password of the electronic lock, the situation is different for wireless routers.
- Can't it be a bit easier? -
Many people don't know that they need to make these settings, or they choose and apply an already broken encryption algorithm, or they leave the default password set by the carrier for wireless internet phone routers.
Actually, I've done that too. There's a complacency that I won't suffer much damage, but I also know how annoying it is to set up security for wireless devices. It would be difficult to expect people who don't even know what an IP is to understand MAC addresses and set up security. Therefore, what's important now is the need for easy-to-use products and technology for authorized users.
To ascertain the truth of the mobile carrier conspiracy theory, one should examine whether the global [FON wireless LAN sharing movement](https://www.fon.com/kr/info/whatsFon) is illegal. Clearly, such sharing movements and public Wi-Fi abroad also consider security, and encryption is standard.

Although I haven't thoroughly examined the bill, I believe that an appropriate level of wireless security is necessary, and network sharing should occur under that security level.

3. We need a network that guarantees QoS and allows sharing. Furthermore, I dream of an Adhoc Mesh Network.
Reference: [Wikipedia QoS](http://ko.wikipedia.org/wiki/QoS)
Personally, I hope for a structure where the bandwidth of a personal wireless network is completely isolated for security, opened to external users in an ad-hoc manner, and individuals can be guaranteed QoS. In that case, wouldn't video downloads be sufficiently guaranteed within the internal wireless network, and then outside, one could use the internet via such an ad-hoc mesh network and share it with others? To guarantee QoS, authentication and security would be essential elements.
Even for smartphones like iPhones, which demand free use of wireless networks, the complete lack of ad-hoc mesh support feels like a thief's mentality—they only want to use it but not contribute network resources. Of course, from the mobile carrier's perspective, an explosive increase in APs, truly an ad-hoc scenario, could be a disaster, and for smartphones, battery consumption would increase during network usage. However, if one intends to use a reasonable amount of open resources, I believe technical preparation to share one's own resources is also necessary.
{{IMG:2}}
Next-generation networks are predicted to be low-power ad-hoc mesh networks all the way to the end devices. Currently, networks still seem closer to a star topology, centered around ISPs, and then regions and home gateways.

Such advanced related technologies have been around for quite some time and have been considered "up-and-coming" for a long time.
**When the internet first emerged, security issues could not be considered, but now we are ready to address security issues alongside it. If we remain an IT powerhouse only in name, boasting about being 1st or 2nd in infrastructure alone, without also becoming a software powerhouse, a green internet powerhouse, and a security powerhouse, it might be like someone proudly driving a sports car while enjoying reckless driving—a ridiculous sight.**
