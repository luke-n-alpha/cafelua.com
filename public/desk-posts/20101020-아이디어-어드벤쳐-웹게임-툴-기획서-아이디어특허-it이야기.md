이전에 한번 올린적이 있던 자료지만, 비쥬얼 노블에 관한 포스트를 작성하면서 생각난김에 ppt자료를  게시물 형태로 다시 올립니다. 혼자 만들어볼까 하다가 못한 놈이죠. 디자인은 네이버 블로그에서 차용했습니다. 목표는 사실 비쥬얼 노블을 웹에서 만들고 공유하고 즐길수 있는 툴을 만들자는거였죠. 비쥬얼 노블은 어드벤쳐 게임의 한 장르입니다. 요즘엔 스토리 몰입도가 높은 어드벤쳐 게임들이 줄어서 아쉽습니다. 이 아이디어 기획서는 최초 생각한건 꽤 오래전 일입니다. 언제인지도 가물가물하네요. 2008년이었나 ?

**1. 시스템 개괄도**
{{IMG:1}}

기본적으로 게임을 UCC로 만들어 보자 라는 개념이다.
사용자에 의해 만들어지는 게임데이터는 게시물과 같은 성격을 가진다.
- 웹 게임은 다양한 장르를 구현할수 있으나 어드벤쳐 는 사용자가 손쉽게 게임을 개발할수 있는 형태이기 때문이다.

**2. 1차 목표 북게임 :
**
{{IMG:2}}

기본적으로 오프라인에서 제공되어지는 책형태의 게임이다. 각 페이지를 읽고, 내용에서 지시하는 페이지로 이동하면서 게임을 즐긴다.
: 특별한 파라미터는 존재하지 않고, 파라미터가 존재하더라도, 사용자의 기억력에 의존한다.

**3. 2차 목표 비쥬얼 노블 어드벤쳐
**
{{IMG:3}}
특정 파라미터들이 시스템에서 존재하며, 파라미터의 값에 따라 선택 가능 여부가 틀려진다. 특정 이벤트를 수행했는지에 따라 게임의 분기가 달라진다. 파라미터값은 수행여부(Boolean), 수치(Int), 입력값(String)가 될수 있다. 고려해야할 요소가 매우 많아 지게 된다.

**4. Scean**
4.1. 어드벤쳐의 한장의 이벤트를 Scean이라 표현한다. 일종의 게시물과 동일한 개념이나 Open Scean을 제외한 Scean은 다른 Scean의 Link에 의해 진입이 된다.
4.2. 각 Scean은 이미지, 텍스트, BGM으로 이루어지며 이는 웹의 일반 게시물과 동일하다.
4.3. 게시물과 다른점은 각 Scean은 다른 Scean과 연결된 1개이상의 분기를 가지게 된다. (엔딩의 경우 분기가 없을수도 있다)
4.4. 2차목표의 경우에는 파라미터에 따라 분기의 활성화 여부를 판단할수 있으며, 각 Scean에서 특정 파라미터값을 입력받거나 자동으로 취득할수 있다.
4.5. 1개의 게임은 n개의 Scean으로 이루어져 있으며 Scean간의 유기적인 관계로 게임이 이루어진다. 권한이 있는 유저는 Scean에디터를 통해 Scean을 만들어나가고 수정할수 있다.
4.6. 플레이 시간이 긴 게임을 플레이 하기 위해서 플레이어의 정보를 저장할수도 있다.
- 또한 완결이 제작중인 게임의 경우도 플레이 중 저장하고 나갈수도 있다. 이때, 플레이어가 플레이중인 Scean시리얼 넘버와 플레이어의 파라미터들이 저장된다.
이는 미완성된 게임의 경우도, 제작자가 다음 이야기를 완성할때까지 기다렸다 다시 플레이 할수 있다.
이는 연재소설의 경우 기다렸다가 해당위치부터 읽는것과 동일한 개념이다.
* 유저가 플레이중인 Scean은 수정,삭제할수 없다.

- 2차목표 : 당신의 이름은 무엇입니까? (String입력)

**10. 복수의 타인에게 제작권한 부여 (공동 개발)**
- 일반적으로 분기가 많아지면, 혼자 스토리를 진행해나가기가 어려워지고 내용이 방대해지게 된다. 혹은 제작을 더 이상 하고 싶지 않으나, 누군가 파생 게임을 만들고 싶어할수 있다. 이때 제작권한을 복수의 타인에게 부여 할수 있다.
- 릴레이 소설, 혹은 연애 시뮬레이션을 상상할경우 각 캐릭터간의 스토리를 따로 다른 사람이 작성할수 있다.
- 카페에서 복수의 사람들이 제작할수도 있다.
- 프롤로그는 처음 게임 개발을 시작한 발제자가 제작권한을 부여하는 권한을 갖는다.
- 프롤로그는 처음 게임 개발을 시작한 발제자만 에디팅할수 있다.
- 그룹으로 권한을 부여할수도 있다.
- 복제 권한 부여 : 타인에게 현재까지 개발한 모든 게임데이터를 복제해서 주면서, 그 데이터를 받는 사람은 발제자와 같은 권한을 갖는다.

Although this material was uploaded once before, while writing a post about visual novels, it came to mind, so I'm re-uploading the PPT material as a post. It's a project I tried to make myself but couldn't finish. The design was borrowed from Naver Blog. The actual goal was to create a tool that allows visual novels to be created, shared, and enjoyed on the web. Visual novels are a genre of adventure games. It's a shame that adventure games with high story immersion are becoming fewer these days. This idea proposal was first conceived quite a long time ago. I can't even remember when. Was it 2008?

**1. System Overview**
{{IMG:1}}

The basic concept is to create games as UCC (User Created Content).
Game data created by users has the nature of a post.
- While web games can implement various genres, adventure games are a form that allows users to easily develop games.

**2. First Goal: Book Game**
{{IMG:2}}

It's basically a book-shaped game provided offline. Players enjoy the game by reading each page and moving to the page indicated by the content.
: No special parameters exist, and even if they do, they rely on the user's memory.

**3. Second Goal: Visual Novel Adventure**
{{IMG:3}}
Specific parameters exist in the system, and the availability of choices changes depending on the parameter values. The game's branching changes based on whether certain events have been performed. Parameter values can be boolean (completion status), integer (numerical value), or string (input value). The number of elements to consider becomes very large.

**4. Scean**
4.1. A single event in an adventure is expressed as a Scean. It's a concept similar to a post, but Sceans, excluding Open Sceans, are entered via links from other Sceans.
4.2. Each Scean consists of images, text, and BGM, which is the same as a general web post.
4.3. The difference from a post is that each Scean has one or more branches connected to other Sceans. (In the case of an ending, there may be no branches)
4.4. For the second goal, the activation status of branches can be determined by parameters, and specific parameter values can be input or automatically acquired within each Scean.
4.5. One game consists of n Sceans, and the game is formed by the organic relationship between Sceans. Authorized users can create and modify Sceans through the Scean editor.
4.6. To play games with long playtimes, player information can be saved.
- Also, even for games currently under development, players can save and exit during play. In this case, the Scean serial number the player is currently playing and the player's parameters are saved.
This means that even for unfinished games, players can wait until the creator completes the next part of the story and then play again.
This is the same concept as waiting for a serialized novel and then reading from that specific point.
* Sceans currently being played by users cannot be modified or deleted.

- Second Goal: What is your name? (String input)
(Hidden Event: In this Scean, affection increases by 2.)

**5. First Goal Game Structure**
{{IMG:6}}
5.1. Prologue Data: The representative post created when a game is first made.
Creator User Information
It's a page that introduces what kind of game it is.
It can be seen as similar to Naver's mobile game introduction page.
[http://mgame.naver.com/skt/gameView.nhn?cid=01102023](http://mgame.naver.com/skt/gameView.nhn?cid=01102023)

5.2. Permission Data:
Playability
Public/Private Status
Editing Permissions (for games where multiple users can edit)
Playing Permissions (Public only to mutual friends, Public only to cafe members)

**6. Game Post**
{{IMG:7}}
* Created games are treated like posts.
They can be scraped to blogs, shared and enjoyed in cafes, and when scraped, the original creator's game introduction cannot be modified,
only additional content can be added to the post.
- This means game posts are treated similarly to Oekaki or videos.
Clicking 'Write Game Comment' means commenting on the game's prologue, not the post itself. In this case, even if scraped, comments can be viewed identically across all posts, and the game creator can observe player reactions.

**The SeanList is visible only to users with creation permissions, in the form of blog or cafe categories and lists.**
**Users with public permissions can publish created games to cafes, open games, and blogs, and they are registered as posts.**
- When players add game comments to a game, they are automatically attached to the prologue.

**10. Granting Creation Rights to Multiple Others (Collaborative Development)**
- Generally, as branches increase, it becomes difficult to proceed with the story alone, and the content becomes vast. Or, a creator might no longer want to continue, but someone else might want to create a derivative game. In such cases, creation rights can be granted to multiple others.
- Imagining a relay novel or a dating simulation, different people can write separate stories for each character.
- Multiple people can also create in a cafe.
- The prologue grants the initial game developer the authority to assign creation rights.
- Only the initial game developer can edit the prologue.
- Permissions can also be granted to groups.
- Granting duplication rights: All game data developed so far can be duplicated and given to others, and the recipient of that data has the same rights as the initiator.
-> It's a kind of bridge concept.

**11. Scope of Application for the First Goal**
- Book-game type games
- Serialized novels
- Continuous lectures
- Quizzes
- Psychological tests with a linked structure
