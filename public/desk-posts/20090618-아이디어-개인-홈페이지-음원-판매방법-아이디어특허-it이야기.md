****
**1.     제목 : 개인 홈페이지 음원 판매방법**
2.     작성일 : 2008년 2월 12일
3.     배경 : 개인 유저들의 홈페이지에 합법적으로 음악을 거는 방법이 부재하다.
저작권에 대한 관심이 높아지고, 법령이 강화 됨에 따라 해당 기술의 니즈가 발생하고 있다.

4.     문제점 : 저작권 문제, 어뷰징 문제

5.     요약 : 포탈에서 구매한 음원을 개인 홈페이지에서 이용 할 수 있는 방법을 서술 한다.
크게 배경음악 서비스와 게시물 음원 삽입 서비스로 나누어진다.

6.     구현 방법 : 위젯과 네이버에 로그인한 유저가 아이템팩토리에서 음원을 구매한다.
사용할 홈페이지의 url을 등록하고 플레이어 위젯을 선택한다.
사용할 자바스크립트 혹은 플래시 소스를 발급한다. 혹은 오픈 api를 제공한다.
플레이요청이 유저로부터 오면 래퍼러를 통해 등록된 사이트로 부터 온 래퍼러인지 확인을 한다.
등록된사이트로부터온 래퍼러인 경우에만 위젯은 정상동작한다.

l  배경음악 등록
1)     네이버에 로그인 한 후, 외부 플레이가 가능한 음원을 구매한다.
2)     해당 음원이 서비스될 url을 등록한다.
3)     플레이어 스킨과 플레이 리스트를 선택한다.
4)     네이버는 해당 url과 쌍으로 되는 key가 포함된 음원 위젯 삽입 소스를 발급한다.
Ex) <embed src=[http://myhomemusic.naver.com/player.swf?key=45930](http://myhomemusic.naver.com/player.swf?key=45930)></embed>
5)     사용자는 해당 소스를 홈페이지에 삽입한다.
6)     네이버 플레이어는 플레이시, refer와 key값을 통해 해당 플레이가 정상적인 호출인지 확인하고 음원을 플레이 한다.
7)     유저는 배경음악 음원 리스트를 네이버에 로그인 하여 변경하거나 관리 할 수 있다.

l  게시판의 음원 컨트롤
1)     네이버에 로그인 한 후, 외부 플레이가 가능한 음원을 구매한다.
2)     해당 음원이 서비스될 url을 등록한다.
3)     네이버는 해당 url과 쌍으로 되는 key를 유저에게 알려준다.
4)     파워에디터의 컨트롤이나 제로보드xe의 위젯 형태로 사용자는 사용할 수 있다.
5)     해당 컨트롤이나 위젯은 처음 네이버에 음원 삽입을 요청할 때, key값을 묻는다.
6)     유저가 해당 key값을 입력한다.
7)     해당 컨트롤이나 위젯은 해당 key값으로 네이버에게 음원 리스트를 요청한다.
8)     유저는 음원리스트 중 삽입할 음원들을 선택 한다.
9)     블로그의 음악삽입 서비스와 동일하게 음원이 삽입된다.

l  키값을 발급받는 것이 어려운 유저들은 제로보드 xe에 네이버 아이디와 비번을 등록하면, 제로보드는 해당 아이디와 비번을 암호화 시켜 기억하고 있으면서 네이버와 인증과정을 통해 동일하게 동작하게 할 수도 있다.
-      제로보드 xe는 소스화되어 동작 하므로 보안상 감추어야 할 모듈들은 flash형태로 전달한다.

l  제공방법
: openAPI 이용, 인증 key값과 refer 정보 확인후, mms프로토콜을 이용해 음원의 휘발성 url을 제공한다.
(개발자적 접근 용이, 확장성 높음, 보안이 약함)
: embed object 이용, 플래시나 실버라이트등의 embed객체를 통해 네이버내에서 직접 서비스한다.
(이 경우, 유저 이용편리, 확장성 낮음, 보안이 높음, 관리의 용이, 스킨 제공가능)

**1. Title: Method for Selling Music on Personal Websites**
2. Date of Creation: February 12, 2008
3. Background: There is no method for individual users to legally embed music on their websites. As interest in copyright increases and laws are strengthened, a need for this technology is emerging.

4. Problems: Copyright issues, abuse issues

5. Summary: Describes a method for using music purchased from a portal on a personal website. It is largely divided into background music services and post music embedding services.

6. Implementation Method: A user logged into Naver purchases music from Item Factory using a widget. The URL of the website to be used is registered, and a player widget is selected. JavaScript or Flash source code for use is issued. Alternatively, an open API is provided. When a play request comes from a user, it is checked via the referrer to see if it came from a registered site. The widget operates normally only if the referrer is from a registered site.

l Background Music Registration
1) After logging into Naver, purchase music that can be played externally.
2) Register the URL where the music will be serviced.
3) Select the player skin and playlist.
4) Naver issues music widget embedding source code containing a key paired with the URL.
Ex) <embed src=[http://myhomemusic.naver.com/player.swf?key=45930](http://myhomemusic.naver.com/player.swf?key=45930)></embed>
5) The user embeds the source code on their website.
6) When played, the Naver player verifies if the play is a legitimate call using the referrer and key value, then plays the music.
7) Users can change or manage their background music playlist by logging into Naver.

l Music Control in Bulletin Boards
1) After logging into Naver, purchase music that can be played externally.
2) Register the URL where the music will be serviced.
3) Naver informs the user of the key paired with the URL.
4) Users can use it in the form of a Power Editor control or a Zeroboard XE widget.
5) When first requesting music embedding from Naver, the control or widget asks for the key value.
6) The user enters the key value.
7) The control or widget requests the music list from Naver using that key value.
8) The user selects the music to embed from the music list.
9) The music is embedded in the same way as the blog music embedding service.

l Users who find it difficult to obtain a key value can register their Naver ID and password with Zeroboard XE. Zeroboard XE can then encrypt and remember these credentials, allowing it to function identically through an authentication process with Naver.
- Since Zeroboard XE operates as source code, modules that need to be hidden for security reasons are delivered in Flash format.

l Provision Method
: Using openAPI, after verifying the authentication key value and referrer information, a volatile URL for the music is provided using the MMS protocol. (Easy for developers, high scalability, weak security)
: Using an embed object, directly service within Naver via embed objects like Flash or Silverlight. (In this case, convenient for users, low scalability, high security, easy management, skin provision possible)
