켄트백이 바이브 코딩 용어대신 증강형 코딩이라는 용어를 가져왔는데 저희가 추구하는 바이브 코딩과 유사해서 공유드립니다. 원문 :

[**Augmented Coding: Beyond the Vibes** Notes from a technically challenging project tidyfirst.substack.com](https://tidyfirst.substack.com/p/augmented-coding-beyond-the-vibes)

[https://tidyfirst.substack.com/p/augmented-coding-beyond-the-vibes](https://tidyfirst.substack.com/p/augmented-coding-beyond-the-vibes)사실 저도 바이브 코딩 보다는 AI기반의 개발방법론이나 AI코딩이라는 용어가 더 어울린다고 생각하지만, 그래도 바이브 코딩이 가진 브랜드 파워 때문에 이를 밀고 있긴 합니다. 그렇게 바이브하지는 않지만 바이브할때까지 열심히 해보려고 합니다.​​

Kent Beck은 "Augmented Coding"과 "Vibe Coding"을 프로그래밍 워크플로우의 완전히 새로운 영역을 탐색하는 두 가지 다른 접근 방식으로 명확하게 구분하며, 특히 **코드 자체의 품질과 개발자에 의한 통제 여부**에 따라 그 가치 체계가 달라집니다.다음은 두 코딩 방식의 구별과 "Augmented Coding"의 가치 체계입니다.​

1. "Augmented Coding"과 "Vibe Coding"의 구별

두 방식의 주요 차이점은 개발자가 코드의 내부 품질에 얼마나 관심을 갖는지에 있습니다.

| 구분 | Vibe Coding (바이브 코딩) | Augmented Coding (증강 코딩) |
| --- | --- | --- |
| **코드에 대한 관심** | 코드 자체에는 신경 쓰지 않음. | **코드, 복잡성, 테스트 및 테스트 커버리지**에 신경 씀. |
| **오류 처리 방식** | 오류가 발생하면, 충분히 괜찮은(good enough) 해결책을 바라며 "지니(genie)"에게 피드백함. | 개발자가 중간 결과물을 주의 깊게 관찰하고, 비생산적인 개발을 막기 위해 개입할 준비를 함. |
| **목표** | 시스템의 동작(behavior)에만 집중. | 프로덕션 준비가 되었으며 성능 경쟁력이 있는 라이브러리 코드를 생성하는 것이 목표가 될 수 있음. |
| **개발자의 역할** | 주로 기능적인 결과에 의존. | 개발자가 설계에 더 많이 개입하며, TDD(Test-Driven Development)를 사용하도록 AI에게 지시하려고 시도함. |
| **결과의 예시** | Beck은 AI가 복잡성을 너무 많이 축적하여 완전히 멈추는 상황을 경험했는데, 이는 증강 코딩을 시도하기 전의 초기 프로젝트에서 발생했음. | ​ |

Kent Beck은 이 두 방식이 다르다는 것을 깨달은 후, 전체 데이터베이스 프로젝트 대신 B+ Tree 라이브러리만을 목표로 프로젝트 범위를 줄였지만, **증강 코딩**을 통해 프로덕션 수준의 성능 경쟁력을 갖춘 라이브러리 코드를 만들 수 있는지 확인하기 위해 범위를 늘렸습니다.​

2. Augmented Coding의 가치 체계 (Value System)

Augmented Coding의 가치 체계는 **손으로 직접 코딩할 때의 가치 체계와 유사**합니다. 그 핵심은 **작동하는 깔끔한 코드(tidy code that works)**입니다. Beck은 증강 코딩을 통해 그 코드의 대부분을 직접 타이핑하지 않을 뿐이라고 언급합니다.이러한 가치 체계를 달성하기 위해, Beck은 AI에게 엄격한 방법론적 지침을 제공합니다. 이는 다음을 포함합니다:• **TDD 및 Tidy First 원칙:** Kent Beck의 TDD(Test-Driven Development)와 Tidy First 원칙을 따르는 것을 핵심 개발 원칙으로 삼습니다.• **TDD 사이클 준수:** Red → Green → Refactor 사이클을 항상 따릅니다.• **Tidy First 접근 방식:** 모든 변경 사항을 **구조적 변경(행동 변경 없이 코드 재배치)**과 **행동적 변경(실제 기능 추가 또는 수정)** 두 가지 명확한 유형으로 분리합니다. 구조적 변경과 행동적 변경을 절대 같은 커밋에 섞지 않으며, 필요할 경우 항상 구조적 변경을 먼저 수행합니다.• **높은 코드 품질 유지:** 개발 전반에 걸쳐 높은 코드 품질을 유지하고, 중복을 철저히 제거하며, 명명 및 구조를 통해 의도를 명확히 표현하고, 가장 단순한 해결책을 사용해야 합니다.• **명확한 커밋 규율:** 모든 테스트가 통과하고, 모든 경고가 해결되었으며, 변경 사항이 단일 논리적 작업 단위를 나타낼 때만 커밋합니다.궁극적으로 Augmented Coding은 여전히 프로그래밍이며, 개발자는 "지니"와 함께함으로써 이전보다 **시간당 더 결과적인 프로그래밍 결정**을 내리고 지루한 일반적인 결정은 줄어드는, 더 나은 프로그래밍 경험을 얻을 수 있습니다.​--------------------------------------------------------------------------------

**비유 (Analogy):**

"Vibe Coding"이 **요리법 없이 "맛있어 보이는" 음식**을 만들기 위해 인공지능 주방장(genie)에게 맡긴 후 간을 대충 맞춰달라고 요청하는 것이라면, "Augmented Coding"은 개발자(요리사)가 재료의 품질, 조리 도구의 청결, 그리고 세부적인 조리 단계를 엄격히 관리하면서, 주방장에게 **요리법(TDD, Tidy First)을 정확히 따르되** 손이 많이 가는 자잘한 작업만 대신해 달라고 요청하는 것과 같습니다. 비록 코드를 AI가 작성하지만, 완성된 결과물의 품질과 구조에 대한 책임과 가치 기준은 여전히 개발자에게 있습니다.​​​​[http://github.com/aicoding-caret](http://github.com/aicoding-caret)[http://facebook.com/groups/aicoding-caret](http://facebook.com/groups/aicoding-caret)

[https://tidyfirst.substack.com/p/augmented-coding-beyond-the-vibes](https://tidyfirst.substack.com/p/augmented-coding-beyond-the-vibes)Honestly, I also think terms like 'AI-based development methodology' or 'AI Coding' are more fitting than 'Vibe Coding,' but due to the brand power 'Vibe Coding' has, we are still pushing it. It's not quite 'vibe-y' yet, but we'll work hard until it is.

Kent Beck clearly distinguishes between "Augmented Coding" and "Vibe Coding" as two different approaches that explore entirely new realms of programming workflow, with their value systems differing especially based on **the quality of the code itself and the degree of control by the developer.** Below is the distinction between the two coding methods and the value system of "Augmented Coding."

1. Distinction Between "Augmented Coding" and "Vibe Coding"

The main difference between the two approaches lies in how much the developer cares about the internal quality of the code.

| Category | Vibe Coding | Augmented Coding |
| --- | --- | --- |
| **Concern for Code** | Doesn't care about the code itself. | Cares about **code, complexity, tests, and test coverage.** |
| **Error Handling** | When an error occurs, feeds back to the "genie," hoping for a "good enough" solution. | The developer carefully observes intermediate results and is ready to intervene to prevent unproductive development. |
| **Goal** | Focuses only on the system's behavior. | The goal can be to generate production-ready, performance-competitive library code. |
| **Developer's Role** | Primarily relies on functional outcomes. | The developer is more involved in design and attempts to instruct the AI to use TDD (Test-Driven Development). |
| **Example of Outcome** | Beck experienced situations where the AI accumulated too much complexity and completely stalled, which occurred in early projects before attempting Augmented Coding. | |

After realizing these two approaches were different, Kent Beck narrowed the project scope to target only a B+ Tree library instead of a full database project, but then expanded the scope to see if **Augmented Coding** could produce production-level, performance-competitive library code.

2. Value System of Augmented Coding

The value system of Augmented Coding is **similar to the value system of manual coding.** At its core is **tidy code that works.** Beck notes that with Augmented Coding, he simply doesn't type most of that code himself. To achieve this value system, Beck provides strict methodological guidelines to the AI. These include:
• **TDD and Tidy First Principles:** Adopting Kent Beck's TDD (Test-Driven Development) and Tidy First principles as core development principles.
• **Adherence to TDD Cycle:** Always following the Red → Green → Refactor cycle.
• **Tidy First Approach:** Separating all changes into two distinct types: **structural changes (code rearrangement without behavior change)** and **behavioral changes (actual feature addition or modification).** Never mixing structural and behavioral changes in the same commit, and always performing structural changes first if necessary.
• **Maintaining High Code Quality:** Throughout development, maintaining high code quality, thoroughly eliminating duplication, clearly expressing intent through naming and structure, and using the simplest possible solution.
• **Clear Commit Discipline:** Committing only when all tests pass, all warnings are resolved, and the changes represent a single logical unit of work.
Ultimately, Augmented Coding is still programming, and by working with the "genie," developers can achieve a better programming experience, making **more consequential programming decisions per hour** and fewer tedious, generic ones.

**Analogy:**

If "Vibe Coding" is like entrusting an AI chef (genie) to create **"delicious-looking" food without a recipe** and then asking them to roughly adjust the seasoning, "Augmented Coding" is like a developer (chef) strictly managing the quality of ingredients, cleanliness of cooking tools, and detailed cooking steps, while asking the chef to **follow the recipe (TDD, Tidy First) precisely** but only handle the tedious, minor tasks. Although the AI writes the code, the responsibility for the quality and structure of the finished product, and the value criteria, still lie with the developer.
