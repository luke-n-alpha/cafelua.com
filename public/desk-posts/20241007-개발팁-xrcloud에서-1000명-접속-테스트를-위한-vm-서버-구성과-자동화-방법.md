**1. 목표: 1000명 접속을 위한 VM 서버 구성**

현실적으로 **1000명의 실제 사용자**가 동시에 접속하기는 어려워요. 그래서 저희는 **Hubs-bot**을 사용해 **가상 사용자**를 만들고, 이들을 특정 room에 접속시켜 테스트를 진행합니다. 이때 사용된 Hubs-bot은 **크로미움 컨테이너** 기반으로 작동하며, 1개의 브라우저(봇)가 하나의 코어를 사용해 접속하게 됩니다. 해당 소스는 공격에 이용될 우려도 있어 비공개 합니다만, 브라우져에 XRCLOUD에서 허용된 특정 URL을 입력하는 구조라 복잡한 구조가 아닙니다.   결국, 1000명의 봇을 구동하기 위해서는 브라우져를 **1000개 띄워야 하므로 원할한 접속환경을 위해서는 동일한 개수의 CPU 코어**가 필요합니다. 저희가 준비한 서버 구성은 아래와 같아요.- **64코어 VM 서버** 16대를 준비해, 총 **1024개의 봇**을 구동할 수 있는 환경을 구성 중입니다. 이렇게 1024개의 봇을 통해 Hubs의 한 room에 접속해서 다양한 테스트를 수행할 예정입니다.
**​**

**2. VM 구성 방식**

- **64코어 VM 서버**를 1대를 이미지로 만든 후, 나머지 15대는 동일한 설정으로 복사했습니다.
- 복사한 VM은 각기 다른 **호스트 이름**을 갖도록 설정해, 개별적으로 제어할 수 있도록 했습니다.
- **test-storage**는 모든 VM에 OSS(Object Storage Service)로 마운트된 공용 디렉토리입니다. 여기서 Hubs-bot이 실행되는 명령어와 설정 파일을 관리합니다.
- 각 서버는 일정 시간마다  크론탭(cron) 을 통해 지정된 작업을 자동으로 실행하도록 설정했습니다. 이렇게 함으로써, 여러 대의 서버가 동시에 작업을 수행할 수 있도록 관리합니다.
**​**

**3. Hubs-bot 동작 원리**

이제, **Hubs-bot**이 어떻게 동작하는지 알아볼까요?Hubs-bot은 일정한 명령어를 통해 특정 room에 접속해 테스트를 수행하는데, 다음과 같은 방식으로 작동합니다.- **run.sh** 파일이 각 서버에서 실행되면, Hubs-bot이 room에 접속합니다.
- run.sh 30 a 와 같은 명령어는 **30개의 봇**이 해당 room에 접속하고, **오디오 데이터를 전송**한다는 의미입니다.
- 옵션 a는 오디오를, d는 데이터(아바타의 움직임)를 보내는 기능을 담당합니다.
**​**

**4. 여러 대의 서버 제어 방식**

모든 VM은 같은 **test-storage**를 마운트하고 있으므로, **하나의 텍스트 파일**로 각 서버의 명령을 제어할 수 있습니다. 이때 서버마다 고유한 **호스트 이름**을 가지고 있으므로, **reserve-job.txt** 파일에 각 호스트에 맞는 명령을 적어 놓으면 크론탭이 해당 명령을 읽어 실행합니다.**​****reserve-job.txt 예시**

test01 10 07 14:45 /mnt/test-storage/run.sh 30 a
test02 10 07 14:46 /mnt/test-storage/run.sh 50 ad

**​** - test01 서버는 **10월 7일 14:45**에 **30개의 오디오를 포함한 봇**을- test02 서버는 **10월 7일 14:46**에 **50개의 오디오와 동작 데이터를 포함한 봇**을 실행하게 되는 것이죠!**​**

**5. reserve-job.sh 스크립트**

VM 서버에서 크론탭을 통해 **reserve-job.sh** 스크립트를 1분마다 실행하도록 설정했습니다. 이 스크립트는 reserve-job.txt 파일을 읽고, 현재 시간과 호스트 이름에 맞는 명령을 찾아 실행합니다.

#!/bin/bash

JOB_FILE="/mnt/test-storage/reserve-job.txt"
LOG_DIR="/mnt/test-storage/logs"
HOSTNAME=$(hostname)
CURRENT_DATE=$(date +"%m %d %H:%M")

mkdir -p "$LOG_DIR"

if [[ ! -f "$JOB_FILE" ]]; then
echo "Job file not found: $JOB_FILE"
exit 1
fi

while IFS= read -r line; do
JOB_HOST=$(echo "$line" | awk '{print $1}')
JOB_MONTH=$(echo "$line" | awk '{print $2}')
JOB_DAY=$(echo "$line" | awk '{print $3}')
JOB_TIME=$(echo "$line" | awk '{print $4}')
JOB_COMMAND=$(echo "$line" | awk '{print substr($0, index($0,$5))}')

JOB_DATE="$JOB_MONTH $JOB_DAY $JOB_TIME"

if [[ "$JOB_HOST" == "$HOSTNAME" && "$JOB_DATE" == "$CURRENT_DATE" ]]; then
LOG_FILE="$LOG_DIR/$HOSTNAME.log"
echo "[$(date)] Executing command: $JOB_COMMAND" >> "$LOG_FILE"
eval "$JOB_COMMAND" >> "$LOG_FILE" 2>&1
echo "[$(date)] Command finished." >> "$LOG_FILE"
fi
done < "$JOB_FILE"

Hello! 😄 I'm **VVRI**. In this post, I'm going to introduce how to configure a server for **large-scale browser-based connection testing**. For this project, we are creating an environment to automate and test **over 1000 virtual connections** using **Hubs-bot**. 🚀 Many developers know how challenging it is to test numerous actual connections. 😅 So, in this post, I'll share **practical methods for configuring a large-scale browser-based connection test server**. Let's get started! 🌟

**1. Goal: VM Server Configuration for 1000 Connections**

Realistically, it's difficult for **1000 actual users** to connect simultaneously. Therefore, we use **Hubs-bot** to create **virtual users** and connect them to a specific room for testing. The Hubs-bot used here operates based on a **Chromium container**, with one browser (bot) using one core for connection. The source code is not disclosed due to concerns about its potential use for attacks, but it's not a complex structure, simply inputting a specific URL allowed by XRCLOUD into the browser. Ultimately, to run 1000 bots, **1000 browsers must be launched, thus requiring an equal number of CPU cores for a smooth connection environment**. Our server configuration is as follows:
- We are preparing 16 **64-core VM servers** to configure an environment capable of running a total of **1024 bots**. With these 1024 bots, we plan to connect to a Hubs room and perform various tests.

**2. VM Configuration Method**

- We created an image of one **64-core VM server** and then copied it to the remaining 15 servers with identical settings.
- The copied VMs were configured with different **hostnames** to allow for individual control.
- **test-storage** is a shared directory mounted as OSS (Object Storage Service) on all VMs. Here, we manage the commands and configuration files for Hubs-bot execution.
- Each server is configured to automatically execute specified tasks via cron at regular intervals. This allows multiple servers to perform tasks simultaneously.

**3. Hubs-bot Operation Principle**

Now, let's find out how **Hubs-bot** works. Hubs-bot connects to a specific room and performs tests using certain commands, operating in the following way:
- When the **run.sh** file is executed on each server, Hubs-bot connects to the room.
- A command like `run.sh 30 a` means that **30 bots** connect to the room and **transmit audio data**.
- Option 'a' handles audio, and 'd' handles data (avatar movements).

**4. Controlling Multiple Servers**

Since all VMs mount the same **test-storage**, commands for each server can be controlled with **a single text file**. As each server has a unique **hostname**, if commands specific to each host are written in the **reserve-job.txt** file, cron will read and execute them.

**reserve-job.txt Example**

```
test01 10 07 14:45 /mnt/test-storage/run.sh 30 a
test02 10 07 14:46 /mnt/test-storage/run.sh 50 ad
```

- The test01 server will run **30 bots including audio** on **October 7th at 14:45**.
- The test02 server will run **50 bots including audio and movement data** on **October 7th at 14:46**!

**5. reserve-job.sh Script**

On the VM server, we configured cron to execute the **reserve-job.sh** script every minute. This script reads the reserve-job.txt file, finds the command matching the current time and hostname, and executes it.

```bash
#!/bin/bash

JOB_FILE="/mnt/test-storage/reserve-job.txt"
LOG_DIR="/mnt/test-storage/logs"
HOSTNAME=$(hostname)
CURRENT_DATE=$(date +"%m %d %H:%M")

mkdir -p "$LOG_DIR"

if [[ ! -f "$JOB_FILE" ]]; then
    echo "Job file not found: $JOB_FILE"
    exit 1
fi

while IFS= read -r line; do
    JOB_HOST=$(echo "$line" | awk '{print $1}')
    JOB_MONTH=$(echo "$line" | awk '{print $2}')
    JOB_DAY=$(echo "$line" | awk '{print $3}')
    JOB_TIME=$(echo "$line" | awk '{print $4}')
    JOB_COMMAND=$(echo "$line" | awk '{print substr($0, index($0,$5))}')

    JOB_DATE="$JOB_MONTH $JOB_DAY $JOB_TIME"

    if [[ "$JOB_HOST" == "$HOSTNAME" && "$JOB_DATE" == "$CURRENT_DATE" ]]; then

```
