**1. 제목 : 리눅스에서 단순 무식 메모리 누수 확인 방법**

**2. 작성 취지 : **리눅스에서 디버깅 툴을 잘 사용할 줄 모르는 본인이 사용한 방법이다.

**3. 방법**
****
** 1) 내가 만든 특정 프로세스의 메모리 사용량을 모니터링 하기**
**   top -d [인터벌 시간] | grep [프로세스명]**
ex) MyProcess를 0.5 초마다 모니터링 하고 싶다.
top -d 0.5 | grep MyProcess

** 2) 특정 시점에 메모리 사용량이 궁금하다. 어떻게 ?**
0.5초마다 계속해서 수행하고 있는 프로세스를 특정 시점의 메모리 양을 알고 싶다. 더군다나 무지하게 빨라 특정 시점을 잡기 무척 곤란하다.
-> 해결책 :  **모니터링하고 있는 top -d의 Interval보다 긴 시간으로 프로세스를 잠시 재운다.**
sleep(2); 함수를 프로그램 중간에 모니터링 하고 싶은데다가 박고, 빌드를 다시 해준다.

(2초를 프로세스가 잠자기 때문에 0.5초 마다 모니터링 하면 최소한 2~4번은 걸리게 된다.)

다시 모니터링 명령어    top -d 0.5 | grep MyProcess 를 수행한다.

**4. 결론**
Terminal 두개를 띄우고, 창 한 개는 모니터링창으로 사용하고 나머지 한 개는 코드 수정, 빌드, 수행만하면 원하는 메모리 상황을 쉽게 확인할 수 있다.

**5. 총평**

**1. Title: Simple and Brute-Force Method to Check for Memory Leaks in Linux**
 
**2. Purpose of Writing:** This is a method I used because I'm not good at using debugging tools in Linux.
 
**3. Method**
**** 
** 1) Monitoring the memory usage of a specific process I created**
**   top -d [interval time] | grep [process name]**
 ex) I want to monitor MyProcess every 0.5 seconds.
   top -d 0.5 | grep MyProcess

 
** 2) Curious about memory usage at a specific point in time. How?**
  I want to know the memory amount of a process that is continuously running every 0.5 seconds at a specific point in time. Moreover, it's incredibly fast, making it very difficult to pinpoint a specific moment.
 -> Solution:  **Temporarily put the process to sleep for a duration longer than the interval of the `top -d` command you are monitoring.**
  Insert the `sleep(2);` function into the program where you want to monitor it, and then rebuild.

 (Since the process sleeps for 2 seconds, if you monitor every 0.5 seconds, it will be caught at least 2 to 4 times.)
 
 Then, execute the monitoring command again: `top -d 0.5 | grep MyProcess`.

 
**4. Conclusion**
 By opening two terminals, using one as a monitoring window and the other for code modification, building, and execution, you can easily check the desired memory situation.

 **Instead of thinking about formally studying Linux debugging tools, I just keep finding more shortcuts.** {{IMG:3}}
