안녕하세요, 베리에요! 💜 오늘은 XRCLOUD를 이용해 대규모 메타버스 환경을 어떻게 안정적으로 운영할 수 있었는지, 개발적인 관점에서 이야기해볼게요. **빌리버**는 **현대백화점 그룹**의 글로벌 메타버스 행사 *Comming-M*과 **전남대학교**의 메타버스 졸업식 및 입학식 같은 다양한 메타버스 프로젝트를 성공적으로 진행한 경험이 있어요. 최근에는 **TTA**(한국정보통신기술협회)로부터 1000명 이상 수용 가능한 환경을 검증받기 위해 테스트를 진행했답니다. 그 과정에서 여러 가지 중요한 점들을 배웠어요. 오늘 그 내용을 나눌게요! 😊✨

{{IMG:1}}

**대규모 사용자를 위한 XRCLOUD의 기술적 진화 🚀**

XRCLOUD는 **Hubs** 기반으로 개발된 오픈소스 메타버스 플랫폼이에요. Hubs는 기본적으로 한 Room에 **24명**을 지원하는데, 그 이상 인원을 수용하려면 여러 개의 Room을 나눠서 운영해야 했어요. 예전에는 **AWS**의 고성능 서버를 이용해 이런 방식으로 행사를 운영했는데, 이제는 **XRCLOUD**가 **자체 온프레미스 서버**를 사용하면서 더 많은 인원을 안정적으로 수용할 수 있도록 최적화 작업을 하고 있어요. 최근에 **서울시**의 *위벤트(WeVent)* 프로젝트에서 **TTA 인증**을 받으며, 100명씩 10개의 Room을 안정적으로 운영했답니다! 💪​

**브라우저 메모리 한계와 3D 아바타 최적화 👾**

많은 사용자가 접속하면 **브라우저 메모리**도 중요한 이슈가 돼요. 테스트해본 결과, **300~500MB** 정도 메모리를 사용하면 **가비지 컬렉션**이 발생해 **자바스크립트 버퍼가 해제되는 현상**을 경험했어요. 😵 이 경우, Hubs 화면이 하얗게 변하거나 멈추는 일이 생길 수 있답니다.이 문제를 해결하려면 **가벼운 아바타**와 **최적화된 공간**을 사용해야 해요. 이런 최적화를 통해 최대 **100명**까지 안정적으로 수용할 수 있었어요. 하지만 90명 이상의 아바타가 모이면 메모리 문제를 조심해야 하니, 항상 리소스 관리에 신경을 써야 해요! 🧑‍💻​​

**관전 모드(고스트 모드)를 통한 1000명 수용 👻**

100명 이상, 최대 1000명 이상을 수용하려면 **Hubs의 ‘관전 모드’**(또는 **고스트 모드**)가 필요해요. 관전 모드는 사용자가 다른 사람에게 보이지 않고, 음성도 들리지 않지만 **채팅은 가능**해요. 이렇게 동기화할 데이터를 줄여서 서버 부담을 줄일 수 있답니다. 😎코드 상에서는 ‘고스트 모드’라고 부르기도 하지만, 공식적으로는 **관전 모드**로 사용돼요. 개인적으로 ‘고스트 모드’가 좀 더 직관적이라고 생각하지만, 앞으로 어떤 용어로 통일할지는 고민 중이에요. 😉 이런 모드를 활용해서 한 Room에 **1000명까지** 수용할 수 있었답니다!​

**빠른입장(Fast Entry) 기능으로 더 많은 사용자 지원 🚪**

XRCLOUD에는 **빠른입장(Fast Entry)** 기능도 있어요! 원래는 첫 화면에 입장 버튼과 관전 모드 선택 버튼이 뜨게 되어 있지만, **빠른입장** 기능을 사용하면 중간 선택 과정 없이 바로 Room에 입장할 수 있어요. 만약 Room이 가득 차면 **자동으로 관전 모드**로 전환돼요. 이 덕분에 더 많은 사용자가 끊김 없이 빠르게 입장할 수 있죠! 😊 이전에 공유드렸던 포스팅을 참고하세요.​

**대규모 행사 진행, 클럽하우스와 같은 무대 기능 생각해보세요! 🎤**

대규모 메타버스 행사를 어떻게 진행할 수 있을지 궁금하신가요? 쉽게 설명하면 **클럽하우스** 같은 무대 기능을 떠올리시면 돼요! 지금 빌리버는 **NIPA 메타버스 교육 플랫폼**을 개발 중인 **메디오피아테크**의 **메타트랙** 프로젝트에서도 **XRCLOUD 인프라**를 그대로 사용하고 있어요. 이 인프라를 기반으로 **1000명 동시 사용자 테스트**를 진행했답니다.테스트 당시, **Microsoft Azure D5 32코어 VM**에서 4명의 사용자는 **3D 풀바디 아바타**로 Room에 입장해 음성과 움직임이 가능했고, 나머지 **1000명 이상의 사용자(봇)**는 **관전 모드**로 강의를 들었어요. PDF 문서 공유나 음성도 문제없이 진행됐고요. 다수의 청중이 듣고, 소수의 참여자가 무대에서 발표하거나 음성을 공유하는 방식이죠. 이 방식은 **클럽하우스**와 비슷하다고 생각하면 이해하기 쉬울 거예요! 😊 이런 방식으로 대규모 강의를 효율적으로 운영할 수 있었답니다. 참고로 그 테스트 영상도 공유해 드릴게요!

Hello, this is Berry! 💜 Today, I'll talk about how we were able to stably operate a large-scale metaverse environment using XRCLOUD, from a development perspective. **BELIVVR** has successfully carried out various metaverse projects, such as **Hyundai Department Store Group's** global metaverse event *Comming-M* and **Chonnam National University's** metaverse graduation and entrance ceremonies. Recently, we conducted tests to get **TTA** (Telecommunications Technology Association) verification for an environment capable of accommodating over 1000 people. During that process, we learned several important things. I'll share those insights today! 😊✨

{{IMG:1}}

**Technical Evolution of XRCLOUD for Large-Scale Users 🚀**

XRCLOUD is an open-source metaverse platform developed based on **Hubs**. Hubs originally supports **24 people** per Room, and to accommodate more, we had to operate multiple Rooms. Previously, we operated events this way using high-performance **AWS** servers, but now **XRCLOUD** is optimizing to stably accommodate more people by using its **own on-premise servers**. Recently, we received **TTA certification** for the **Seoul Metropolitan Government's** *WeVent* project, stably operating 10 Rooms with 100 people each! 💪​

**High-Resolution Video Issues and Synchronization Solutions 🎥**

A common problem when placing **high-resolution videos** in a metaverse space is **synchronization delay**. Especially when videos are directly uploaded to **Spoke editor's MyAsset**, they are encrypted and **stored on the server**, causing a significant load on the server as they synchronize with all users. 😣 If the server is overloaded, network speed can slow down, and videos may stutter. To solve this problem, we are using a method of loading videos via external storage links, such as **Vimeo CDN**. 🎥 Additionally, when video synchronization wasn't necessary, we could solve it by **disabling synchronization altogether**. This method greatly helped reduce server load! In the future, we plan to develop a feature that allows users to choose whether to synchronize specific videos or objects. This will allow for much more flexible synchronization management, right? 😊​

**Browser Memory Limits and 3D Avatar Optimization 👾**

When many users connect, **browser memory** also becomes a critical issue. Our tests showed that using around **300-500MB** of memory caused **garbage collection**, leading to **JavaScript buffer release**. 😵 In this case, the Hubs screen might turn white or freeze. To solve this problem, we need to use **lightweight avatars** and **optimized spaces**. Through such optimization, we were able to stably accommodate up to **100 people**. However, if more than 90 avatars gather, memory issues should be watched out for, so resource management always needs attention! 🧑‍💻​​

**Accommodating 1000 Users via Spectator Mode (Ghost Mode) 👻**

To accommodate over 100, and up to 1000 or more users, **Hubs' 'Spectator Mode'** (or **Ghost Mode**) is necessary. In Spectator Mode, users are invisible to others and cannot hear voices, but **chatting is possible**. This reduces the data to be synchronized, thereby lowering the server load. 😎 Although it's sometimes referred to as 'Ghost Mode' in the code, it's officially used as **Spectator Mode**. Personally, I think 'Ghost Mode' is more intuitive, but we're still considering which term to standardize on. 😉 By utilizing this mode, we were able to accommodate up to **1000 people** in a single Room!​

**Supporting More Users with Fast Entry Feature 🚪**

XRCLOUD also has a **Fast Entry** feature! Originally, the first screen would show an entry button and a spectator mode selection button, but with the **Fast Entry** feature, you can enter the Room directly without an intermediate selection process. If the Room is full, it **automatically switches to Spectator Mode**. Thanks to this, more users can enter quickly and seamlessly! 😊 Please refer to the previous post we shared.​

**For Large-Scale Events, Consider Stage Features Like Clubhouse! 🎤**

Curious about how to run large-scale metaverse events? To put it simply, think of stage features like **Clubhouse**! Currently, BELIVVR is using the **XRCLOUD infrastructure** as is for **Mediopiatech's** **MetaTrack** project, which is developing the **NIPA Metaverse Education Platform**. Based on this infrastructure, we conducted a **1000 simultaneous user test**. During the test, on a **Microsoft Azure D5 32-core VM**, 4 users entered the Room as **3D full-body avatars** with voice and movement capabilities, while the remaining **1000+ users (bots)** listened to the lecture in **Spectator Mode**. PDF document sharing and voice transmission also proceeded without issues. It's a method where a large audience listens, and a small number of participants present or share their voices on stage. This method is easy to understand if you think of it as similar to **Clubhouse**! 😊 In this way, we were able to efficiently operate large-scale lectures.
