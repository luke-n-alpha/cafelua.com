노트북을 새로 얻게 되어 윈도우즈7을 새로 설치했습니다. 그래서 이왕이면 브라우져도 판올림 해볼까 해서 Ie9 rc를 깔아봤습니다.
불과 며칠밖에 사용하지 않았지만, 결국 Ie8로 원복했습니다. Ie9만 벌써 세번째 깔았다 지웠다 했네요. Rc면 좀 나아질까 싶었는데. 일단 국내의 라이트 유저가 당장 Ie9을 까는 것은 권하고 싶지 않습니다.

**1. 장점 **
일단 장점부터 시작하겠습니다.
****
**1) 빠른속도 **
Ie9은 매우 빨라졌다고 합니다. 하지만 대부분 병목은 브라우져가 아니고 덩치큰 웹페이지와 네트워크의 문제라 그다지 팍 체감되지는 않습니다.

**2) html5 **
Html5를 지원하는 최초의 ms판 브라우져입니다.

**3) active x
**Ms꺼라 ax를 지원합니다. 기존의 ax를 지원하는 국내의 상거래시장과 은행과 정부기관, 그리고 게임포탈이 이용가능합니다. Ax가 원흉이라 한들 이러한 기능들을 안쓰고 국내에서 산다는것은 사실상 어렵습니다.

**4) 도킹 탭
**탭을 브라우져 바깥으로 브라우져를 두개를 합쳐서 탭으로 만드는것이 자유롭습니다. 사용해보니 의외로 편리하더군요.

**5) 깔끔해진 메뉴, 넓어진 컨텐츠 창
**크롬처럼 컨텐츠영역을 넓히고 최소의 메뉴만 배치해서 상당히 깔끔해졌습니다. 기존에 따로 있던 검색창의 경우 주소창이 그 역할을 같이해줍니다.

**2. 문제점
1) 플래시의 네비게이션이 먹는 문제
**휴대폰드라이버 때문에 lg에 들렀더니 플래시로 만들어진 네비게이션이 동작하지 않더군요. Uplus뿐이 아니었습니다. 플래시로 메뉴를 만든 많은 사이트들이 동작하지 않았습니다. 플래시는 바이너리를 다시 만들어야하기 때문에 만약 ie9이 이를 해결하지 않으면 국내에서는 흔한 플래시 네비게이션 사이트들의 플래시 파일을 교체해야할지도 모르겠습니다. 템플릿으로 웹을 제작하는 업체들은 대부분 플레시 네비게이션을 쓰고 있죠.
물론 호환성보기를 눌러주면 해결됩니다.

**2) 이미지가 안나오는 문제
**예전에도 있었는데 제 pc문제인줄 알았는데 윈도 밀고나서도 이런 문제가 재현되기도 하더군요. 브라우져를 모두 종료 한후 다시 띄워야합니다. 브라우져에서 사용하는 이미지용 힙메모리 크기라도
제한이 있는걸까요? 자주는 아니지만 한번 발생하면 여간 불편한게 아닙니다. 예전 win98에서 이미지엑박 에러처럼 이미지가 모두 하얗게 나와버립니다.

**3) 포탈의 기능오류
**현재 국내 포탈들도 ie9에는 대응을 안하고 있는듯합니다. 네이버블로그의 주소복사기능이 안된다던지 보안로그인 기능이 역시 안됩니다.
다음컴즈의 경우에는 로드뷰는 아예 보이지 않더군요.
아마도 ie9을 지원하려면 좀 기다려야 하나봅니다. 아직 저같이 관심있는 유저들외에는 굳이 ie9을 찾아서 깔지는 않으니까요.

**3. 특징점
1) 무거운 툴바의 경고
**Ie9을 깔고 네이버툴바를 깔았더니 사용시에 경고메시지를 띄우더군요. 초기에 로딩하는데 소요되는 시간이 표기되면서요. 0.2초를 넘으면 기본적으로 띄우고 지울것을 권고하는데 이 기능이 확산되면 유저들은 주저없이 삭제 버튼을 누를가능성이 높을것 같습니다. 툴바를 올인원으로 개발하기보다는 각각 기능을 분리하여 유저가 원하는 기능만 설치하여 최소의 로딩시간을 갖도록할 필요가 있어보입니다. 어쩌면 툴바의 시대는 점점 끝나가는지도 모르죠.

**4. 의의
**아무튼 결론을 따지면 아직은 유저들에게는 시기상조입니다. 호환성버튼을 수시로 눌러줘야하다보니 속터집니다.
그러나 사실 ie9은 큰 의의가 있습니다. Html5와 ax의 두가지 필요기술을 공존하는 첫 브라우져란 것이죠. 국내에는 사실상 이런 브라우져가 필요합니다.
그래야만 맘놓고 html5로 개발이 가능합니다. Html5가 아무리 좋다고해도 ie 유저들을 버리고 개발하는 것은 국내의 실정상 무리입니다. 국내 포탈이 ie6버리기 운동을 했음에도 여전히 ie6의 국내유저비율은 아직도 30%에 육박합니다. 이러한 상황에서 html5로만 개발하는것은 큰 무리수고 결국 두가지이상의 버젼을 개발해야하는 상황입니다. 이러한 상황에서 ie9의 보급은 ie유저들도 html5의 한가지기술로 대응이 가능하다는 점은 서비스제공자들에게는 큰 의의가 있다고 할것입니다.

Having gotten a new laptop, I installed Windows 7. So, while I was at it, I thought I'd upgrade my browser and installed IE9 RC.
I only used it for a few days, but I eventually reverted to IE8. This is already the third time I've installed and uninstalled IE9. I thought the RC version might be better. For now, I wouldn't recommend that casual users in Korea install IE9 immediately.

**1. Advantages**
Let's start with the advantages.
****
**1) Fast Speed**
IE9 is said to be much faster. However, most bottlenecks are not due to the browser itself but rather large webpages and network issues, so the speed increase isn't dramatically noticeable.

**2) HTML5**
It is the first MS browser to support HTML5.

**3) ActiveX**
Being an MS product, it supports ActiveX. This means that domestic e-commerce markets, banks, government agencies, and game portals that rely on existing ActiveX are usable. Even if ActiveX is considered the root cause of problems, it's practically difficult to live in Korea without using these functions.

**4) Docking Tabs**
It's easy to drag tabs out of the browser window and combine two browsers into tabs. I found it surprisingly convenient when I used it.

**5) Cleaner Menu, Wider Content Window**
Like Chrome, it has a wider content area and minimal menus, making it very clean. The address bar now doubles as the search bar, which was previously separate.

**2. Problems**
**1) Flash Navigation Issues**
When I visited LG for a phone driver, the Flash-based navigation didn't work. It wasn't just Uplus; many sites with Flash menus didn't function. Since Flash requires rebuilding binaries, if IE9 doesn't resolve this, common Flash navigation sites in Korea might need to replace their Flash files. Most companies that build websites using templates use Flash navigation.
Of course, clicking the compatibility view button solves the problem.

**2) Image Display Issues**
This issue existed before, and I thought it was a problem with my PC, but it reappeared even after reinstalling Windows. I have to close all browser windows and reopen them. Is there a limit to the heap memory size for images used by the browser? It doesn't happen often, but when it does, it's quite inconvenient. Like the 'image X-box' error in old Win98, all images appear white.

**3) Portal Function Errors**
Currently, domestic portals don't seem to be compatible with IE9. For instance, Naver Blog's address copy function doesn't work, and neither does the secure login feature.
In the case of Daum Communications, Road View doesn't appear at all.
It seems we'll have to wait a bit for IE9 support. After all, not many users actively seek out and install IE9, apart from those interested like myself.

**3. Notable Features**
**1) Warning for Heavy Toolbars**
After installing IE9 and then Naver Toolbar, a warning message popped up during use, indicating the initial loading time. If it exceeds 0.2 seconds, it basically recommends removing it. If this feature becomes widespread, users are likely to press the delete button without hesitation. It seems necessary to develop toolbars with separate functions rather than as all-in-one packages, allowing users to install only the features they want for minimal loading times. Perhaps the era of toolbars is gradually coming to an end.

**4. Significance**
In conclusion, it's still too early for users. Having to constantly press the compatibility button is frustrating.
However, IE9 actually holds great significance. It is the first browser to coexist with two essential technologies: HTML5 and ActiveX. In Korea, such a browser is practically necessary.
Only then can development with HTML5 proceed without worry. No matter how good HTML5 is, abandoning IE users for development is unrealistic given the situation in Korea. Even after domestic portals launched a campaign to abandon IE6, the proportion of IE6 users in Korea still approaches 30%. In such a situation, developing solely with HTML5 is a big gamble, and it ultimately leads to having to develop two or more versions. In this context, the widespread adoption of IE9 is highly significant for service providers, as it means IE users can also be catered to with a single HTML5 technology.
