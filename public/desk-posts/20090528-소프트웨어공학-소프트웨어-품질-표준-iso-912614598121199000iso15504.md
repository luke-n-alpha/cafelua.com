**1.     ****기출문제 출제된 관련 토픽**
-       품질 표준
-       웹 품질 평가 체크 리스트
-       품질 경영 6시그마
-       S/W 제품 품질 : ISO 9126 / 14598 / 12119/ 9000
-       S/W 프로세스 품질 : CMMI/SPICE(ISO15504)/ISO 12207
-       Software Metric
-       SLA

**2.     품질의 가치**
- 이해관리자에게 높은 만족도를 제공하며, 추후에 발생할 수 있는 비용을 최소화하여 기업 경쟁력의 요소로 작용

**3 품질의 속성 (로버트 L 클래스)**
3.1. 이식성 : 다른 플랫폼으로 이식 용이
3.2. 신뢰성 : 프로그램의 안정성
3.3. 효율성 : 시간을 포함한 비용대비의 성능
3.4. 사용성 : 유저의 사용편의성
3.5. 테스트용이성 : 개발 과정 중 테스트를 편리하도록 하여 품질에 기여
3.6. 이해 용이성 : 사용방법의 이해, 소프트웨어 구조, 코드의 이해
3.7. 수정 용이성 : 기능 변경, 확장, 제거의 용이

**3.     소프트웨어의 품질**
{{IMG:1}}
**3.1. 소프트웨어 제품 품질**
3.1.1. ISO 9126 : 품질 특성과 척도에 관한 지침
고객관점의 소프트웨어 6가지 품질특성, 부특성으로 세분화 정의
{{IMG:2}}
[특성/부특성]
3.1.2. ISO 12119
- 소프트웨어 제품의 품질
- 사용자 문서와 프로그램으로 구분, ISO/IEC 9126의 품질모델 준수
- 테스트 절차도 규정
{{IMG:3}}
3.1.3. ISO 14598
- 소프트웨어 품질의 측정,평가에 필요 절차 방법
- 개발자, 구매자, 평가자로 구분해 제품 평가 활동 다룸
{{IMG:4}}

3.2. 소프트웨어 프로세스 품질
3.2.1. CMM/CMMI
- 소프트웨어와 시스템 공학의 역량 성숙도 평가 모델
- Staged 모델 : 한단계씩 프로개스 개선, 구조적인 방법
- Continous 모델  : 유연한 접근, 문제가 필요한 PA영역에 선택적 개선
{{IMG:5}}
3.2.2. SPICE(ISO15504)
- 소프트웨어 프로세스 평가, 개선, 품질 생산성 향상 표준
- 개발기관의 능력을 아래와 같이 6단계로 구분
{{IMG:6}}

3.2.3. ISO 12207
- ISO에서 정한 SDLC 프로세스
- 소프트웨어 개발과 유지보수에 필요한 작업단계 정의
- 23개의 프로세스, 95개 활동, 224개의 산출물 정의

: 기본공정 : 공급,획득,개발,운영,유지보수
:  조직공정 : 관리,개선,기반구조,교육훈련
:  지원공정 : 문서화,형상관리,품질보증,문제관리 등

{{IMG:7}}
3.3. 공급자와 구매자간의 프로세스 품질 모델
3.3.1. ISO 9001
- SDLC의 과정에 대한 품질 보증 모델
- 품질 시스템 순기활동
- 공급자와 구매자간의 관리 책임 명시          {{IMG:8}}
3.4. 기존의 국제 표준을 보강하고 통합하는 소프트웨어 평가 모델인 ISO/IEC 25000
- SquaRE 프로젝트
- ISO/IEC 9126과 14598 대체 목적 : 표준에 불일치 부분 발견
- 4+1 구조
ㆍ품질 모델(25010 Quality Model Division)

ㆍ품질 메트릭(25020 Quality Metrics Division)

ㆍ품질 요구사항(25030 Quality Requirement Division)

ㆍ품질 평가(25040 Quality Evaluation Division)

ㆍ+(plus) 전체를 반영하는 부분(25000 Quality Management Division)
{{IMG:9}}
3.5 국내 표준
- KS, KICS, TTAS
- KModel
: 정보통신부 소프트웨어 진흥원에서 만든 한국형 프로세스 평가 모델
: CMMI, SPICE 와 비슷
: initial, good, excellent란 3가지로 다음과 같이 5가지 영역에 대해 평가.
영역 1. 소프트웨어 개발 계획수립, 통제 등 관리프로세스에 관한 사항
영역 2. 소프트웨어개발공정에서 필요한 분석, 설계 등 개발 프로세스에 관한 사항
영역 3. 소프트웨어 품질관리에 필요한 품질보증 등 지원프로세스에 관한 사항
영역 4. 조직의 프로세스 표준화 및 이의 적용?확산 등에 관한 조직관리 사항
영역 5. 소프트웨어 프로세스의 유지 및 개선 등에 관한 사항
: 인증을 통해 공공분야에 가산점 부여, 해외표준 연계로 활성화 / 인증기관, 심사제를 통한 운영
: 중소기업인들의 형식적인 K Model 의 문제 지적
4.     SLA
-  서비스 수준 협약서비스
: 서비스/품질 수준에 따라 등급을 나누어 서비스 제공자간에 체결하는 협약
:  품질 위반시 패널티

5.     웹 품질 평가
5.1  한국 웹사이트 평가 개발원
- WEB QUAL 웹사이트 품질인증
4개 영역 220 세부 항목
- 컨탠츠 : 현재성, 이해가능성, 다양성및 완전성, 유용성, 정확성
- 상업성/사용자서비스 : 거래과정, 마케팅, 커뮤니케이션 채털의 다양성및 활성화, 대응능력, 공익성, 기타지원
- 디자인 : 상호작용성, 정보의 구조, 내비게이션, 시각적 요소
- 기술 : 시스템 성능, 보안
5.2. 웹접근성 : 장애인 차별법
- 인식의 용이성 : 시각장애자, 색맹을 위한 부분
- 운용의 용이성 : 키보드이용가능, skip 기능, 새창 제공 공지
- 이해의 용이성 : 테이블 요약정보, 타이틀 제공, 레이블 서식 이용, 컨탠츠 순서
- 기술적 진보성 : 웹어플리케이션 접근성 준수
5.3. 웹표준
-  W3C Markup Validation Service
: 웹사이트의 웹 표준 준수성 확인
-  W3C mobileOK Checker
: Mobile 환경하에 가능한 웹페이지 확인
- ACID 테스트 : 브라우져의 웹표준 준수성 테스트
- 오픈웹 : AX와 IE만 사용가능한 전자정부와 인터넷 서비스를 대상으로 국제표준에 맞도록 개선을 요구하는 국내 커뮤니티

**2. Value of Quality**
     - Provides high satisfaction to stakeholders, minimizes future costs, and acts as a factor in corporate competitiveness.
 
**3. Attributes of Quality (Robert L. Glass)**
     3.1. Portability: Easy to port to other platforms
     3.2. Reliability: Program stability
     3.3. Efficiency: Performance relative to cost, including time
     3.4. Usability: User-friendliness
     3.5. Testability: Contributes to quality by facilitating testing during the development process
     3.6. Understandability: Understanding usage methods, software structure, and code
     3.7. Modifiability: Ease of changing, extending, or removing functions

3.1.1. ISO 9126: Guidelines for Quality Characteristics and Metrics
                    Defines 6 software quality characteristics from a customer perspective, subdivided into sub-characteristics.

3.2. Software Process Quality
   3.2.1. CMM/CMMI
    - Capability maturity model for software and systems engineering
    - Staged Model: Step-by-step process improvement, structured approach
    - Continuous Model: Flexible approach, selective improvement in PA areas where issues are present
{{IMG:5}}
3.2.2. SPICE(ISO15504)
 - Standard for software process assessment, improvement, and quality productivity enhancement
 - Classifies the capability of development organizations into 6 levels as follows:
{{IMG:6}}
 
 3.2.3. ISO 12207
  - SDLC process defined by ISO
  - Defines work stages required for software development and maintenance
  - Defines 23 processes, 95 activities, and 224 deliverables

  : Primary Processes: Acquisition, Supply, Development, Operation, Maintenance
         : Organizational Processes: Management, Improvement, Infrastructure, Training
         : Support Processes: Documentation, Configuration Management, Quality Assurance, Problem Management, etc.

    3.3. Process Quality Model between Supplier and Acquirer
          3.3.1. ISO 9001
           - Quality assurance model for the SDLC process
           - Quality system cyclical activities
           - Specifies management responsibilities between supplier and acquirer          {{IMG:8}}

      - SquaRE project
      - Purpose to replace ISO/IEC 9126 and 14598: Inconsistencies found in standards

   3.5. Domestic Standards
      - KS, KICS, TTAS
      - KModel
        : A Korean-style process evaluation model created by the Ministry of Information and Communication's Software Promotion Agency
        : Similar to CMMI, SPICE
        : Evaluated across 5 areas, categorized into 3 levels: initial, good, and excellent.
     Area 1. Matters related to management processes such as software development planning and control
     Area 2. Matters related to development processes such as analysis and design required in the software development process
     Area 3. Matters related to support processes such as quality assurance required for software quality management
     Area 4. Organizational management matters related to process standardization within the organization and its application/diffusion
     Area 5. Matters related to the maintenance and improvement of software processes
        : Provides bonus points in the public sector through certification, activated by linkage with international standards / Operated through certification bodies and an auditing system
        : Points out the problem of small and medium-sized enterprises' perfunctory use of K-Model
4. SLA
    - Service Level Agreement Service
: An agreement signed between service providers, dividing services/quality levels into grades
     : Penalties for quality violations
 
5. Web Quality Evaluation
  5.1 Korea Web Site Evaluation & Development Institute
    - WEB QUAL Website Quality Certification
    4 areas, 220 detailed items
    - Content: Currency, Understandability, Diversity & Completeness, Usefulness, Accuracy
    - Commerciality/User Service: Transaction process, Marketing, Diversity & Activation of communication channels, Responsiveness, Public interest, Other support
    - Design: Interactivity, Information structure, Navigation, Visual elements
    - Technology: System performance, Security
 5.2. Web Accessibility: Disability Discrimination Act
    - Perceivability: Sections for visually impaired, colorblind
    - Operability: Keyboard usability, skip function, new window notification
    - Understandability: Table summary information, title provision, use of label formats, content order
    - Technical Robustness: Compliance with web application accessibility
 5.3. Web Standards
    - W3C Markup Validation Service
        : Checks website's compliance with web standards
    - W3C mobileOK Checker
        : Checks web pages for mobile environment compatibility
    - ACID Test: Tests browser's compliance with web standards
    - Open Web: A domestic community that demands improvement of e-government and internet services, which are only usable with AX and IE, to comply with international standards.
