**1. ****제목 : **모바일기기의 온라인 스토리지 응용방법

**2. 최초 작성일 :** 2009년 5월 19일

**3. ****내용**** :** 기존의 모바일 기기의 경우 메모리의 제약사항이 존재한다. 이를 온라인환경하를 가정하여 활용 방안을 모색해본다.

**4. 특징 :**
**  - 작은 로컬 스토리지를 캐시로 활용**
: 자주 사용, 혹은 최근 사용한 파일은 로컬에 저장
: 이를 통해 온라인의 회선 점유율을 최소화 한다.
**  - 파일의 인덱스나 썸네일을 로컬 스토리지에 저장하여 간략한 내용 조회 가능, 폴더 구조 변경 가능**
**  - 유저는 온라인과 로컬의 차이를 최소한만 느끼도록 함**
: 온라인 상태에서는 없는 내용을 조회하는 경우에만 다운로드 시간을 요구함
: 오프라인 상태에서는 썸네일과 요약내용으로 해당 내용을 조회가 가능
(폴더 편집과 관리는 본문 내용이 존재하지 않더라도 가능함)
- 이동단말이 아닌 고정 PC등 다수의 단말기기와 SYNC 를 허락함

**5. 활용방안**
- Wibro모듈이 달린 카메라, 카메라폰
: - 사진을 찍으면 로컬에 저장됨
- 전송 모듈은 서버와 개인의 인증과정을 거치고 해당 내용을 서버로 전송
- 서버측은 사진의 유효성을 체크한후, 카메라에게 해당 내용을 삭제해도 좋다는 내용을 전송
- 카메라는 삭제에 대한 내용을 받으면, 썸네일만을 남기고 삭제하여 스토리지를 아낌
- 로컬 스토리지의 크기에 따라 최근이미지는 삭제하지 않도록 하여 전송지연을 최소화 할 수 있음
- 삭제된 이미지도 조회시 다운로드 하여 보는것이 가능하고, 썸네일만을 확인하는 경우는 크게 문제되지 않음
- 폴더, 앨범 편집은 로컬에서도 진행이되며 해당 내용은 서버로 전송되어 서버도 같은 내용을 수행함
- PC의 어플리케이션을 통해 PC의 로컬 폴더도 싱크 가능
: PC어플리캐이션도 단말에 설치된 어플리캐이션과 동일한 기능, 로컬 스토리지 사용 제한을 설정 가능
- 블루투스나 Zigbee를 통한 노트북등의 이동 스토리지 단말과 카메라와도 동일한 기능 수행 가능함
: 포탈의 서버대신, 노트북에 서버 프로그램을 설치하고, 블루투스로 카메라와 연결
: 카메라에서 사진을 찍으면 노트북과 동기화

**6. 구조**
* 서버 (Hadoop등의 가상 스토리지 제공)
* 온라인 스토리지 어플리케이션은 카메라등의 어플리케이션과 직접, 혹은 간접 연동
* 온,오프라인 적응

**1. Title:** Application Methods for Online Storage on Mobile Devices
 
**2. Original Publication Date:** May 19, 2009
 
**3. Content:** Existing mobile devices have memory limitations. This document explores ways to utilize them, assuming an online environment.
 
**4. Features:**
**  - Utilize small local storage as a cache**
    : Frequently used or recently used files are stored locally
    : This minimizes online bandwidth usage.
**  - Store file indexes or thumbnails in local storage for quick content viewing, and allow folder structure changes**
**  - Minimize the difference users perceive between online and local**
    : In online mode, download time is only required when viewing content that is not present locally.
    : In offline mode, content can be viewed using thumbnails and summaries.
     (Folder editing and management are possible even if the main content is not present.)
  - Allow SYNC with multiple devices, such as fixed PCs, not just mobile terminals.
 
**5. Application Methods**
  - Cameras and camera phones with Wibro modules
    : - When a photo is taken, it is stored locally.
      - The transmission module undergoes a personal authentication process with the server and sends the content to the server.
      - The server checks the validity of the photo and sends a message to the camera indicating that the content can be deleted.
      - Upon receiving the deletion message, the camera deletes the content, leaving only the thumbnail, thus saving storage.
      - Depending on the size of the local storage, recent images can be kept to minimize transmission delays.
      - Deleted images can still be viewed by downloading them, and simply checking thumbnails is not a major issue.
      - Folder and album editing are performed locally, and the changes are sent to the server, which then performs the same actions.
      - PC local folders can also be synced via a PC application.
       : The PC application has the same functions as the application installed on the device, and local storage usage limits can be set.
  - The same functions can be performed with mobile storage devices like laptops and cameras via Bluetooth or Zigbee.
    : Instead of a portal server, install a server program on a laptop and connect to the camera via Bluetooth.
    : When the camera takes a photo, it syncs with the laptop.
 
**6. Structure**
  * Server (providing virtual storage like Hadoop)
  * Online storage applications are directly or indirectly linked with applications like cameras.
* Online/offline adaptation
