**1. 데이터 베이스 기본 개념**
** 가. 데이터의 의미**
**  - 데이터, 정보, 지식, 지혜와의 비교**

| 항목 | 내용 | 사례 |
| --- | --- | --- |
| 데이터 | 단순한 자료, 사실 | 지역별 인구수, 지역별 산업 |
| 정보 | 사용자의 필요에 의해 데이터를 가공하여 만들어진 데이터 | 산업이 변화된 지역의 인구 변화 |
| 지식 | 정보에서 추출된 일반화된 패턴, 의사결정에 도움이 되는 정보 | 지역별 산업과 인구간의 상관 관계, 공식 |
| 지혜 | 지식을 내재적 가치로 만들어내는 정신적인 능력, 가치를 만들어내는 룰을 습득하는 능력 (지능) | 인구감소에 적합한 산업 구조 변화 |

**  - 데이터 베이스의 정의 : ** 조직의 여러 응용시스템이 공용하기 위해 최소의 중복으로 통합, 저장된 운영 데이터의 집합 (통합,저장,운용,공용)

| 정의 요소 | 내용 | 사례 |
| --- | --- | --- |
| 통합(Intergrated) 데이터 | 데이터를 통합하여 중복을 제거 | 각 사업부서에 공통 데이터 통합 |
| 저장(Storaged) 데이터 | 컴퓨터 매체에 저장 | 하드디스크에 저장 |
| 운영(Operational) 데이터 | 조직목적이나 기능수행에 필요한 데이터 | 사용자 권한 정보 데이터 |
| 공용(Shared) 데이터 | 조직에 있는 여러 응용 시스템이 공동으로 생성하고 유지하며 이용하는 공동의 데이터 | 네트워크에 연결된 데이터 베이스 |

** - 데이터 베이스의 가치**

| 가치 | 내용 | 사례 |
| --- | --- | --- |
| 중복성 감소(Redundancy) | 데이터 통합으로 중복성 감소, 기억장치 감소, 통제권 강화 | 정규화를 통한 중복 데이터 제거 |
| 불일치 회피(Inconsistency) | 두개의 데이터가 함께 수정이 되어야 할때 하나가 수정이 안되어 일관성이 깨지는 상황 방지 | 통합되어 있는 데이터로 수정될 데이터 개수를 줄여주고, 트랜잭션을 이용하여 불일치 방지 가능 |
| 데이터 공유(Shared) | 응용 프로그램간의 필요 데이터 공용 접근 | 분산 DB, 네트워크상에서 DB에 동시에 접근 가능 |
| 표준화(Standard) | 중앙 통제, 적절한 채널을 통해서만 접근 가능한 정책 수립 가능 | DB를 공용 사용하기 때문에 다른 응용프로그램들이 같은 인터페이스 사용, DBA의 통제 및 표준 테이블명등의 정책 가능 |
| 보안(Security) | 데이터 베이스의 적절한 수준의 접근 권한 제어 가능 | 유저별, 그룹별 DB의 자원 접근 권한을 따로 설정할 수 있음 |
| 무결성(Integfity) | 데이터 베이스의 정확성을 보증 | 중앙통제를 통해, 중복 제거와 불일치 회피등을 통해 무결성의 요건에 쉽게 만족 시킬 수 있음 |

**  - 관계(relationship)** : 객체간의 관계, 계체를 기술하는 속성관계(테이블과 컬럼간)와 개체 집합 사이의 관계(테이블간)를 나타내는 개체 관계로 분류 [요구사항 명세서에서는 주로 형용사,부사]

** 다. 데이터베이스 시스템(DBS)**
{{IMG:3}}
- DB : 한 조직의 여러 응용 시스템이 공용하기 위해 최소의 중복으로 통합, 저장된 운영데이터의 집합
데이터 사전 : 자료에 관한 정보 저장소, 데이터 베이스 메타데이터 레파지토리
- DBMS : 데이터 베이스를 구축하고 이용하는 기능을 제공하는 시스템 소프트웨어 (실제 패키지)
관계형(RDBMS),객체지향(OODBMS), 객체관계(ORDBMS)
- DBL : 데이터 베이스 시스템을 다루기 위한 언어
DDL 정의기능(논리적,물리적 스키마)
DML 조작기능(삽입,삭제,갱신,검색)
DCL 제어기능(무결성,보안,병행수행)
- 사용자 : DBA(데이터베이스 설계,구축, 운영, 튜닝, 표준화), DA(데이터 관리체계, 표준수립, 모델링, 보안모델)
유저(응용프로그래머, 프로그램 사용자)

**2. 데이터 베이스 운영**
** 가. 트랜잭션**
- 트랜잭션의 특징

| 구분 | 내용 |
| --- | --- |
| 원자성(Atomicity) | 분해 불가, 전체 처리 혹은 전체 수행안함 (All or Nothing) |
| 일관성(Consistaency) | 실행 결과 모순 없음 |
| 고립성 (Isolation) | 단독 실행, 동시실행 불가 |
| 영속성 (Durability) | 완료된 결과 저장 |

- 트랜잭션의 처리 방법 : DCL에 해당

| 처리방법 | 주요 개념 |
| --- | --- |
| Commit | 해당 Transaction을 완료하고, 결과를 저장 이후 새로운 Transaction 수행가능 |
| RollBack | 해당 Transaction 폐기(Abort)하고 데이터베이스의 저장 내용을 철회(RollBack) 이후 새로운 Transaction 수행가능 |
| 성공적 프로그램 종료 | Commit 과 동일한 효과 이후 새로운 Transaction 수행불가 |
| 비정상 프로그램 종료 | RollBack 과 동일한 효과 이후 새로운 Transaction 수행불가 |

** 나. 동시성 제어**
- 동시성 제어의 필요성

| 문제점 | 내용 |
| --- | --- |
| 갱신내용손실(Lost update) | 트랜잭션들이 동일 데이터를 동시에 갱신할 경우 발생하는 문제 |
| 현황파악 오류(Dirty Read) | 트랜잭션 수행 중, 다른 트랜잭션이 해당 데이터를 참조 할때 발생하는 문제 |
| 모순성(Inconsistency) | 두 트랜잭션이 동시에 실행하고, 일관성이 없는 모순된 상태로 남는 문제 |
| 연쇄복귀(Cascading Rollback) | 트랜잭션들이 같은 데이터를 한 트랜잭션이 정상 Commit했으나 다른 트랜잭션이 갱신을 취소하고 복귀 |

**   - 동시성 제어 로킹 기법**
상호 배제(Mutual Exclusive) 이용

| 종류 | 내용 |
| --- | --- |
| 공유 Lock(Shared lock) | 다른 Transaction 읽기허용 |
| 전용 Lock(Exclusive lock) | 읽기, 쓰기 모두 금지 |

**   - 분산 트랜잭션을 위한 2PC**
: 2단계로 나누어 lock을 하는 방법으로, 직렬 가능성을 보장 할 수 있는 규약으로 범용 이용
: 교착상태 발생 가능성이 존재함 (예방과 탐지로 해결)

| 단계 | 내용 |
| --- | --- |
| 확장 | 트랜잭션은 Lock 만 수행 |
| 수축 | 트랜잭션은 UnLock 만 수행 |

**   - 타임 스탬프 순서 기법**
DBMS가 트랜잭션의 입력 시간을 확인하여 순서를 정함
교착상태 방지, 연쇄복귀 초래 가능
논리적 계수 방법 (카운터 이용) / 시스템 시계 사용 방법(시스템 클럭 이용)
** 다. 2PC**
- 분산 트랜잭션의 원자성 보장을 위해 2단계로 나누어 수행하는 기법
- 서버(데이터 소유 노드), 클라이언트(분산 트랜잭션 발생 노드)
조정자(분산트랜잭션과 참여자 관리), 참여자(분산 트랜잭션 수행)
{{IMG:6}}
- Prepare 1단계 : 조정자가 참여자에게 준비 신호 요청, 응답 수집
- Commit 2단계 : 모두 성공했으면 commit 전파, 하나라도 실패했으면 rollback 전파
라. 회복 : 장애시 이전의 일관된 상태로 복원

| 구분 | 개념 | col3 |
| --- | --- | --- |
| 회복의 기본원칙 (중복) | 데이터 | 데이터 중복 |
| Archive 또는 Dump | 다른 저장장치로 자료 복사 덤프 |  |
| Log 또는 Journal | 갱신된 속성의 과거값 / 갱신값 별도 유지 온라인로그(디스크), 보관로그(테이프) |  |
| 회복을 위한 조치 | REDO | Archive 사본 + Log : commit 후의 상태 즉, 회복된 DB상태로 데이터베이스 복원 |
| UNDO | Log+Backward 취소 연산 : 해당 트랜잭션 시작상태 즉, 원래의 데이터 베이스 상태로 복원 |  |
| 시스템 | 회복관리기 | 신뢰성 제공을 위한 DBMS서브 시스템 |

- 기법간 비교

| 구분 | 로그 기반 기법 | 체크포인트 기법 | 그림자 페이지 기법 |
| --- | --- | --- | --- |
| 개념 | 로그 파일을 이용한 복구 | 로그파일과 검사점 이용 | 그림자 페이지 테이블 이용 |
| 특징 | Redo, Undo를 결정하기 위해 전체 로그를 읽어야 하므로 시간이 많이 걸림 Redo를 할 필요가 없는 트랜잭션을 또다시 Redo 해야하는 문제 | 로그기반보다 상대적으로 회복 속도가 빠름 | - Undo가 간단하고 Redo가 불필요하므로 수행속도가 빠르고 간편 - 여러 트랜잭션이 병행 수행되는 환경에서는 단독으로 사용이 어렵고, 로그 기반이나 검사점 기법과 함께 사용 - 데이터 단편화 발생 - 그림자 페이지 테이블 복사, 기록의 오버헤드 |

3. 데이터 베이스 트리
가. 트리의 구성요소

| 구분 | 설명 |
| --- | --- |
| Root Node | level 이 0인 노드 |
| leaf Node | 차수가 0인 마지막 노드 |
| degree | 노드의 서브트리 수 |
| level | 루트로부터의 노드까지 경로 길이 |
| Depth | 트리에 속한 노드의 최대 레벨 |

나. 이진 Tree
- 정의 : 모든 노드의 차수가 2이하로 구성된 유한집합의 트리, 공집합 또는 하나의 루트노드와 왼쪽 서브트리, 오른쪽 서브트리로 구성된 노드의 집합
- 이진 Tree 종류

| 종류 | 설명 |
| --- | --- |
| 완전이진 트리(complete binary tree) | 깊이가 K-1까지는 포화이진트리이고, 레벨K에서 노드배열이 왼쪽에서 오른쪽으로 나열된 트리 |
| 포화 이진 트리(full binary tree) | 깊이가 K일때 전체 노드의 수가 2^(k-1) 노드들로 꽉 찬 트리 |
| 경사 트리(skewed tree) | 노드가 좌측 또는 우측 한쪽으로만 치우친 트리 |

- 이진 Tree 순회 방법

| 구분 | 설명 | 사례 |
| --- | --- | --- |
| 전위 순회(Preorder) 순회 | 중 -> 좌 -> 우 | ABDHIECFG |
| 중위 순회(Inorder) 순회 | 좌 -> 중 -> 우 | HDIBEAFCG |
| 후위 순회(Postorder) 순회 | 좌 -> 우 -> 중 | HIDEBFGCA |

다. B Tree
{{IMG:8}}
- 개념
: 루트와 리프를 제외한 나머지 모든 노드는 최소 트리의 차수(m)/2개의 서브트리를 가짐
: 루트가 리프가 아니면 적어도 2개의 서브트리를 가짐
: 모든 리프 노드는 레벨이 동일한 균형 트리
: 노드 안에는 키 값들로 정렬
: 리프노드는 키값이 소팅되어 검색이 용이하도록 양방향으로 연결(link)
- 균형 알고리즘
1) 재배치(redistribution) : 트리구조의 변경 없음
: 해당 노드 왼쪽/오른쪽 노드에 최소 키값보다 많은 키값을 갖고 있을 때 사용
: 선택된 형제노드로부터 부모노드를 경유하여 키값을 해당 노드로 이동
: 부모노드, 형제노드, 해당노드의 키값 중 중간 값을 부모 노드로 보내고 나머지를 2개로 나누어 할당
: 키값의 분포를 균형있게 유지하여 트리성능 개선
2) 합병(merge, concatenation) : 트리구조 변경
: 재배치가 불가능할 경우 사용(분열의 반대개념)
: 부모노드와 형제노드의 키값과 해당 노드의 키값을 하나의 노드로 합병
: 합병당한 두 노드 중 하나를 새로 만들어진 노드로 대치하고, 나머지 한노드는 제거
: 최악의 경우 루트 노드까지도 변경

 c. B-Tree
{{IMG:8}}
   - Concept
   : All nodes except the root and leaves have at least (m)/2 subtrees, where m is the order of the tree.
   : If the root is not a leaf, it has at least 2 subtrees.
   : A balanced tree where all leaf nodes are at the same level.
   : Key values are sorted within the nodes.
   : Leaf nodes are linked bidirectionally for easy searching with sorted key values.
  - Balancing Algorithm
   1) Redistribution: No change in tree structure.
      : Used when the left/right sibling node of the current node has more key values than the minimum.
      : Moves a key value from the selected sibling node to the current node via the parent node.
      : The median key value among the parent node, sibling node, and current node is sent to the parent node, and the remaining values are divided and allocated to the two nodes.
      : Improves tree performance by maintaining a balanced distribution of key values.
   2) Merge (Concatenation): Changes tree structure.
      : Used when redistribution is not possible (opposite concept of splitting).
      : Merges the key values of the parent node, sibling node, and current node into a single node.
      : One of the two merged nodes is replaced by the newly created node, and the other is removed.
      : In the worst case, even the root node can be changed.
 d. B, B+, B* Tree Comparison

| Category | B | B+ | B* |
| --- | --- | --- | --- |
| Sequential Access | Inorder Traversal | Search only leaf nodes | Inorder Traversal |
| Direct Access | Tree traversal search | Traverse and search index set tree | Tree traversal search |
| Speed | Normal | Sequential search is fast | Faster than B-tree |
| Redundancy | No search key redundancy | Duplicate keys exist in index set and sequential set | No search key redundancy |
| Node Key Movement Criteria | When node is more than 1/2 full | When node is more than 1/2 full | When node is more than 2/3 full |
| Node Management | Non-leaf nodes are larger, and storage space management is complex | All nodes are the same size, and nodes to be deleted exist in leaf nodes | Non-leaf nodes are larger, and storage space management is complex |

 e. T-Tree
   {{IMG:9}}
   - Contains multiple data items in a node
   - Node has a left subtree with values smaller than the minimum value
   - Node has a right subtree with values larger than the maximum value
   - The rightmost element of the left subtree is the GLB (Greatest Lower Bound)
   - The leftmost element of the right subtree is the LUB (Least Upper Bound)
   - Comparison with B-Tree

| Category | T-Tree | B-Tree |
| --- | --- | --- |
| Utilized DBMS | Main Memory DBMS | Relational DBMS |
| Logical Address Translation | Tree node directly points to main memory address | Requires translation of logical address to physical address for pointing |
| Entry Size | Economical use of memory address space due to direct pointing to main memory address | Requires logical address value, header information, and physical address area, etc. |
| Design Focus | Focuses on reducing CPU usage time for fast speed and performance | Focuses on minimizing I/O for data stored on disk |
| Access Speed | Improved speed due to direct main memory access | Additional processing required to translate logical address to physical address |

 g. Trie Tree
  - A tree structure where the number of characters forming a key value constitutes the level.
  - A structure that represents key values by the order of characters or numbers that make up the key.
