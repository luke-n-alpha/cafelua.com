****요약 : **기존의 태깅 기반의 이미지 검색 결과들을 기반으로, 쿼리별로 다수의 상품 이미지 모델을 만들고, 이미지를 입력받으면 해당 상품을 찾아준다는 내용입니다.  최근 구글에서 발표한 이미지 검색을 상상해 보면 비슷할것 같네요. ^^;**
****-- 아래는 발명 초안 전문 ----****
****
****1. 제목 : 쇼핑의 이미지 검색 구현 방법**
**2.기존의 쇼핑 이미지 검색 : **기존에 이미 많은 회사에서 이미지 검색을 통해 쇼핑 검색을 하고자 하는 시도가 있었다.그러나 일반적인 사진에서 특정 쇼핑 상품을 검색하는 방식으로 접근되었다.

{{IMG:1}}<- 사용자가 해당 이미지에서 핸드폰의 위치를 클릭시, 이로부터 물체의 영역을 잡아내고 물체를 기존의 모델  {{IMG:2}}   과 비교하여 해당 모델을 찾아낸다.
: 그러나 위와 같은 방식은 모델을 만들기가 매우 어렵고 다양한 사진에서와 유사도는 매우 낮다. **3. 착안점**: 많은 유저들이 상품 정보를 스크랩을 통해서 가져가게 된다. 특히 특정 상품에 대한 이미지들은 매우 한정적이지만, 이미지 관점에서는 매우 다양한 패턴을 지닌다.{{IMG:3}}  ex) 아이스크림폰으로 검색한 화면
종류는 몇 종류 안되지만, 위의 이미지들을 가지고 아이스크림폰을 한 개의 모델로 만든다는 것은 사실상 어렵다.
**4. 구현 방법 **
{{IMG:4}}                            [네이버내에서 이를 구현하기 위한 기존 정보들의 개념도]  **1) 모델을 이용하여 구현하는 방법**   1.1) 하나의 상품은 다수의 이미지 모델을 지니게 되는데, 이는 상품의 영역분리 등을 하지 않고 해상도만 정규화한 다수의 이미지를 가지게 한다. (하나의 클래스는 다수의 이미지 모델을 가진다.)     ->  특정 이미지가 들어왔을 때, 해당 이미지모델 중 가장 유사한 것을 찾은 후, 해당 상품 URL을 알려준다.   1.2) 상품의 다수의 이미지 모델 수집 방법은 검색결과와 CP들이 제공하는 정보를 이용한다.     : 기존의 이미지 검색의 결과를 이용한 DB  -  LG-LH5000 이란 폰은 아이스크림폰, 김태희폰 등의 검색어 쿼리를 갖게 되고 이때 나오는 이미지 검색의 상위 결과가 모델이 되게 된다.     : 전문가 리뷰에 등록된 이미지들 -  많은 사람들이 상품의 깨끗한 이미지들을 찾기가 어려우므로 전문가 리뷰등에 등록된 이미지들을 찾아 스크랩하게 된다. 때문에 이러한 이미지들은 매우 좋은 모델이 된다.   **Ex)****  LG-LH5000**       -  전문가 리뷰 페이지의 이미지 : [http://shopping.naver.com/detail/detail.nhn?cat_id=00110201&nv_mid=4113856717&ani=0&tc=6](http://shopping.naver.com/detail/detail.nhn?cat_id=00110201&nv_mid=4113856717&ani=0&tc=6)       -  아이스크림폰 검색 페이지의 이미지 : [http://image.search.naver.com/search.naver?where=image&sm=tab_jum&query=%uC544%uC774%uC2A4%uD06C%uB9BC%uD3F0%20](http://image.search.naver.com/search.naver?where=image&sm=tab_jum&query=%uC544%uC774%uC2A4%uD06C%uB9BC%uD3F0%20)      -   LH5000 검색 페이지의 이미지 :  [http://image.search.naver.com/search.naver?sm=tab_hty&where=image&query=LH5000](http://image.search.naver.com/search.naver?sm=tab_hty&where=image&query=LH5000)
{{IMG:5}}
**2) 모델을 이용하여 구현 하는 방법**  2.1) 기존의 이미지 서버에서 가장 유사한 이미지를 찾는다.  2.2) 가장 유사한 이미지의 태깅 리스트를 추출한다.  2.3) 태깅리스트와 가장 근접한 쇼핑 객체명을 찾아 해당 쇼핑 페이지를 보여준다.     (이때, 보여주는 쇼핑 객체는 한 개가 아니라 유사도 순으로 보여주어도 된다.) {{IMG:6}}

**7. 효과**: 블로그나 웹 서핑 도중 해당 이미지를 클릭시 바로 쇼핑 검색을 가능하게 해주어, 유저가 파일을 올리지 않아도 검색이 가능하게 한다. 해당 이미지의 태깅은 다른 누군가의 블로그 정보를 통해 해두었을 가능성이 높고, 그 태깅 정보를 통하여 모델이 만들어져 있거나, 혹은 다른 쇼핑 객체를 유추할 수 있다. {{IMG:7}} -       네이버 내의 경우, 블로그등에 사용할 수 있으며, 외부 사이트 까지 적용하기 위해서는 툴바등의 서비스에 적용 할 수 있다. **1) 차별성** -  하나의 상품에 다수의 이미지 모델을 만들어 두어 정확한 이미지 모델을 만들어 두지 않는 검색 방식 -  이미지 혹은 통합검색 같은 다른 검색 쿼리, 혹은 이미지 검색의 태깅 정보를 이용한 이미지 모델의 데이터를 수집하는 방법 - 이미지 서버에서 유사 이미지를 찾아, 해당 태깅 정보를 통해 쇼핑 등에 활용하는 방법 - 블로그에 이미지로 쇼핑 검색을 하는 기능 추가하여 웹 서핑중 사용자가 손쉽게 이미지쇼핑 검색을 이용하게 하는 방법 - 툴바를 이용하여 외부에서도 손쉽게 이미지 쇼핑 검색을 이용하는 방법  **http://opencast.naver.com/FS565****[****](http://www.hanrss.com/add_sub.qst?url=http%3A%2F%2Fblog.rss.naver.com%2Ffstory97.xml)** {{IMG:8}}

**Summary:** This content describes creating multiple product image models per query based on existing tag-based image search results, and then finding the corresponding product when an image is input. It seems similar to the image search recently announced by Google. ^^;
**-- Full Draft of Invention Below ----**

**1. Title: Method for Implementing Image Search in Shopping**
**2. Existing Shopping Image Search:** Many companies have already attempted to conduct shopping searches through image search. However, the approach has been to search for specific shopping products from general photos.

{{IMG:1}}<- When a user clicks on the location of a mobile phone in the image, the object's region is extracted, and the object is compared with an existing model {{IMG:2}} to find the corresponding model.
: However, this method makes it very difficult to create models, and the similarity across various photos is very low. **3. Key Idea:** Many users obtain product information through scraping. While images for specific products are very limited, they exhibit a wide variety of patterns from an image perspective. {{IMG:3}} ex) Screen searched for "Ice Cream Phone"
Although there are only a few types, it is practically difficult to create a single model for the Ice Cream Phone using the images above.

**4. Implementation Method**
{{IMG:4}} [Conceptual Diagram of Existing Information for Implementation within Naver] **1) Method using models** 1.1) A single product has multiple image models, which means it has multiple images with only resolution normalized, without object segmentation. (One class has multiple image models.) -> When a specific image is input, the most similar image model is found, and then the corresponding product URL is provided. 1.2) The method for collecting multiple image models for a product uses search results and information provided by CPs (Content Providers). : DB using existing image search results - A phone called LG-LH5000 has search queries like "Ice Cream Phone," "Kim Tae-hee Phone," etc., and the top results from image searches for these queries become the models. : Images registered in expert reviews - Since many people find it difficult to find clean images of products, they scrape images registered in expert reviews, etc. Therefore, these images become very good models. **Ex) LG-LH5000** - Image from expert review page: [http://shopping.naver.com/detail/detail.nhn?cat_id=00110201&nv_mid=4113856717&ani=0&tc=6](http://shopping.naver.com/detail/detail.nhn?cat_id=00110201&nv_mid=4113856717&ani=0&tc=6) - Image from Ice Cream Phone search page: [http://image.search.naver.com/search.naver?where=image&sm=tab_jum&query=%uC544%uC774%uC2A4%uD06C%uB9BC%uD3F0%20](http://image.search.naver.com/search.naver?where=image&sm=tab_jum&query=%uC544%uC774%uC2A4%uD06C%uB9BC%uD3F0%20) - Image from LH5000 search page: [http://image.search.naver.com/search.naver?sm=tab_hty&where=image&query=LH5000](http://image.search.naver.com/search.naver?sm=tab_hty&where=image&query=LH5000)
{{IMG:5}}
**2) Method using models** 2.1) Find the most similar image from the existing image server. 2.2) Extract the tagging list of the most similar image. 2.3) Find the shopping object name closest to the tagging list and display the corresponding shopping page. (At this time, the shopping objects displayed can be more than one, shown in order of similarity.) {{IMG:6}}

**7. Effects:** By allowing immediate shopping search when an image is clicked during blog or web surfing, users can search without uploading files. It is highly probable that the image has been tagged through someone else's blog information, and this tagging information can be used to create a model or infer other shopping objects. {{IMG:7}} - For Naver internally, it can be used in blogs, etc., and to apply it to external sites, it can be integrated into services like toolbars. **1) Differentiation** - A search method that creates multiple image models for a single product, rather than relying on a single precise image model. - A method for collecting image model data using other search queries like image or integrated search, or tagging information from image search. - A method for finding similar images on an image server and utilizing their tagging information for shopping, etc. - A method for adding an image-based shopping search function to blogs, allowing users to easily use image shopping search while web surfing. - A method for easily using image shopping search externally via a toolbar. **http://opencast.naver.com/FS565****[****](http://www.hanrss.com/add_sub.qst?url=http%3A%2F%2Fblog.rss.naver.com%2Ffstory97.xml)** {{IMG:8}}
