엔프로텍터를 두고 유저들은 멜스웨어라고 까지 비방하고 있고, 안드로이드 마켓에 엔프로텍터의 등장은 시끄러운 이슈를 던져주었습니다. 도대체 앤프로텍터는 무엇을 그렇게 잘못했기에 이렇게 말이 많은걸까요?

**1. 왜 웹보안을 위해 어플리케이션을 깔아야하는가?**
** - 웹의 목적을 잊어버린 수단****
******엔프로텍터와 시큐어웹등 인터넷 뱅킹 사용시 액티브엑스로 몇가지의 어플리케이션을 내려 받습니다. 사실 이때 내려받는 액티브엑스란 기술은 웹이라기보다는 사실 윈도우즈 어플리케이션에 가깝습니다. 특정 웹 사이트에 접근하기위해서 특정 어플리케이션을 까는것이 우리의 현실입니다.
그런데 여기서 하나의 의문점이 듭니다.
왜 인터넷 뱅킹에 웹을 사용중인가 하는것입니다. 웹의 특징은 업데이트가 필요없고 빠른 개발, 다양한 플랫폼에서의 접근 가능등의 목적을 위해 개발됩니다. 이 중 빠른개발은 인터넷 뱅킹등의 작업에는 어플리케이션 개발에 비해 웹이 더 개발이 쉬운지는 의문입니다.
** 그렇다면 다른 장점을 가져가야 하는데 여기에 앞단에 어플리케이션 설치로 인해 인터넷 웹 뱅킹의 가장 큰 장점인 플랫폼의존도를 버리는 장점은 무용지물이 됩니다.
**그렇다면 애시당초 인터넷뱅킹은 윈도우즈 어플리케이션으로 개발을 하지 않는 이유를 모르겠습니다.  {{IMG:1}}

**2. 사용자의 가용성을 해치는 엔프로텍터
- 보안에는 가용성이란 항목이 존재합니다. 트레이드 오프에 균형이 필요합니다만, 프로그램은 죽지말아야 한다는 가장 기본적인 룰을 어기고 있습니다.**
앤프로텍터등의 ax의 기술의 가장 큰 문제는 사용자의 가용성을 해치는것입니다. 가장 잘 된 보안이란 사용자가 모르는 안전한 기술입니다. 그러나 사용자에게 나 이거하고 있으니 댁의 컴퓨터가 더 안전해지고 있습니다. 라고 떠들뿐만 아니라 설치후에는 로그인 정보, 심지어는 브라우져에 입력했던 모든 내용을 날려버리며 브라우져를 재구동합니다.
특정서비스를 쓰다가 프로그램이 중간에 재부팅되는 건데 이러한 사용자 행동이 사용자를 얼마나 열받게 할른지는 쉽게 상상이가능합니다.
** 강력하다고만 좋은게 아니죠. 가장 강력한건 은행 가서 직접 등본띄어서 거래하는겁니다.**

**3. 왜 국내의 모든 은행, 게임사는 이 회사의 솔루션을 쓰고 있을까?
- 공공기관 SI업체들의 문제점이 풀풀 느껴지는 분위기 **
국내에 보안업체가 정확히 몇개가 되는지는 모르겠지만 왜 대부분이 이 회사의 솔루션을 쓰는걸까요? 어떤 특허라도 가지고 있는건지 아니면 공인인증서처럼 국가에서 체택한건지.. 이게 공기업인건지.. 무슨필수어플인건지.
영업력의 승리라고도 생각할 수 있겠지만 도대체 왜 모두 여기걸 쓰고 있는지도 의문입니다. 여기에다 또 안철수연구소껀 왜 또까는건지.. 의아하기만 합니다.
국내의 공공기관 정보화 프로젝트들이 상당수가 그저 밥그릇 만들기였다는 인상이 있는만큼 이것 역시 자유롭지 못할겁니다.

**4. 안드로이드에 엔프로텍터가 필요한가?**
** - 중요한 사용자의 선택권은 어디로 ?, 그리고 왜 특정 기업에 국가가 편을 들어주는가 ?**
물론 필요할수도 있습니다. 그러나 기본적으로 엔프로텍터는 사용자단의 보안입니다. 따라서 사용자단말이 뚫린거라면 전적으로 사용자 책임입니다. 그리고 이에대한 선택은 사용자가 해야하는것이 옳지 않을까요?
그래야만 안철수연구소, 이스트소프트등의 보안업체들도 여기에 끼어들수 있습니다. 엔프로텍터를 강제하는것 역시 그다지 중립적이지 않다는 생각입니다.

**5. 주관 기관에 바랍니다.**
**사실 엔프로텍터의 문제를 보자면 국내의 공공기관 프로젝트들의 문제가 붉어져 나온것이 아닌가 합니다.** 주관부서들은 이해관계에 복잡하게 얽혀져 중립적이지 못할 뿐만아니라 기술상황에대한 기민한 반응을 못하고 있는것이 아닌가합니다. 이는 국내 기업을 보호하는것이 아니라 국내 기술이 해외기술에 발맞추지 못해 낙후되는 상황을 가져옵니다. 국내 웹개발자들은 상당수가 웹에 보안기능이 있다는 것 조차 모르고있습니다.

Users are even slandering nProtect as malware, and its appearance on the Android Market has sparked a noisy issue. What exactly did nProtect do so wrong to generate so much controversy?

**1. Why do we need to install an application for web security?**
** - A means that has forgotten the purpose of the web****
******When using internet banking with nProtect and SecureWeb, several applications are downloaded via ActiveX. In fact, the ActiveX technology downloaded at this time is closer to a Windows application than a web application. It is our reality to install a specific application to access a specific website.
But here, a question arises.
Why is the web being used for internet banking? The web is developed for purposes such as no need for updates, rapid development, and accessibility from various platforms. Among these, it's questionable whether rapid development makes web development easier than application development for tasks like internet banking.
** If so, other advantages should be pursued, but with the front-end application installation, the biggest advantage of internet web banking, which is abandoning platform dependency, becomes useless.
**Therefore, I don't understand why internet banking wasn't developed as a Windows application from the start.  {{IMG:1}}

**2. nProtect Harms User Availability
 - In security, there is an item called availability. A balance in trade-offs is necessary, but the program violates the most basic rule that it should not crash.**
 The biggest problem with technologies like nProtect's ActiveX is that they harm user availability. The best security is a safe technology that the user is unaware of. However, it not only loudly proclaims to the user, "I'm doing this, so your computer is becoming safer," but after installation, it also wipes out login information and even all content entered into the browser, then restarts the browser.
It's like the program reboots in the middle of using a specific service, and it's easy to imagine how frustrating such user behavior can be for users.
** Being powerful isn't always good. The most powerful way is to go to the bank and conduct transactions directly with a copy of your resident registration.**

**3. Why do all domestic banks and game companies use this company's solution?
 - An atmosphere where the problems of public institution SI companies are strongly felt **
I don't know exactly how many security companies there are in Korea, but why do most of them use this company's solution? Do they have some kind of patent, or was it adopted by the state like the public certificate? Is this a public enterprise? Is it some kind of essential application?
One might think it's a victory of sales power, but it's still questionable why everyone is using this one. And why are AhnLab's products also being criticized? It's just puzzling.
Given the impression that many of Korea's public institution informatization projects were merely about creating vested interests, this situation is likely not free from that influence either.

**4. Is nProtect necessary on Android?**
** - Where did the important user's choice go?, And why does the state favor a specific company?**
Of course, it might be necessary. However, nProtect is fundamentally user-side security. Therefore, if the user's device is compromised, it is entirely the user's responsibility. And shouldn't the user be the one to make the choice regarding this?
Only then can security companies like AhnLab and ESTsoft also participate. I believe that forcing nProtect is also not very neutral.

 
**5. A request to the supervising authorities.**
**In fact, looking at the problems with nProtect, it seems to be an outgrowth of issues within domestic public institution projects.** The supervising departments appear to be not only intricately entangled in conflicts of interest, making them non-neutral, but also failing to respond agilely to technological developments. This does not protect domestic companies; rather, it leads to a situation where domestic technology falls behind international standards. Many domestic web developers are not even aware that the web has security features.
