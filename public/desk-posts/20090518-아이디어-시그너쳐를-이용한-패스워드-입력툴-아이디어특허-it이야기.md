**1. 제목 : 시그너쳐를 이용한 패스워드 입력툴**
**2. 배경 :** 최근 터치기술이 인기를 얻고 있으며, 쓰는 입력 방식이 각광을 받고 있다. 타블렛 PC나 PDA의 경우, 일반 키 입력이 매우 불편한데 반해, 그리는 편은 자유로운 편이다.
**3. 차별성 : **기존의 시그너쳐를 이용한 로그인 방식은 아이디 정보와 시그너쳐를 매핑한다. 그러나 이는 시그너쳐를 패스워드와 매핑함으로서 보안성을 높이고, 구현을 훨씬 용이 하게 해준다.
**4. 유사 특허
**공개 번호 : 10-2006-0032258 타블랫 PC의 로그온 방법
[http://patent.naver.com/patent/specification.php?ApplicationNumber=1020040080828](http://patent.naver.com/patent/specification.php?ApplicationNumber=1020040080828)
- 아이디를 시그너쳐와 매핑하기 위해서는 유저수만큼의 클래스가 발생하고, 그만큼 비슷한 시그너쳐가 나올 확률이 훨씬 높아져 인식에 어려움을 격는다.
- 실제 동일한 사용자라 하더라도 동일한 입력이 들어오지 않는다. 디지타이징 된 정보는 셈플링을 거치기 때문에, 입력 수가 제한되고, 펜의 압력등을 기록 할수 없는 입력도구를 이용하는 경우가 많아 종이의 시그너쳐 인식에 비해 훨씬 난이도가 높아, 실제 구현에 어려움이 있다.
****
**5. 개선점**
- 착안점 : 아이디는 일반적으로 웹 페이지에 저장 체크박스를 만들어 두어도 크게 문제가 되지 않는다. 상대적으로 타블렛 pc나 pda는 개인기기기 때문에 다수의 사용자가 쓰는 경우는 드물어 기기에 아이디가 바뀌는 경우는 드물다.
- 모델 생성 방법 : 최초, 패스워드를 입력 받을 때, 1회를 입력 받지 않고, 다수의 입력을 받아 모델을 생성한다. 그것을 통해 다수의 공통특징을 찾아내고, 그것이 최초 입력 임계치 보다 클 경우, 다시 입력 할 것을 요청한다.
Ex) 모델생성시 허용 distance 임계치 값 : 50
시그너쳐 5회 패스워드 특징 입력값 :   80  90  100  85  110   => 110-80= 30 SUCESS
 모델은 110+80/2 = 95
시그너쳐 5회 패스워드 특징 입력값 :   80  70  50  95  110   => 110-50= 60 Fail
- 인식 방법 : 특정 아이디와 시그너쳐에 의한 접근이 시도 된다면, 기존의 아이디를 대체 하는 방식과 달리, 기존 모델과 시그너쳐 입력과의 유사도를 검사 하여, 최초 설정된 값의 임계치 값 이내이면, 로그인을 허용한다.
Ex) 로그인시 허용 distance 임계치 값 : 60
모델 특징 값 95 : 입력 값 170 => 170-95 = 75 => 60보다 크므로 FAIL
모델 특징 값 95 : 입력 값 70 => 95-70 => 25 => 60이내이므로 SUCCESS
- 보안성의 향상 : 단순히 3획의 삼각형을 시그너쳐를 하더라도, 삼각형을 그리는 획 순서와 각도를 보기 때문에 같은 이미지더라도 많은 경우의 수가 발생하며, 최종 시그너쳐의 이미지를 캡춰하거나, 네트워크상에서 데이터를 보더라도 사전에 정의된 특징을 알고 있지 않으면, 로그인을 할 수 없다. 일반적으로 알려진 글자 Code보다 보안성이 높다.
- 기억하기 쉽다 : 사람들은 글자보다 이미지를 쉽게 기억한다.
- 일반적으로 사용될 수 있는 시그너쳐의 특징 값 : 획수, 획의 시작 위치와 끝 위치, 획의 순서, 획의 각도, 시그너쳐 전체의 비율, 각 획을 쓰는데 소요된 시간
- 활용 가능 범위 : 일반 PC, 타블렛 PC, PDA, 펜혹은 터치 모바일 기기

**1. Title: Password Input Tool Using Signature**
**2. Background:** Recently, touch technology has gained popularity, and writing input methods are receiving attention. For tablet PCs or PDAs, general key input is very inconvenient, whereas drawing is relatively free.
**3. Differentiator:** Existing login methods using signatures map ID information to signatures. However, this method maps signatures to passwords, thereby enhancing security and making implementation much easier.
**4. Similar Patent**
**Publication Number: 10-2006-0032258 Logon Method for Tablet PC**
[http://patent.naver.com/patent/specification.php?ApplicationNumber=1020040080828](http://patent.naver.com/patent/specification.php?ApplicationNumber=1020040080828)
- To map an ID to a signature, a number of classes equal to the number of users are generated, which significantly increases the probability of similar signatures appearing, leading to recognition difficulties.
- Even for the same user, identical inputs are not received. Digitized information undergoes sampling, which limits the number of inputs. Furthermore, input tools often cannot record pen pressure, making recognition much more difficult compared to signature recognition on paper, thus posing challenges in actual implementation.
**5. Improvements**
- Key Idea: Generally, storing an ID on a web page with a "remember me" checkbox doesn't cause significant problems. Relatively, tablet PCs and PDAs are personal devices, so it's rare for multiple users to use them, and thus rare for the ID on the device to change.
- Model Generation Method: Initially, when receiving a password, instead of a single input, multiple inputs are received to create a model. Through this, common features are identified, and if they exceed the initial input threshold, re-entry is requested.
      Ex) Allowed distance threshold for model generation: 50
Signature 5-time password feature input values: 80 90 100 85 110 => 110-80= 30 SUCCESS
 Model is 110+80/2 = 95
Signature 5-time password feature input values: 80 70 50 95 110 => 110-50= 60 Fail
- Recognition Method: If access is attempted with a specific ID and signature, unlike methods that replace the existing ID, this method checks the similarity between the existing model and the signature input. If it falls within the initially set threshold value, login is permitted.
Ex) Allowed distance threshold for login: 60
   Model feature value 95: Input value 170 => 170-95 = 75 => Greater than 60, so FAIL
Model feature value 95: Input value 70 => 95-70 => 25 => Within 60, so SUCCESS
- Enhanced Security: Even if a simple 3-stroke triangle is used as a signature, because the stroke order and angles of drawing the triangle are considered, many possibilities arise even for the same image. Even if the final signature image is captured or data is viewed over a network, login is impossible without knowing the predefined features. This offers higher security than generally known character codes.
- Easy to Remember: People remember images more easily than characters.
- Generally Usable Signature Feature Values: Number of strokes, start and end positions of strokes, stroke order, stroke angles, overall signature proportion, time taken to write each stroke.
- Applicable Scope: General PCs, Tablet PCs, PDAs, pen or touch mobile devices.
