네이버의 신기술에 관해 소개하는 네이버랩에서 네이버 전용 파폭을 만들었네요. 파폭에 네이버 테마씌운것 같은데.. 뭐가 달라졌는지는 저도 잘..
써보니 좋네요. 필요할때는 IE탭과 적당히 섞어서 쓰니, 다른 문제도 없고 체감속도는 확실히 빠릅니다. 문제가 있다면, frame의 border를 없애는 코드가 먹지 않아서 좀 지저분하게 보이는군요. frameborder 가 비표준 태그였나...
스크립트로 도배된 곳에서는 IE와 좀 상이점이 생겨서 문제가 발생하는 듯 하지만, 그 외에는 괜찮아보입니다. Active X가 안된다고 말들이 많지만, 실제로 사용해보면 Active X를 사용하는 곳은 정부기관과 금융기관정도.. 무엇보다도 공인인증서가 안됩니다.
속도는 특히 이미지가 많은쪽에서는 IE보다는 체감속도가 확실히 좋네요. 특히 쇼핑몰 같이 스크롤이 큰 경우 크게 차이납니다. 다만, 결제가 잘되는지는 테스트 못해봤습니다. 안될 가능성이 90%라고 봅니다. IE탭쓰면 해결되겠지만.. ㅎㅎ

플러그인을 설치시 싸이월드도 별 문제없이 돌아가네요. 네이버 블로그는 뭐 특별한 작업 없이 돌아가구요. 크롬의 경우, 테스트는 아직 못해봤지만, 사파리 기반이란거 봐서 속도는 좋을듯하나 아직 호환성면에서는 그닥일듯 합니다. 구글처럼 큰회사가 잡았으니 곧 더 멋진놈이 나오겠죠.

IE외의 브라우져를 써보니.. 가장 큰 문제는 Active X보다는 다른 브라우져로 테스트 조차 안해본 일반 사이트들의 레이아웃이 깨지는 문제가 더 심각하네요. 포탈의 경우는 대채적으로 양호합니다.

며칠전 PC월드인가.. 웹표준을 잘지키기 때문에 모브라우져가 다양한 플랫폼에서 잘 돌아간다라는 개념없는 기사가 올라왔더군요. ㅡㅡ;
Java는 웹표준을 잘지켜서 다양한 플랫폼에 돌아가나? 웹표준은 다양한 브라우져에서 일괄적으로 보인다는것이고, 다양한 플랫폼지원은 해당 브라우져가 다양한 플랫폼에 포팅되었느냐의 이슈일 뿐입니다.

수년전부터 뜨거운 감자로 급부상하고 있는 웹표준이야기가 일반인들도 운운할정도로 최근 MS의 웹 OS계획과 구글의 브라우져 개발로 관심을 더 가지게 된 듯합니다. 한국이 Active X를 많이 쓴다고 걱정할 일은 기우에 지나지 않습니다.
한국이 Active X를 많이 쓰게 된 이유는 IE를 많이 썼기 때문이지, 웹표준을 어기는게 목적이 아니었으니까요. 일반 유저들이 IE에서 많이 벗어나면 결국 또 다른 브라우져에 대응하는 웹을 만들기 마련입니다.

시장을 늘 늦게 쫓아가는 정부가 가장 문제긴 하겠지만 말입니다.

무조건 MS는 악의 축이다 같은 시장과 동떨어진 이상주의 말고, 현 상황을 가장 객관적으로 설명하고 건설적으로 토의하는 포스팅이 있어서 링크를 걸어봅니다. (하지만, 왠만하면 개발자만 클릭하시길..)

Naver Lab, which introduces Naver's new technologies, has created a Naver-exclusive Firefox. It seems like they just applied a Naver theme to Firefox... I'm not entirely sure what's different.

After using it, it's good. When needed, I mix it with IE Tab, and there are no other issues, and the perceived speed is definitely fast. If there's a problem, the code to remove the frame border doesn't work, making it look a bit messy. Was `frameborder` a non-standard tag...?

In places heavily reliant on scripts, there seem to be some differences from IE, causing issues, but otherwise, it looks fine. There's a lot of talk about ActiveX not working, but in practice, the places that use ActiveX are mostly government and financial institutions... Most importantly, public certificates don't work.

The speed, especially on image-heavy sites, definitely feels better than IE. The difference is significant, especially on sites with extensive scrolling, like shopping malls. However, I haven't tested if payments work well. I'd say there's a 90% chance they won't. Using IE Tab would solve it, though.. haha.

When installing plugins, Cyworld also runs without any particular issues. Naver Blog runs without any special effort. As for Chrome, I haven't tested it yet, but given that it's Safari-based, the speed should be good, but compatibility might not be great yet. Since a big company like Google is behind it, something even better will surely come out soon.

After using browsers other than IE... the biggest problem is not ActiveX, but rather the more serious issue of layouts breaking on general websites that haven't even been tested with other browsers. Portals, in general, are satisfactory.

A few days ago, I saw a nonsensical article, I think in PC World, claiming that 'a certain browser runs well on various platforms because it adheres to web standards.' ㅡㅡ;
Does Java run on various platforms because it adheres to web standards? Web standards mean consistent rendering across various browsers, and multi-platform support is merely an issue of whether that browser has been ported to various platforms.

The topic of web standards, which has been a hot potato for years, seems to have gained more attention recently, even among the general public, due to MS's web OS plans and Google's browser development. Worrying about Korea using a lot of ActiveX is an unnecessary concern.
The reason Korea used a lot of ActiveX was because IE was widely used, not because the goal was to violate web standards. If general users move away from IE in large numbers, websites will eventually be built to support other browsers.

The government, which always lags behind the market, is probably the biggest problem, though.
