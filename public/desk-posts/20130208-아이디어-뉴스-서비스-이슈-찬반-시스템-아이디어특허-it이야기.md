해당 아이디어는 2008년 6월 17일에 냈던겁니다. 각 언론사들이 편향된 정보를 제공하고, 사용자들은 보다 다양한 의견을 만들기보다는 보수와 진보로만 나뉘는것이 아쉬워서 보다 다양한 의견들을 정직하게 보여주는 시스템을 그려보고자 그려봤던겁니다. 해당 아이디어는 출원까지 진행되었으나 진보성면에서 기각된 아이디어로 공개합니다. (대한민국에서 서비스 모델가지고 특허내기는 거의 불가능합니다.)  이 아이디어대로 하면 각 언론사, 기자들의 논조들이 항목별로 까발려지고, 네티즌들의 댓글 여론 추이를 시각적으로 볼수 있습니다. 예전에 네이버가 하도 중립성 논란에 휘말릴 때, 언론사로부터 언론을 공급받는 만큼 기계적인 중립이란 뭔가? 하고 생각해보다가..그려봤던 그림입니다.  물론,서비스팀에는 검토라도 됐는지 까지는 잘 모르겠습니다. ^^;개발자 주제에 굉장히 열심히 작성한 문서인데, 결국은 특허 용돈 벌이 수준에서 끝난듯 언론의 중립성과 토론 시스템에 대해 고민하시는 분들이라면 참고하시면 좋을 것 같아 공개합니다. --**1. 제목 : 이슈 찬반 시스템****2. 최초 작성일 : 2008년 6월 17일**  **3. 배경**     현재의 뉴스 시스템은 단순히 뉴스를 카테고라이징만 하고 있어서 기사들의 성격을 알기가 어렵고, 유저들의  의견이 반영되는 곳이 매우 제한적임. 이를 극복하기 위한 대안을 제시하려고 함 **4. 목표** 1) 각 종 이슈를 한 눈에 볼 수 있어야 함 2) 좋은 글을 상위로 올리는 효과가 있어야 함 3) 블로그와 연동을 통하여 활발한 의견 개진이 가능한 시스템이어야 함 4) 뉴스의 기사들에 대한 성격을 정의할 수 있어야 함 5) 모든 이슈를 포괄할 수 있는 적응성이 있어야 함 **5. 용어 설명** **1)  이슈 :** 간단한 제목이나 단어로 대표 되는 주제어 [사각형]  (해당 이슈가 존재하지 않는 경우, 블링크처럼  사용자가 추가 할 수도 있다.) **2)  찬/반 웹 객체  :** 기자나 유저에 의해서 생산되는 웹의 게시물들 [원] - 한 개의 웹 객체는 다수 의 이슈의 찬/반을 가지게 된다.  ex) 기사, 포스팅,  댓글 **3) 관련 웹 객체 [모서리 잘린 사각형] : **이슈 관련 게시판, 링크, 연관 검색어 등이   해아되는 것으로서 찬,반의 입장을 가지지 않는 객체를 의미한다.  **4) 의견 :** 웹 객체가 갖는 다른 이슈나 객체와의 찬/반의  연관 관계 [그림의 라인]**

This idea was conceived on June 17, 2008. It was drawn up because I felt it was a shame that various media outlets provided biased information, and users were divided only into conservative and progressive camps rather than forming more diverse opinions. I wanted to create a system that honestly showed a wider range of opinions. This idea was even submitted for a patent application but was rejected due to lack of inventiveness. (It's almost impossible to patent a service model in South Korea.) If implemented according to this idea, the editorial stances of each media outlet and journalist would be revealed by category, and the trend of public opinion in netizens' comments could be visually observed. Back when Naver was constantly embroiled in neutrality controversies, I wondered, "What exactly is mechanical neutrality when we receive news from media companies?" and this is the drawing that came out of that thought. Of course, I'm not sure if the service team even reviewed it. ^^; This document was written very diligently for a developer, but it seems to have ended up just being a patent "pocket money" level. I'm making it public in case it might be helpful for those who are contemplating media neutrality and discussion systems.
--
**1. Title: Issue Pro/Con System**

**2. First Draft Date: June 17, 2008**

**3. Background**
The current news system merely categorizes news, making it difficult to understand the nature of articles, and user opinions are reflected in very limited ways. This proposal aims to present an alternative to overcome this.

**4. Goals**
1) All kinds of issues should be viewable at a glance.
2) There should be an effect of promoting good articles to the top.
3) It should be a system that allows active opinion sharing through integration with blogs.
4) The nature of news articles should be definable.
5) It should have adaptability to encompass all issues.

**5. Terminology Explanation**
**1) Issue:** A topic represented by a simple title or word [Rectangle] (If the issue does not exist, users can add it, similar to Blink.)
**2) Pro/Con Web Object:** Web posts produced by journalists or users [Circle]
- A single web object can have multiple issues with pro/con stances.
ex) Article, Posting, Comment
**3) Related Web Object [Rounded Rectangle]:** Refers to objects that do not take a pro or con stance, such as issue-related bulletin boards, links, and related search terms.
**4) Opinion:** The pro/con relationship of a web object with other issues or objects [Line in the diagram]

****6. Example of Issue Registration when Creating Web Objects**
1) You can search for the relevant issue, take a pro/con stance, or create a new issue.

A single web object can select multiple issues. This functionality applies to articles, postings, and comments.

3) Clicking on an issue at the top will take you to the issue page.
4) In the case of news articles, journalists may intentionally not register their stance on an issue. Therefore, to ensure system reliability, for major issues, system administrators can add pro/con stances based on the article's content.

**7. Example of Issue Page**
{{IMG:5}}
**1) The purpose is to allow users to grasp the pro/con situation of an issue at a glance.**
- It is basically a concept similar to Blink, but while Blink only links positive web documents (sympathy), an issue encompasses both positive and negative web objects (pro and con).
(Duplicate issue titles cannot exist. However, if an issue grows and there is a clear reason to distinguish it from a past duplicate issue, an administrator can directly access the system to modify the name of the past issue.)
2) Furthermore, the scope, which was limited to blog postings, has been expanded to include news articles and comments. Trackbacks can be utilized more extensively, and the currently scattered discussion forums can be automatically grouped by issue. Various polls can also be conducted within the discussion forums. **(This consolidates user communication spaces into one.)**
3) Related web objects, such as related cafes and related issues, can be implemented identically to Blink.
4) Exposing related search terms increases search traffic, and exposing real-time search rankings allows users to grasp the accurate situation of an issue. **(In this case, comprehensive real-time search terms are much more meaningful than rapidly rising real-time search terms.)**
6) Netizen Pro/Con Tally Method: **Netizen pro/con for an issue is determined by the number of participating users who created pro/con web objects, and a graph shows the change in public opinion. Clicking on a specific date allows users to view the Best articles registered for that issue at the time.**
- Using this, users can understand the reasons for changes in public opinion regarding an issue at that time.
- Tallying is done at regular intervals (daily or every few hours), and it is counted by the number of users who expressed pro/con opinions. Even if one user writes multiple comments and postings, it is counted as only 1 pro or con to enhance fairness.

****8. Best Web Object Selection Method within an Issue**
1) These web objects have "Sympathy" and "Bad Manners" buttons.
- Previously, "Dislike" simply lowered the cleanliness index when clicked by people with opposing views. To prevent this, it has been renamed to "[Bad Manners]," and if "[Bad Manners]" is clicked multiple times, the user's cleanliness index decreases, and they receive a penalty in points for being promoted to Best.
2) Best Web Object Selection Method
- It is selected based on the number of "Sympathy" clicks for that issue.
- The elapsed time since creation is also set as a penalty, so Best posts automatically change. (Refer to the previous Naver News Best Comment system.)
- Best posts are selected with 'n' items from pro and 'n' items from con, contributing to neutrality, and public opinion trends can be checked by looking at the pro/con ratio at the top.
- Also, even if comments are from different news articles, if they belong to the same issue, they are gathered in one place, increasing the concentration of each web object.

**8. Inheritance of Issue Stance by Sub-objects**
1) Web objects with an issue (articles, postings, comments) operate as sub-issues of each issue, and thus can also have pro/con web objects attached, automatically inheriting the original web object's issue stance according to pro/con.

****9. Example of Sub-object Page**
1) The purpose is to allow users to grasp the situation regarding the web object at a glance.
{{IMG:9}}
(A sub-issue does not have a single proposition. A sub-issue is an issue object associated with a single URL or specific content, and while it can have duplicate names, it cannot have duplicate associated URLs.)
-> Therefore, the issue itself is not the subject of debate; the web object itself becomes the subject of debate.
2) At the very top, there is content about the article or posting, and pro/con is set for that web object.
3) This page can be accessed from each article in the news or each post in a blog.

**10. My Opinion Page**
{{IMG:10}}
1) Notifies when a web object that opposes/supports your comment or post is registered. (Similar to a new comment system)
2) A system to view an individual's participation in issues (similar to other comment viewing features but provides a more accurate understanding of user tendencies).
3) Can be expanded into a My Space concept where you can manage the issues and discussion forums you've created.

**11. News Service Page**
{{IMG:11}}
The service page basically uses an algorithm, like real-time search terms, to rank items higher, thereby eliminating neutrality controversies. If multiple closely related issues are exposed only at the top, those deemed duplicate issues are deleted, and accessibility to related issues is increased.

**12. Media Company Issue Page**
1) A separate issue page based on articles written by each media company is provided, allowing users to easily compare the editorial differences of each media company and check netizens' reactions.
2) Portal issue tendencies can also use this data to strive for neutrality and implicitly compel media outlets to maintain neutrality. The ratio of article tendencies for each issue and the total pro/con of netizens for articles (sub-issues) belonging to that issue are displayed.
3) Users can select between overall major issues and media company major issues, allowing them to check and compare differences in the issues primarily covered by each media outlet.
