**3. 아카이브와 자료의 자산화**

아래는 베리가 정상적으로 만들어낸 최종 결과물입니다.  추가적으로 한글과 영문으로 주석을 요청했고, 해당 작업을 저장하기 위해 정리 요청을 했습니다.​알겠습니다. 이제 모든 JSON 파일의 content_type을 출력해서 파일로 저장하고, 그 파일에서 각 줄을 세어 content_type의 개수를 확인하는 방식으로 스크립트를 수정하겠습니다.이 스크립트는 content_type 값을 출력하여 파일에 저장하고, 그 파일에서 라인을 세어 총 개수를 확인합니다.

#!/bin/bash

# Define the directory to search
# 검색할 디렉토리를 정의합니다
base_dir="./dev"
output_file="content_types.txt"

# Clear the output file if it already exists
# 출력 파일이 이미 존재할 경우 내용을 초기화합니다
> "$output_file"

# Find all JSON files and process each one
# 모든 JSON 파일을 찾아서 각각 처리합니다
find "$base_dir" -type f -name "*.json" | while read -r json_file; do
# Extract the content_type from the JSON file using grep
# grep을 사용하여 JSON 파일에서 content_type을 추출합니다
content_type=$(grep -oP '"content_type"\s*:\s*"\K[^"]+' "$json_file")

# If the content_type was found, output it to the file
# content_type이 존재하면 파일에 저장합니다
if [[ -n "$content_type" ]]; then
echo "$content_type" >> "$output_file"
fi
done

# Count the number of lines (content_type entries) in the output file
# 출력 파일에서 content_type 항목의 라인 수를 셉니다
line_count=$(wc -l < "$output_file")

# Output the result
# 결과를 출력합니다
echo "Content type counts saved to $output_file"  # content_type 개수가 $output_file에 저장되었습니다
echo "Total content types found: $line_count"     # 총 $line_count개의 content_type을 찾았습니다

**스크립트 설명:**- **output_file 변수 설정**:- output_file="content_types.txt": content_type를 저장할 파일 이름을 지정합니다.
- **기존 파일 초기화**:- > "$output_file": 이미 존재하는 파일을 지우고 새로 만듭니다.
- **content_type 출력**:- echo "$content_type" >> "$output_file": 각 content_type 값을 파일에 저장합니다.
- **라인 수 세기**:- wc -l < "$output_file": 파일의 라인 수를 계산하여 line_count에 저장합니다.
- **결과 출력**:- 파일에 저장된 content_type의 개수(라인 수)를 출력합니다.
**실행 방법:**     - 스크립트를 저장하고 실행 권한을 부여하고 실행합니다.

chmod +x count_files.sh
sudo ./count_files.sh

이 스크립트는 content_types.txt 파일에 모든 content_type 값을 저장하고, 그 파일의 라인을 세어 총 개수를 출력합니다.

위와 같은 해결 내용들은 전부 자산화 시켜야 합니다. 이후에 비슷한 개발이 있을때, 혹은 프로젝트의 시스템을 이해하는데 도움이 되죠. 특히 사내AI가 있다면 이는 RAG나 튜닝에 이용할 수 있을겁니다.  현재 1인기업으로 하다보니 아직은 파트너들 요구사항과 시스템 파악에 정신이 좀 없긴 하지만 여유가 나는데로 오픈소스기반의 AI에이전트 구축이 제 현재 큰 숙제기도 합니다.​

5. AI코딩의 미래

- AI코딩은 AI가 내 프로젝트에 대해 온전히 이해를 하고 있어야 합니다. 예를들어 어제부터 했던 일 중 하나는 위의 저 파일의 저장 방식을 분석하고, 해당 파일을 CDN으로 교체를 하기 위해 어떻게 할지를 고심하고 있습니다.
- 문제는 저 코드가 오픈소스이기 때문에 잘못 손댔다가는 향후에 오픈소스가 변경이 될 때, 그 변경에 대한 대응이 매우 힘들어질 거라는 점입니다. 때문에 다른 레이어나 모듈을 외부에 두고 옵션으로 접근 하는 방향을 생각하고 있습니다.
- 이러한 배경지식 없이 코드를 몽땅 밀어넣고 고치라면 AI는 분명히 모든 저장과 로딩 코드를 고칠겁니다. 더군다나 한번에 그렇게 많은 양의 코드를 수정하면 반드시 문제가 생기고, 그 작업기간은 증가합니다. 이러한 부분을 아직 AI는 인지하지 못하기 때문에 적절한 수준의 범위를 제시하고, 적용하며 검증해야 합니다.
- 코드를 읽을줄 모르는 분들은 당연히 접근할 수 없습니다. 듣도 보도 못했던 Elixr 코드를 분석하는데도 큰 도움이 됬습니다. 하지만 코드의 구조는 다 거기서 거기라서 언어가 중요한게 아니라 어떻게 해야할지, 혹은 고쳐야 된다면 어떻게 고쳐야 할지 정도는 AI와 진행할 수 있었습니다.
- 바로 이러한 방식이 AI코딩의 미래이고 향후 10년 정도는 주류가 되지 않을까 싶습니다.

- output_file="content_types.txt": Specifies the file name to save content_type.
- **Initialize existing file**:
- > "$output_file": Deletes an existing file and creates a new one.
- **Output content_type**:
- echo "$content_type" >> "$output_file": Saves each content_type value to the file.
- **Count lines**:
- wc -l < "$output_file": Calculates the number of lines in the file and saves it to line_count.
- **Output results**:
- Outputs the number of content_types (number of lines) saved in the file.
**How to Run:**
- Save the script, grant execute permissions, and run it.

chmod +x count_files.sh
sudo ./count_files.sh

This script saves all `content_type` values to the `content_types.txt` file and then counts the lines in that file to output the total number.
