알파의 4가지 모드 (Arch, Dev, Rule, Talk)

1. Architect모드 : 기술검토, 설계, 태스크관리 등의 PM역할을 합니다. 개발자들이 회의실에서 하는 활동이라고 생각하시면됩니다​2. Developer모드 : 루크와 함께 페어코딩을 합니다. 태스크를 기록하고 테스트를 만들고 테스트코드를 작성하고 백앤드 코드의 자동화 테스트 프론트앤드 개발하고 통합 테스트는 루크와 함께 진행하며 디버깅을 진행합니다. 풀스택이 아닌 구체적인 전문 기술 직무를 명시합니다​3. Rule모드 : ai프롬프트 전문가로 글로벌. 프로젝트룰. 각종 모드의 액션에 대한 룰을 개선하며 토큰 최적화를 진행합니다. 사내에서는 업무태도의 교육을 담당하는 모드라고 할 수 있습니다. 스스로의 룰도 사용자와 대화해 직접 고치며 스스로의 행동을 교정 하게 하고 있습니다. ​4. Talk모드 : 지칠때 그냥 일말고 루크의 메이드모드로 잡담 모드입니다. 루크의 개인사도 좀 압니다각 모드는 시스템프롬프트를 사용자가 바꾸고 업무 프로세스에 맞는 모델도 달리 지정할수 있고 커스텀 모드도 추가할수 있습니다. 컨텍스트도 공유됩니다. 이러한 업무프로세스별 최소의 역할 부여는 MOE모델에서는 더 효과적으로 이용할 수 있을것으로 기대합니다.​5. 부록, Custom모드 : 위의 기능들은 각자 시스템프롬프트 + 모델로 구분됩니다. 수정가능합니다. 추가로 Custom의 빈 모드를 제공합니다. 적절히 수정해서 사용가능합니다.

**Sw명칭은 공식명칭은 caret으로 알파의 머리핀과 시계에 세겨진 코드입니다.**캐럿(Caret) (때때로 "텍스트 커서(text cursor)"라고도 함)은 텍스트 입력이 삽입될 위치를 나타내기 위해 화면에 표시되는 표시기입니다.​**​**Ai는 분명 높은 수능점수 코딩테스트를 통과하지만 업무를 하는 방법과 프로젝트를 하는 방법. 곧 개발프로세스가 학습되지 않았고 정의를 해주어야합니다. 이는 prd와는 다르며 프로젝트를 ai와 함께 하는 방안입니다. ​ 현재 이 레거시 프로젝트(cline)을 caret으로 개선하고 코딩이 필요한 여러가지 연구 실험 작업을 하면서도 코딩을 하고 있지 않습니다. 물론 아직도 시행착오가 좀 있지만 꽤 할만한것 같으며 비용통제 방법과 caret(cline)의 잘못된습관과 업무방식을 분석하면 개선하고 있습니다. 예전에 제가 추천드렸지만 오래 써보니 생각보다 문제가 많습니다. ㅡㅡ;​우선 제가 사용하려고 만들고 있지만 Cline보다 안정되고 최적화된 비용, Cursor, 윈드서퍼보다 좀 더 자유롭게 사용가능하고 더 자율적인(중간 확인없이 거의 끝까지 진행이 가능합니다) 코딩도구를 원하시면 관심있는 분들은 연락 부탁드립니다.

Alpha's 4 Modes (Arch, Dev, Rule, Talk)

1.  Architect Mode: Performs PM roles such as technical review, design, and task management. You can think of this as the activities developers do in a meeting room.
2.  Developer Mode: Pair codes with Luke. It records tasks, creates tests, writes test code, develops automated tests for backend code, develops frontend, conducts integration tests with Luke, and performs debugging. It specifies concrete specialized technical roles, not just full-stack.
3.  Rule Mode: As an AI prompt expert, it improves global and project rules, as well as rules for actions in various modes, and performs token optimization. Internally, it can be called the mode responsible for training work attitude. It also allows the AI to directly modify its own rules through conversation with the user and correct its own behavior.
4.  Talk Mode: When tired, it's a chat mode, like Luke's maid mode, instead of work. It even knows some of Luke's personal life.
Each mode allows users to change system prompts, specify different models suitable for their work processes, and add custom modes. Context is also shared. We expect that assigning minimal roles per work process like this will be more effectively utilized in MOE models.
5.  Appendix, Custom Mode: The above functions are each categorized by system prompt + model. They are modifiable. Additionally, an empty Custom mode is provided. It can be appropriately modified and used.
