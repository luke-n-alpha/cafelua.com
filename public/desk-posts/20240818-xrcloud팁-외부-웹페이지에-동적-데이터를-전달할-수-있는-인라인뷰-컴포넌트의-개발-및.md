**​****1. 문서의 목적 및 개요**- 웹기반의 메타버스 XRCLOUD는 다양한 외부 웹서비스나 페이지와 연결될 수 있는 기능을 제공합니다. Spoke웹 메탑버스 에디터에서 제공하는 컴포넌트는 link컴포넌트와 Image컴포넌트가 있으며, Image컴포넌트는 이미지를 버튼 처럼 사용할 수 있어 Image컴포넌트를 사용합니다.
- 하지만 Room은 Spoke로 만들어진 Scene(공간 프로젝트)을 인스턴스화한 공간으로 Image외 link컴포넌트에 들어간 link를 동적으로 변경하거나 혹은 해당 외부 웹사이트에 데이터를 전달할 수 없습니다.
- 이에 BELIVVR의 XRCLOUD에서는 InlineView컴포넌트를 만들어 Room에 접속할때 데이터를 전달하고 해당 데이터는 Room에 연결된 웹페이지에 전달 될 수 있도록 만들었습니다. 이를 통해 XRCLOUD를 이용한 개발자는 Room에 연결된 웹페이지에 데이터를 전달하여 유저별로 다른 목적 페이지로 라우팅 시키거나 혹은 유저별 맞춤 정보를 제공할 수 있습니다.
**2. 인라인 뷰의 데이터 전달 및 사용 방법****1) 사전 준비**- Scene에 인라인뷰 컴포넌트를 배치합니다.
- 인라인뷰 컴포넌트는 거의 Image컴포넌트의 기능을 다 가지고 있으며, 차이점은 목적 페이지에 대한 타겟 프레임을 허브내에 별도로 만든 iframe으로 할 수 있도록 기능을 제공하며 두가지 iframe과 두가지 라우팅 유형이 제공됩니다. - Main : 3D공간이 표기되는 영역입니다.
- Side View : PC에서 채팅과 접속자가 표기되는 영역으로 주로 모바일 형태의 콘텐츠에 적합합니다.
- Self Window : 전체 페이지를 라우팅합니다.
- New Window : 새탭을 띄워 해당 페이지를 라우팅합니다.

[**How to develop and utilize an inline frame component that can transfer dynamic data to an external webpage | Notion** 1. Purpose and Overview of the document belivvr.notion.site](https://belivvr.notion.site/591573adf4f8482c8c135447fb011975?pvs=74)

**1. Purpose and Overview**
- The web-based metaverse XRCLOUD provides functions that can connect to various external web services or pages. The components provided by the Spoke web metaverse editor include the link component and the Image component. The Image component is used because it allows images to be used like buttons.
- However, a Room is a space instantiated from a Scene (space project) created with Spoke, and it cannot dynamically change the link embedded in the link component other than the Image, nor can it transfer data to that external website.
- To address this, BELIVVR's XRCLOUD created an InlineView component that allows data to be transferred when connecting to a Room, and this data can then be passed to the webpage connected to the Room. This enables developers using XRCLOUD to transfer data to the webpage connected to the Room, allowing them to route users to different destination pages or provide personalized information.
**2. Inline View Data Transfer and Usage**
**1) Preparation**
- Place the InlineView component in the Scene.
- The InlineView component has almost all the functions of the Image component. The difference is that it provides the ability to set the target frame for the destination page as a separately created iframe within the hub, and offers two types of iframes and two routing types.
    - Main: This is the area where the 3D space is displayed.
    - Side View: This is the area where chat and connected users are displayed on PC, mainly suitable for mobile-form content.
    - Self Window: Routes the entire page.
    - New Window: Opens a new tab and routes to that page.
**2) Calling**
- When calling, use the getRoom API to retrieve the Room's URL.
- [https://api.xrcloud.app/api/rooms/{roomId}](https://api.xrcloud.app/api/rooms/%7BroomId%7D)
- The data to be passed is sent in query parameter format within `linkPayload`.
- [https://api.xrcloud.app/api/rooms/{roomId}](https://api.xrcloud.app/api/rooms/%7BroomId%7D)?linkPayload={Data}
- Use the private URL among the returned URLs. This is to prevent the `linkPayload`, which expires over time, from being leaked.

**3) User Usage**
- A user who accesses via the previously obtained private URL, when clicking on an inlineView, will be directed to the pre-configured destination URL for that inlineView. The data transferred in `linkPayload` will be added as a query parameter named `hubsParam`.
- `InlineViewName` will be passed as the name of the inline view clicked by the user, indicating which component the user clicked to access that page.
**3. Application Methods**
**1) Providing Personalized Information to Users**
- By transferring user identification information in `LinkPayload`, it is possible to provide functions that display user-specific information.

**3) Transferring Common Data to CPs (Content Providers)**
- By notifying CPs (Content Providers) who edit and provide spaces about common platform parameters, necessary common data can be transferred between each content.
- For example, in the platform we are developing, we want external content to receive the platform's avatar and display name to maintain user consistency across the platform.
- Therefore, we made it a common platform standard to transfer avatar and name in `linkpayload` and distributed it.

- **Create Scene**
    - **The service admin is creating spaces for each CP through XRCLOUD's Scene Create API.**
    - **1-1. When creating a space, CPs can freely use inline views in the Spoke editor to connect various external contents to the Room. This includes Unity Webgl content.**
    - **1-2~4. When the service platform deploys a Scene, it automatically creates a Room via the Create Room API, developing a 1:1 structure.**
- **GetRoom API**
    - **On the service page used by the user, a Private URL for the user to access the Room is requested, and at this time, the user's avatar information and name information are sent together in the Payload.**
**3~4. Return Private room URL & Open Room url**
- **The platform receives a Private URL that the user can access. When this URL is displayed on the screen, the user clicks on that URL (button) to access the Room.**
**5. Open Page and Send payload**
- **When the user clicks on an inlineView component in the accessed Room, that component transfers the Payload information and the inlineView's name as query parameters to the out-link service page of the InlineView, which was set when the Scene was created.**
- **The CP parses these parameters and processes the avatar and name identically.**
**ex) Notice delivered to Metatrack's CP**
- **`hubsParam` transfers necessary parameters. Metatrack used `|` as a delimiter to send class ID, user ID (UUID), user name, avatar URL, and a token for login processing in Metatrack.**
- **`inlineViewName` is the name of the inlineView component defined in Spoke.**
- **Parameters must be accessed via a temporary (private) URL generated through class entry to be transferred. Since it is a temporary URL that expires, it will not be accessible later if used as a static URL. For reference, the admin does not have information to send such as class information or avatar information, and uses a fixed public URL.**
