## Method, Apparatus and Computer-Readable Recording Medium for Recognizing Characters Included in Hangul Documents

METHOD, APPARATUS AND COMPUTER-READABLE RECORDING MEDIUM FOR RECOGNIZING CHARACTER INCLUDED IN HANGUL DOCUMENT
IPC Code G06K 9/62 (2006.01)
Application Number 1020090064687 (2009.07.15)
Publication Number 1020110007009 (2011.01.21)
Registration Number 101015233 (2011.02.09)
Naver Academic Information URL : [http://academic.naver.com/view.nhn?doc_id=39380571&applicationNumber=1020090064687](http://academic.naver.com/view.nhn?doc_id=39380571&applicationNumber=1020090064687)

I was surprised to hear about this patent registration. Did I even file such a comprehensive patent? When I tried to summarize it, I realized it's the entire structure of the OCR engine from the Naver OCR project I participated in. Briefly, it used multiple recognizers such as mesh recognition, jaso (Korean character component) recognition, and run-length of character strokes. Even with engines 1, 2, and 3, if engine 1 yields a high-probability result, engines 2 and 3 are not executed to increase speed. If the probability is low, it combines the results to select the character with the highest probability.
This method was something I devised because pattern recognition becomes very slow when recognized by multiple engines or various methods. If I explain in more detail, it might lead to technology leakage... so I'll just give a brief explanation. It might be helpful for those studying pattern recognition.

This engine is used at [http://t.lab.naver.com/ocr/](http://t.lab.naver.com/ocr/).
