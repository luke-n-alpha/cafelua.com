지난번에 공개해드린  [톡에 사용하면 좋을 드로잉 이모티콘 삽입기]의 아이디어 원본 문서를 찾아 공개합니다. (어디있나 했더니.. 폴더 구석에 짱박혀 있었네요.) 좀 더 자세한 구현 방법이 있으니 도움이 될것 같아 추가 공개합니다.

**1. 제목: 의미기반 심볼 OCR**

**2. 배경 :** 기존의 OCR은
해당 Class가 문자나 비슷한 그림을 찾는데 주안을 두고 있다.

{{IMG:1}}

그러나 사용자는 토끼를 찾기 위해서는

{{IMG:2}}

란 입력을 할
수 도 있다.

그러나 기존의 OCR방법을 이용하면, 내부적으로 거의 비슷한 토끼의 이미지를 가지고
있지 않는 한, 토끼를 검색 할 수는 없다.

이를 위해서는
일반적인 “토끼”란 심볼을 인식하는 OCR이 필요로 한다.

**3. 기존 OCR 혹은 이미지 기반 검색의 구조의 차이**

**1) 기존**

사용자
입력 : 이미지 {{IMG:3}}

시스템 : 미리 Classfy되어있는 비슷한 이미지의 검색{{IMG:4}}

사용자
출력 : 가장 비슷한 이미지 혹은 해당 이미지의 텍스트 코드 출력

**2) 변경**

사용자
입력 : 이미지 {{IMG:5}}

시스템 : 미리 Classfy되어있는 비슷한 이미지의 검색 {{IMG:6}}

해당 이미지에
대한 의미(코드)에 해당되는 이미지 테이블을 선택한다

{{IMG:7}}

사용자
출력 : 의도한 심볼의 다양한 이미지를 볼 수 있다.

**4. 인식률
향상 및 유저 인터페이스 계선**

**1) 카테고리
선택**

**    유저가 입력 전에, 동물, 표정, 사물을 미리 선택하게 한다.**

**  이는 많은 심볼을 찾을 때 전통적으로 쓰던 UI이므로 사용자는 큰 불편을 느끼지 않을 것이다.**

사용자가 를 입력 하였을 때 {{IMG:8}}가
나오기를 원하는 사람은 없을 것이다. 그러나, 현실적으로
어떤 OCR 방법을 쓰더라도 분리해내는 것은 쉽지 않다. 때문에
유저에게 의도하는 바를 카테고리를 선택하게 한다.

이는
기존 OCR에서 언어를 미리 설정 하여 인식률을 높이는 것과 비슷하다.

그러나
기존 OCR에서는 주로 한명의 유저가 한 개 혹은 두개의 언어정도만 주로 이용하지만, 심볼의 경우에는 많은 카테고리를 이용하므로 카테고리 선택의 기능은 매우 중요하다.

I am releasing the original idea document for the [Drawing Emoticon Inserter good for use in chat], which I shared last time. (I wondered where it was... turns out it was tucked away in a folder corner.) Since it contains more detailed implementation methods, I'm sharing it additionally, hoping it will be helpful.

**1. Title: Meaning-based Symbol OCR**

**2. Background:** Existing OCR
focuses on finding characters or similar images within its class.

{{IMG:1}}

However, to find a rabbit, a user
might make an input like this.

{{IMG:2}}

However, using existing OCR methods, it cannot search for a rabbit unless it internally possesses an almost identical image of a rabbit.

For this, an OCR that recognizes the general symbol of "rabbit" is needed.

**3. Differences in Structure between Existing OCR or Image-based Search**

**1) Existing**

User Input: Image {{IMG:3}}

System: Search for similar pre-classified images {{IMG:4}}

User Output: Most similar image or text code of that image

**2) Changed**

User Input: Image {{IMG:5}}

System: Search for similar pre-classified images {{IMG:6}}

Selects an image table corresponding to the meaning (code) of that image

{{IMG:7}}

User Output: Can view various images of the intended symbol.

**4. Improved Recognition Rate and User Interface Improvement**

**1) Category Selection**

**Allow the user to pre-select categories like animals, expressions, or objects before input.**

**Since this is a UI traditionally used when searching for many symbols, users will not feel much inconvenience.**

When a user inputs a drawing, no one would want {{IMG:8}} to appear. However, realistically, it is not easy to differentiate them regardless of the OCR method used. Therefore, allow the user to select the intended category.

This is similar to how existing OCR improves recognition rates by pre-setting the language.

However, in existing OCR, a single user typically uses only one or two languages, but in the case of symbols, many categories are used, making the category selection feature very important.
