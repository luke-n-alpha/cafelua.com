****
**- 최초 작성일 : 2010년 3월 25일**

**가, 서론 **
** **구글링이나 네이버 검색을 통해 주민등록번호같은 개인정보가 유출되거나 찾으려는 시도가 많다. 이에 대한 피해를 최소화 하는 방법을 제시한다.
****
**나. 용어
** ' 개인정보 판독기 : 정형화된 주민등록번호의 패턴 로직같은 컨탠츠와 쿼리에 개인정보 혹은 개인정보 검색의도가 있는지를 판독하는 프로그램, 이에 대한 자세한 구현방법은 제시하지 않는다.

**다. 컨탠츠 라이프 사이클별 보호 방법
**
** 1. 생성**
카페에서 사용자가 컨탠츠 내에 글을 올리는 시점으로 컨탠츠가 서버 db에 작성되기 이전에 개인정보 판독기를 거친다.
' 개인정보 판독기가 개인정보 포함 여부를 판단하고 최초 작성 유저에게 검색 옵션의 활성화 여부와 개인정보로 의심되는 내용이 포함되어 있음을 주지시켜준다. 사용자의 액션에 따라 컨탠츠 서버에 개인정보가 포함된 컨탠츠 유입을 원천 차단 할 수 있다.
이는 검색에 이용되는 컨탠츠 뿐만아니라 검색에 이용되지 않는 이메일등의 기능에도 사용이 가능한 기능이다.
****
** 2. 검색 컬랙션생성및 크롤링
** 검색 컬랙션 생성이나 웹 크롤링 과정을 통해 생성된 컨탠츠는 개인정보 판독기를 거쳐 개인정보 포함여부를 판단하고, 위험도별로 대상의 정보를 별도의 개인정보 의심리스트에 보관한다. 이를 통해 원 컨탠츠 생성및 보유유저에게 자동 혹은 수동으로 위험여부를 공지할수 있다. 공지대상은 컨탠츠 생산 유저 혹은 서비스 관리자가 된다. 카페의 경우, 원 작성자와 카페관리자, 외부 웹사이트의 경우, 게시물작성자와 사이트 운영자및 관리자가 된다.
반복해서 수집되는 동일 컨탠츠는 공지를 스킵하여 공지를 받는 유저에게 불편을 끼치지 않도록 하거나 컨탠츠 소유유저로부터 의사 표현을 받는 경우 이후 해당 컨탠츠는 공지를 제외하거나 개인정보판독 대상에서 제외한다.
****

** 3. 검색 쿼리를 통한 컨탠츠 검색 단계
** 쿼리자체가 개인정보 검색이 목적으로 의심되는 경우 검색 사용자에게 해당여부를 알리거나 검색 자체를 거부 할 수 있다.
****
**
**** 4. 컨탠츠 소멸
** 2.에서 생성된 개인정보 컨탠츠 리스트는 프로그램에 의해 자동적인 방법, 혹은 관리자의 검수로 제거 하여 검색에서 제외할 수 있다.
2.에서 컨탠츠 유저에게 공지를 하여 컨탠츠를 검색못하도록 설정하거나 컨탠츠를 삭제하게 하여 검색에서 제외할 수 있다.  컨탠츠 소유 유저의 동의에 의해 컨탠츠를 유지하고 공지및 개인정보 검사대상에서 제외할 수 있다.

**라. 효과
** 1. 개인정보 검색에 관해 잘 모르는 라이트한 유저의 의도되지 않은 개인 정보 유출 차단
2. 작성시 개인정보 유출및 포함 여부를 공지함으로서 컨탠츠 db에 개인정보를 포함시키지 않도록 하여 포탈의 개인정보 취급에 관한 리스크 감소
3. 개인정보 보호에 대한 의식개선
4. 개인정보 도용및 수집의 차단 효과

**마. 특징점**
1. 웹 컨탠츠 생성시 개인정보 포함에 대한 알리미 기능
2. 검색 대상 수집시 개인정보 포함여부에 따른 검색 대상 제외 기능
3. 검색 대상 수집시 개인정보 포함여부에 따른 원 컨탠츠 유저에 대한 알리미 기능
4. 검색 대상 수집시 개인 정보 포함 리스트를 운영하는 서버
5. 개인정보 검색을 목적으로 한 검색 쿼리 판단및 그에 대한 액션

**- First Written: March 25, 2010**
 
**A. Introduction**
** **There are many attempts to leak or find personal information, such as resident registration numbers, through Google or Naver searches. This document proposes methods to minimize the damage caused by this.
**** 
**B. Terminology
** ' Personal Information Reader: A program that determines whether content and queries, such as the pattern logic of standardized resident registration numbers, contain personal information or an intent to search for personal information. Detailed implementation methods for this are not provided.
 
**C. Protection Methods by Content Lifecycle
**
** 1. Creation**
 In a cafe, when a user posts content, the content goes through a personal information reader before being written to the server DB.
 ' The personal information reader determines whether personal information is included and notifies the original author about the activation status of search options and the presence of suspected personal information. Depending on the user's action, the inflow of content containing personal information into the content server can be completely blocked.
 This function can be used not only for content used in searches but also for features like email that are not used in searches.
**** 
** 2. Search Collection Creation and Crawling
** Content generated through search collection creation or web crawling processes goes through a personal information reader to determine the inclusion of personal information, and the target's information is stored in a separate suspected personal information list based on risk levels. This allows for automatic or manual notification of risks to the original content creator and owner. The notification recipients are the content producer or service administrator. In the case of a cafe, it is the original author and cafe administrator; for external websites, it is the post author and site operator/administrator.
For identical content collected repeatedly, notifications can be skipped to avoid inconveniencing the recipient, or if the content owner expresses their intent, that content can be excluded from future notifications or personal information scanning.
****

** 3. Content Search Phase via Search Query
** If the query itself is suspected of aiming to search for personal information, the search user can be notified of this fact, or the search itself can be denied.
****
**
**** 4. Content Expiration
** The list of personal information content generated in step 2 can be removed from search either automatically by a program or through manual review by an administrator.
 In step 2, content users can be notified to set content as unsearchable or to delete content, thereby excluding it from search. With the consent of the content owner, content can be maintained and excluded from notifications and personal information scanning.
 
**D. Effects
** 1. Blocking unintentional personal information leakage by casual users who are unaware of personal information search risks.
 2. Reducing the risk associated with portal's handling of personal information by notifying users of personal information leakage and inclusion during creation, thereby preventing personal information from being included in the content DB.
 3. Improving awareness of personal information protection.
 4. Blocking the theft and collection of personal information.
 
**E. Key Features**
1. Notification function for personal information inclusion during web content creation.
2. Function to exclude search targets based on personal information inclusion during search target collection.
3. Notification function for original content users based on personal information inclusion during search target collection.
4. Server operating a list of personal information included during search target collection.
5. Judgment of search queries aimed at personal information search and corresponding actions.
