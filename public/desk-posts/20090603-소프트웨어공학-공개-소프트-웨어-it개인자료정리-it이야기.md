**1. 공개 소프트 웨어(Open Source)의 개념**
- 자유롭게 사용, 복제, 배포, 수정이 가능하며 소스코드가 공개 되어 있는 특징을 가진 소프트웨어, 공짜라는 의미가 아니라 독점적이지 않은 이란 의미로 상용화에는 이용이 가능한 소프트웨어
** 가. OSI 에서 정의한 10가지 오픈 소스의 조건**

| 무료 재배포 | 로열티 또는 판매 비용이 없어야 함 |
| --- | --- |
| 소스 코드 | - 프로그램에 소스 코드가 포함되어야 하며, 컴파일이 완료된 형태로 배포 가능 - 알아보기 힘든 소스코드는 사용 될 수 없음 |
| 소스 코드의 무결성 | - 패치파일의 배포를 허용할 때 만, 소스코드가 변경된 형태로 배포되는 것을 제한 - 변경, 파생작업을 통해 다른 버전, 다른 이름 생성 |
| 개인 또는 그룹의 평등 | - 어떤 개인이나 그룹에 차별을 두어서는 안됨 |
| 분야에 대한 평등 | - 특정 분야 사용에 제한두지 않음 |
| 라에센스는 다른 소프트웨어를 제한하지 않음 | 함께 배포된 다른 소프트웨어에 제약사항을 두지 않음 |

** 5. 개정된 GPL 3.0 (2007년 6월 29일)
가. 배경**
- 각국의 법제도 반영 필요
- 특허권에 대한 고려
- 신기술 증가
** 가. Tivoization과 DRM **
- GPL을 이용한 Tivo가 소스를 공개하였으나 설치 정보를 제공하지 않아, 이용자들이 정상 동작하지 않았음
- 3.0에서는 설치 정보 포함 규정, DRM 관련 규정의 제목을 “Digital Restrictions Management"로 표기
- GPL3.0이 적용되는 프로그램을 포함한 DRM은 법적 보호를 받지 못함
** 나. 특허권의 취급 **
- 특허권자가 GPL로 배포시, 해당 소프트웨어 이용자에게는 특허 주장하지 못함
=>  MPL조건의 A코드와 GPL 조건의 B코드를 합치는 경우, GPL은 'A+B'에 GPL 적용 요구, MPL은 A부분을 MPL로 요구

**1. Concept of Open Source Software**
 - Software characterized by free use, reproduction, distribution, and modification, with its source code publicly available. It doesn't mean "free of charge" but rather "non-proprietary," meaning it can be used for commercialization.
** a. 10 Open Source Conditions Defined by OSI**

| Free Redistribution | No royalties or sales fees |
| --- | --- |
| Source Code | - The program must include source code, and can be distributed in compiled form - Obscure source code cannot be used |
| Derived Works | Modification and derived works are possible, distributed under the same conditions as the original software's license |
| Integrity of Source Code | - Restrict distribution of modified source code only when allowing distribution of patch files - Create different versions, different names through modification and derived works |
| Equality of Individuals or Groups | - No discrimination against any individual or group |
| Equality for Fields of Endeavor | - No restrictions on use in specific fields |
| License Distribution | - The license is valid wherever the program is redistributed - No need for additional license issuance |
| License Must Not Be Specific to a Product | - The license applies to the entire program - Even partial use requires compliance with the license |
| License Must Not Restrict Other Software | No restrictions on other software distributed with it |
| License Must Be Technology-Neutral | Does not restrict technology or interface style |

** b. Comparison with Similar Concepts**

| Name | Concept | Scope |
| --- | --- | --- |
| Free Software (Freeware) | - Concept created by Richard Stallman and FSF (Free Software Foundation) - A subset of Open Source - Did not include whether commercial use was allowed - Some freeware is limited to users (in this case, it is not included in the scope of open source software) | Software, Source |
| Shareware | - A form of computer software marketing - Limited in usage period or functionality - Similar term to Trial Version | Software |
| Open API | - A web interface to access free services existing on the web | Web Service |

| Item | Content | Example |

| Item | Content | Example |

**3. Major Open Source Issues**
 a. Source Code Disclosure
  - Source code must be disclosed for derivative works of software, but it is difficult to mechanically distinguish between derivative works and mere aggregations.
  : Linux Kernel: Dynamic kernel modules (Loadable Kernel Modules) also operate by linking with the GPL Linux kernel, but an exception is recognized.
  : Java Platform Case: The JVM of the GNU Classpath project is GPL, but other Java Applications linked to and operating on that JVM are recognized as exceptions.
** b. Patent Rights**

| Category | Patent Owner | Rights |
| --- | --- | --- |
| Licensor | Copyright Owner | - Patent rights are treated separately from open source licenses - Royalties can be collected if used in proprietary licensed S/W |
| Licensee | User | - No issue if patent rights are not asserted, but if asserted, the open source license expires, and royalties can be calculated |
| Third Party | Third Party | - Distribution is not possible if the owner does not allow a royalty-free patent license |

** c. Dual Licensing**
  - Using multiple licenses: For commercial use and open source community collaboration.

**5. Revised GPL 3.0 (June 29, 2007)
a. Background**
   - Need to reflect legal systems of various countries
   - Consideration of patent rights
   - Issues with compatible licenses
   - Increase in new technologies
**a. Tivoization and DRM**
   - Tivo, which used GPL, released its source code but did not provide installation information, causing users to be unable to operate it normally.
   - In 3.0, a provision for including installation information was added, and the title of the DRM-related provision was changed to "Digital Restrictions Management."
   - DRM that includes programs covered by GPL3.0 does not receive legal protection.
**b. Treatment of Patent Rights**
   - When a patent holder distributes under GPL, they cannot assert patents against users of that software.
   - Third-party patents can only be distributed under GPL if the patent holder provides a free license to GPL users.
**c. License Compatibility: Apache, Affero GPL**
   - When the licenses of the combined codes conflict with each other
    => If code A under MPL conditions and code B under GPL conditions are combined, GPL requires GPL to be applied to 'A+B', while MPL requires the A portion to remain under MPL.
     Therefore, 'A+B' that satisfies the requirements of both licenses cannot be developed.
