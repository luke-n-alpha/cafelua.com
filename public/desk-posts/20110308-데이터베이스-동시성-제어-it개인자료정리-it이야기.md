**1. 개념**
- 다수의 트랜젝션을 병렬로 처리함에 있어, 갱신 손실, 불일치 모순성을 방지 하기 위해 트랜잭션을 직렬화 시키는 기법

**2. 목적**
- 다수의 트랜젝션 처리의 갱신손실, 불일치 모순성 방지
** 가. 갱신손실 (Lost update)**
- 지연된 업데이트로 트랜젝션의 업데이트 내용이 반영되지 않는 경우
- T1의 X=X+50의 연산 내용이 손실된 예

| ** T1** | ** X** | ** T2 ** |
| --- | --- | --- |
| 100 |  |  |
| Read(X) |  |  |
| X=X+50 | Read(X) |  |
| Write(X) | 150 | X=X*2 |
| 200 | Write(X) |  |

** 나. 불일치 모순성 (Inconsistency)**
- 연산 중 중첩 업데이트로 트랜젝션의 연산 내용이 불일치 되는 경우
- T1의 기대값 [X:150, Y:250], T2의 기대값 [X:200, Y:400], 중첩 트렌젝션의 수행 결과 [X:300, Y:450]

| ** T1** | **X ** | ** Y** | ** T2** |

| Read(X) |  |  |  |
| X=X+50 |  |  |  |

| X=X*2 |  |  |  |

| Y=Y*2 |  |  |  |

**3. 동시성 제어 기법**
가. 기술의 종류

| ** 기술** | **내용 ** | ** 세부 기술 ** |
| --- | --- | --- |
| Locking | 데이터 읽기, 쓰기 제한 | 2PL(2Phase-Locking) Shared lock(Write Lock) Exclusive Lock(Read Lock) |
| TimeStamp | 트렌젝션의 수행 시간 정렬 | Sysmtem Clock, Logical Counter 이용 |
| Validation | 낙관적 수행후, 오류 검증 | Read Phase 수행후 Validation Phase에 검증, Execution Phase에 Rollback |

나. 기술의 장단점 비교및 이에 따른 선택

| ** 기술** | **장점** | **단점 ** |
| --- | --- | --- |
| Locking | - 간단한 알고리즘 - 사전에 안전성 보장 | - Lock 대기시간 - Deadlock 우려 |
| TimeStamp | - Deadlock 없음 - lock 대기시간 없음 | - RollBack확률 높음 - Cascading rollback 가능성 |
| Validation | - 동시 처리 능력 증가 - 트랜잭션 대기시간 없음 | - 장기 트랜젝션 철회시 낭비 |

- Rollback 비용과 Lock 대기시간 비용의 Trade Off를 고려하여 선택

**1. Concept**
- A technique to serialize transactions to prevent update loss and inconsistency when processing multiple transactions in parallel.

**2. Purpose**
- To prevent update loss and inconsistency in processing multiple transactions.
**a. Lost update**
- A case where a transaction's update content is not reflected due to a delayed update.
- Example of T1's X=X+50 operation content being lost.

| ** T1** | ** X** | ** T2 ** |
| --- | --- | --- |
| 100 |  |  |
| Read(X) |  |  |
| X=X+50 | Read(X) |  |
| Write(X) | 150 | X=X*2 |
| 200 | Write(X) |  |

**b. Inconsistency**
- A case where transaction operation content becomes inconsistent due to nested updates during an operation.
- T1's expected values [X:150, Y:250], T2's expected values [X:200, Y:400], Nested transaction execution result [X:300, Y:450]

| ** T1** | **X ** | ** Y** | ** T2** |
| --- | --- | --- | --- |
| 100 | 200 |  |  |
| Read(X) |  |  |  |
| X=X+50 |  |  |  |
| Write(X) | 150 |  |  |
| Read(X) |  |  |  |
| X=X*2 |  |  |  |
| 300 | Write(X) |  |  |
| Read(Y) |  |  |  |
| Y=Y*2 |  |  |  |
| 400 | Write(Y) |  |  |
| Read(Y) |  |  |  |
| Y=Y+50 |  |  |  |
| Write(Y) | 450 |  |  |

**3. Concurrency Control Techniques**
a. Types of Techniques

| ** Technique** | **Content ** | ** Detailed Technique ** |
| --- | --- | --- |
| Locking | Restricts data read and write | 2PL(2Phase-Locking) Shared lock(Write Lock) Exclusive Lock(Read Lock) |
| TimeStamp | Orders transaction execution time | Uses System Clock, Logical Counter |
| Validation | Error verification after optimistic execution | Verification in Validation Phase after Read Phase, Rollback in Execution Phase |

b. Comparison of Advantages and Disadvantages of Techniques and Selection Based on Them

| ** Technique** | **Advantages** | **Disadvantages ** |
| --- | --- | --- |
| Locking | - Simple algorithm - Guarantees safety in advance | - Lock waiting time - Risk of Deadlock |
| TimeStamp | - No Deadlock - No lock waiting time | - High probability of Rollback - Possibility of Cascading rollback |
| Validation | - Increased concurrency - No transaction waiting time | - Waste when long transactions are aborted |

- Selection is made considering the trade-off between rollback cost and lock waiting time cost.
