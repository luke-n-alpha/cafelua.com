**1. 넘치는 클라우드 이야기**요즘은 클라우드란 용어가 넘치고 있습니다. 간단한 사진 편집은 이미 각 커뮤니티사이트들은 강력한 도구들을 제공하고 있었고 포토샵과 워드는 이미 웹에서 구동할 수 있는 시대입니다. 메일은 이미 아웃룩 대신 웹솔루션을 많이 사용하고 있습니다. 업무환경의 많은 부분은 이제 웹브라우져 하나만으로 다 되어가는 시대가 되고 있습니다.
**2. 그러나 정작 IT최전선의 개발자들에게는 아직..** 그러나 가장 그 클라우드서비스 조차 만들어내는 it산업의 현장의 모습은 어떨까요? 바로 개발자들의 이야기입니다. 이미 이들은 구글docs를 능숙하게 사용하는 이들이 많습니다. 그리고 24인치 듀얼모니터와 ssd 그리고 대용량 램, 회사에서 pc는 가장 강력한 머신을 사용하고 있습니다. 그 이유는 ecplise와 visual studio가 정말 무겁기 때문이죠. 또한 거대한 프로젝트의 경우 소스가 엄청나게 크고 이를 컴파일링하는데 오랜 시간이 걸립니다. 이들은 스마트폰에 들어가는 앱이나 웹서비스를 pc에 올려보며 테스트를 함께 진행하고 있습니다.
**** **3. 로컬 개발환경의 비효율성**
** 1) 복잡한 개발 환경 셋팅**  개발환경의 셋팅또한 그리 간단하지 않아서 새로 셋팅하려면 수시간에서 하루도 소비하기 마련입니다.
**
**** 2) 서비스 환경과 다른 에뮬레이터와 로컬 웹서버** 사실 이는 매우 큰 비효율성을 만들고 있었습니다. 스마트폰 에뮬레이터는 다양한 pc환경에 최적화되지 못한 경우도 많고, 웹서비스의 경우 로컬환경과 실제 서비스환경이 다른경우도 많죠. 때문에 통합배포와 계속되는 회귀 테스트를 거칩니다. ** 3) 로컬외에도 수많은 외부 자원들의 설정** 이제 환경셋팅을 마치면 소스를 내려받고 이제 부터 코딩에 들어갑니다. 아. 그전에 소스레포지토리의 권한을 받아야하고 db를 사용하고 있다면 그쪽 계정도 받아야 하죠.

사용자가 서비스를 사용하는 것은 로그인 한번이면 끝나는데 개발자가 서비스를 고치거나 만들기위해서는 서비스와 상관없는 이런 작업을 각 개발자마다 해야했던 겁니다. 따라서 조직차원의 통합개발환경이 중요하게 되고 간편한 배포시스템 테스트 시스템, 사내 표준 개발환경등등이 계속 조정됩니다. 그러는 과정을 클라우드의 기술을 이용해 해결할 수 없을까요? 당연히 그런 고민은 등장합니다. **4. 개발환경은 클라우드로 안돼 ?

**1. The Abundance of Cloud Talk**
These days, the term 'cloud' is ubiquitous. For simple photo editing, various community sites already offered powerful tools, and we are now in an era where Photoshop and Word can run on the web. For email, many are already using web solutions instead of Outlook. Much of the work environment is becoming an era where everything can be done with just a web browser.
 **2. However, for Developers on the IT Front Lines, Not Yet...** But what about the reality on the ground for the IT industry, which creates even those cloud services? This is the story of developers. Many of them are already proficient in using Google Docs. And they use 24-inch dual monitors, SSDs, and large-capacity RAM; at work, their PCs are the most powerful machines. The reason is that Eclipse and Visual Studio are truly heavy. Also, for massive projects, the source code is incredibly large, and compiling it takes a long time. They test apps for smartphones or web services by running them on their PCs.
**** **3. Inefficiency of Local Development Environments**
 ** 1) Complex Development Environment Setup** Setting up a development environment is also not simple, often taking several hours to a full day to set up anew.
**
**** 2) Emulators and Local Web Servers Different from the Service Environment** In fact, this created significant inefficiencies. Smartphone emulators are often not optimized for various PC environments, and for web services, local environments often differ from actual service environments. Therefore, they undergo integrated deployment and continuous regression testing. ** 3) Configuration of Numerous External Resources Beyond Local** Once the environment setup is complete, they download the source code and begin coding. Oh, before that, they need to get permissions for the source repository, and if they're using a DB, they need an account for that too. 

While a user can use a service with just one login, developers had to perform these service-unrelated tasks for each developer to fix or create a service. Therefore, an organization-wide integrated development environment becomes important, and simple deployment systems, testing systems, in-house standard development environments, etc., are continuously adjusted. Couldn't these processes be solved using cloud technology? Naturally, such concerns arise. **4. Why Not Cloud for Development Environments?** If word processors can be cloud-based, there's no reason why development environments can't be. Moreover, Eclipse is developed in Java, which is web-environment friendly. Thanks to this, while it shows terrible performance on PCs, it would be easier to move to the cloud than Visual Studio. ** 1) What if Google...?** Especially when it comes to cloud, the company that comes to mind like a synonym is Google. What will Gosling, the father of Java, do at Google? I indulge in a wild imagination that he might create a Java IDE that runs in a web environment. This HTML5-based IDE tool might even generate code automatically by selecting design patterns with a mouse. Looking at Google's developer support site, the UX is so well-designed that you might wonder, 'Is this really a developer site?' Come to think of it, search auto-completion was that feature I admired in Visual Studio 6.0, now moved to the web. Perhaps Google is drawing a big picture of making Google synonymous with the computing environment, where development, deployment, and earning money all happen within Google. It turns out there was already a cloud version of Eclipse called Orion. In fact, creating a simple C compilation environment, which is taught first in school, would already be trivial. ** 2) Major Changes Cloud Brings to Development Environments** If web programs are moved to the cloud, concerns about compilation and testing could be greatly reduced. Perhaps the commit process might even disappear. It might even be possible to fix things together in real-time. Of course, if fixed together before conflicts, it might not run properly. Anyway, it means real-time collaboration becomes possible. Also, companies wanting services can build development environments at relatively low costs and receive high-level services. And cloud service companies like Google will generate further profits through this. **Gosling, the founder of JAVA, has joined Google. It is anticipated what changes he will bring about in the world Google is envisioning.**
